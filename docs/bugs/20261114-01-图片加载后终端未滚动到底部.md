## 1. 缺陷描述

在终端中执行 `img` 查看图片后，如果图片与上方历史输出超出可视区域，输出区不会滚动到最新位置：图片下半部分与输入行被顶出视口，用户必须手动向下滚动才能看到输入框和图片底部。

M9 需求文档第 2.2 节要求「图片加载完成后自动滚动到底部，输入行保持可见」，实际行为不满足该验收项。

**实测数据（修复前，Chrome 1280×800）**：

| 指标 | 执行 `img` 前 | 执行 `img` 后 |
| --- | --- | --- |
| `scrollTop` | 0 | 0 |
| `scrollHeight` | 749 | 1160 |
| `clientHeight` | 749 | 749 |
| 距底部 | 0 | **411** |
| 输入行 `top` | 518 | **1163**（已超出 800 视口） |
| 图片 | 无 | `pluto.jpg` 558×558，`complete: true` |

## 2. 复现步骤

1. 启动 `npm run dev`，浏览器打开站点，视口高度约 800px。
2. 连续执行 3–4 次 `help`（或任意产生较多输出的命令），让输出区出现滚动。
3. 执行 `img /mnt/gallery/pluto.jpg`。
4. 观察：图片已加载，但输出区仍停在原来的滚动位置，图片底部与输入行在视口之外。
5. 在开发者工具中读取 `.terminal__scroll` 的 `scrollTop` / `scrollHeight` / `clientHeight`，可见距底部明显大于 0。

## 3. 根因分析

`src/terminal/components/Terminal.vue` 原实现只在 `store.chunks.length` / `input.value.length` 变化时调用一次 `scrollToBottom()`：

```ts
watch(
  () => [store.chunks.length, input.value.length] as const,
  () => {
    void nextTick(scrollToBottom)
  },
  { flush: 'post' },
)
```

时序如下：

1. `img` 命令写入 `html` chunk，Vue 更新 DOM，`watch` 触发 `scrollToBottom()`。
2. 此时 `<img>` 尚未加载完成，输出区高度按旧内容计算（749px），滚动到底部后 `scrollTop` 仍为 0。
3. 图片异步加载完成，`<img>` 产生 558px 的实际高度，`scrollHeight` 从 749 增至 1160。
4. **没有任何后续逻辑再次滚动**，因此 `scrollTop` 停在 0，距底部 411px。

`loading="lazy"` 不是根因（图片实际已 `complete: true`）；根因是**图片加载导致的异步高度变化没有触发滚动跟随**。同类问题也会出现在任何异步改变输出区高度的内容上（图片、`md` 内图片、字体/窗口尺寸变化等）。

## 4. 修复方案

在 `Terminal.vue` 中增加「贴底跟随」，不改命令契约与输出结构：

1. 新增 `stickToBottom` 状态与 `onScroll`：距底部 ≤ 24px 视为贴底；用户主动上滚后置为 `false`。
2. 在滚动容器上以**捕获阶段**监听图片 `load` / `error`（这两个事件不冒泡）：若当前贴底，`nextTick` 后滚动到底。
3. 用 `ResizeObserver` 观察 `.terminal-output`：输出区高度变化（图片加载、窗口缩放等）时，若贴底则滚动到底；作为 `load` 事件的兜底。
4. `chunks` / 输入变化时仍恢复贴底并滚动（保持既有「执行命令后跳到底部」行为）；用户上滚阅读历史时，异步图片加载不会强行拉回。
5. `onBeforeUnmount` 中移除 `load` / `error` 监听并 `disconnect` observer，避免组件销毁后泄漏。

未修改 `img` 的 HTML / CSS（仍为 `loading="lazy"` / `decoding="async"`、`max-width:100%`、`max-height:70vh`）。
