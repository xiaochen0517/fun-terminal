## 1. 需求背景

M4 之后，终端已经能「知道自己在哪、能走到别处、能回看历史」，但**仍然看不到任何文件内容**：VFS 只有目录，`ls` / `cat` 尚未注册，访客输入 `ls` 只会得到「未找到命令」。一个只能 `cd` 却看不到任何东西的终端，还不能称为「文件系统」；M6 的插件挂载、M7 的文章数据、M8 的博客浏览都要靠这两条命令来验证和阅读。

当前代码的真实状态：

| 项 | 现状 | M5 需要改变的部分 |
| --- | --- | --- |
| `src/commands/builtin/` | 只有 `echo` / `help` / `clear`（M2）与 `pwd` / `cd` / `history`（M4） | 新增 `ls` / `cat` 两条核心命令 |
| VFS 初始树 | `/`、`/home/guest`、`/mnt` 均为目录；home 与 `/mnt` 为空 | home 下内置 3 个只读示例节点（Q-01），`/mnt` 仍为空、挂载规则不变 |
| `help` | 6 条命令 | 8 条命令（自动从注册表生成，无需改 `help` 实现） |
| `VfsNode` | 只有 `name` / `type` / `parent` / `children` / `content` / `meta`，**没有 size / mtime** | `ls -l` 的大小由 `content` 计算 UTF-8 字节数；不展示属主、时间 |
| `~` 展开 | 私有实现于 `cd.ts`（`expandHomeArgument`） | 抽成命令层共享工具，`cd` / `ls` / `cat` 共用（Q-08） |
| 路径解析 | `resolve(cwd, 参数)` + `ctx.vfs.resolve` | 两命令沿用同一模式，命令内不复写 `.` / `..` / 反斜杠规则 |
| `terminal-store.spec.ts` | 用 `ls -la /mnt` 作为「未知命令」样例 | 改用真正的未知命令，并补 `ls` / `cat` 集成用例 |
| 输出模型 | `text` / `error` 已够用 | **不新增 chunk 类型**；两命令只写 `text` 与 `error` |
| 组件 / 执行器 / 解析器 / 注册表 / VFS | M1–M4 已验收 | 零改动 |

**为什么现在做 M5**：

- **VFS 第一次被真实命令消费**：M3 的 `readDir` / `readFile` / `resolve` 至今没有生产调用方，`ls` / `cat` 会一次性暴露目录读取、文件读取、不存在分支的真实用法；接口若有不顺手之处，现在调整最便宜。
- **M6 的挂载验证依赖 `ls`**：插件把内容树挂到 `/mnt/blog`、`/mnt/demo` 后，访客与验收人只能靠 `ls` 确认「挂载是否成功、目录里有什么」；没有 `ls`，M6 的演示无法自证。
- **M8 的 `blog read --raw` 要复用 `cat` 能力**：文本读取、二进制识别、末尾换行处理应先在核心命令里固化，插件只做自己的展示层，避免每个内容插件各写一套读取逻辑。
- **`cat` 需要可演示的文本**：M5 阶段还没有任何插件内容，若不补示例文件（Q-01），`cat` 只能靠单测覆盖，无法完成 GUI 人工验收，违背「每个里程碑可独立演示」的原则。
- **错误文案与路径约定需要一次收口**：`ls` / `cat` 之后还有 `blog` / `img` / `mount` 等命令，逐参数报错、`~` 展开、选项拒绝的写法越早统一，后续越少返工。

## 2. 需求描述

### 2.1 目标

让访客能**看见目录、读懂文件**：`ls` 浏览目录与文件属性，`cat` 读取文本内容；两者都基于核心 VFS，不依赖任何插件，安装插件前后行为一致。

```
                         ┌─ 选项校验（ls: -a/-l；cat: -n）
 用户输入 ls / cat ──────┤
                         ├─ 逐参数 resolvePathArgument（~ 展开 → path.resolve(cwd, …)）
                         ├─ ctx.vfs.resolve(target) → VfsNode
                         └─ 目录：隐藏过滤 → 排序 → 格式化 ─────────► text
                            文件：图片/二进制/大小/换行/编号判断 ──► text | error
```

两条命令只做「读上下文 → 查询 VFS → 写输出」：**不改组件、不改执行器、不改 Store、不改 `CommandContext` 契约**（只新增一个命令层共享的路径工具与一份 home 示例内容）。

### 2.2 用户可见行为

1. **`help`**：列出全部 8 条命令（`cat`、`cd`、`clear`、`echo`、`help`、`history`、`ls`、`pwd`），仍按名称升序、两列对齐；`help ls` / `help cat` 展示说明与用法。
2. **`ls`**：无参数列出 `cwd`；默认**一行一个条目**，目录名追加 `/`（如 `notes/`），以 `/` 后缀与文件区分；默认隐藏以 `.` 开头的条目。
3. **`ls -a`**：显示隐藏条目，并在目录内容最前面额外列出 `.` 与 `..`（根目录不列 `..`）；显式把隐藏路径作为参数时，无论是否带 `-a` 都正常处理。
4. **`ls -l`**：每行一条，格式为「权限位 + 大小 + 名称」；目录权限统一 `drwxr-xr-x`、大小显示 `-`，文件权限统一 `-rw-r--r--`、大小为 UTF-8 字节数；大小列右对齐，宽度取所有待显示条目的最大值（至少 6）；不输出 `total`、属主、组、时间。
5. **`ls -al`**：同时具备 3、4 两条行为。
6. **`ls` 的路径参数**：支持相对路径、绝对路径、`~`、`~/子路径`、`.`、`..`、重复斜杠、结尾斜杠与反斜杠；文件作为参数时输出该参数原文（如 `ls README.md` 输出 `README.md`，`ls -l README.md` 输出一行长格式）。
7. **`ls` 多路径**：按参数顺序逐个输出；存在多个操作数且其中有目录时，目录前输出 `路径:` 表头，块与块之间空一行；单个路径不存在只报该路径的错误，其余参数继续输出；空目录在单参数时不输出任何内容（Unix 行为），在多参数时只输出表头。
8. **`cat`**：按参数顺序读取文本文件，**原样保留**缩进、空行、Markdown 标记；文件末尾没有换行时补一个换行，避免下一次提示符与正文粘连；文件已以换行结尾时不重复追加。
9. **`cat -n`**：为每一行加行号，行号右对齐 6 位、后跟一个制表符（与 GNU `cat -n` 一致）；空行也编号；多文件时行号**连续**，不按文件重置。
10. **`cat` 多文件**：内容按参数顺序连续拼接；某个文件失败时输出该文件的错误后继续处理后续文件，不吞掉其他文件的内容，也不打乱输出顺序。
11. **`cat` 的错误**：目录、文件不存在、图片、二进制、文件过大、缺少参数、不支持的选项、`~user`、`HOME` 缺失，分别给出明确中文提示；全部走 `error` 块，`cwd` 与会话不受影响。
12. **`~` 与相对路径**：`cat ~/README.md`、`cd notes` 后 `cat welcome.txt`、`ls ..` 均按当前 `cwd` 正确解析；`~` 只支持 `~` 与 `~/...`，`~user` 明确报错。
13. **窄屏**：375px 下 `cat` 的长行、`ls -l` 的长行自动换行、无横向滚动条，输入行仍可点击聚焦。
14. **刷新**：`cwd` 回到 `/home/guest`、历史清空，`ls` / `cat` 可重新使用（会话不持久化，沿用 D-08）。
15. **无噪音**：成功时不写 `console.*`、不产生未处理 Promise rejection；错误不 `throw`，不打断串行队列。

> **访客不可见但必须成立**：`ls` / `cat` 不 import Store、`window`、`fetch` 或静态文件，只通过 `CommandContext` 取数据；VFS 仍只读，两命令没有任何写路径。

### 2.4 范围边界

**本次包含**：

- `ls`：`-a`、`-l`、多路径、文件参数、隐藏过滤、排序、空目录、逐参数错误。
- `cat`：`-n`、多文件、末尾换行、行号连续、图片/二进制/超限/目录/不存在识别。
- 命令层共享的 `~` 展开与路径解析工具（`cd` 行为不变）。
- home 只读示例内容（`README.md`、`notes/welcome.txt`、`.profile`），使 `cat` 与 `ls -a` 可独立验收。
- 两条命令的单测、集成测试与文档回写。

**本次不包含**：

| 能力 | 负责里程碑 / 说明 |
| --- | --- |
| `ls -R` 递归、`-h` 人类可读大小、`--color`、`-t` / `-S` / `-r` 排序选项、`-d` | 本期不做；`-h` 与排序选项列入 Backlog，真有需求时再评审 |
| `ls` 默认多列自适应、目录着色 | Q-02 建议 M5 用单列 + `/` 后缀；多列与着色需要终端宽度测量/富文本，与 M10 响应式一起评估 |
| `ls -l` 的 `total` 合计、真实权限位、属主/组、mtime、链接数 | VFS 只读且 `VfsNode` 无这些字段；统一展示固定权限位与字节大小 |
| `cat -A` / `-b` / `-s` / `-v`、语法高亮、分页（`less` / `more`） | 本期不做；M10 再评估输出上限与分页 |
| 读取 stdin（`cat` 不带文件时从管道读） | 浏览器无 stdin；无参数时给出用法提示 |
| 文件写入、权限模型、符号链接、真实本地目录 | VFS 一期只读，`mkdir` / `rm` / `touch` 不在一期 |
| 路径/参数 Tab 补全、`Ctrl+L` / `Ctrl+C`、输出条数上限、移动端深度适配 | M10 |
| 博客正文、图片渲染、插件挂载内容 | M7 / M8 / M9；M5 只读取核心 VFS 中的现有节点 |
| 文章原文与 `blog read --raw` 的同源校验 | M8；M5 的 `cat` 只要对 VFS 文本通用即可 |
| 命令历史持久化、跨会话状态 | 不做（D-08：刷新即重置） |

## 3. 方案设计

### 3.1 总体结构与职责

| 模块 | 职责 | 变更 |
| --- | --- | --- |
| `src/commands/builtin/ls.ts` | 选项校验 → 逐参数解析 → 目录/文件格式化 → 输出 | 新增 |
| `src/commands/builtin/cat.ts` | 选项校验 → 逐文件解析 → 分类/阈值/换行/编号 → 输出 | 新增 |
| `src/commands/builtin/path-argument.ts` | `~` 展开与「参数 → 绝对路径」的唯一实现，供 `cd` / `ls` / `cat` 共用 | 新增 |
| `src/commands/builtin/cd.ts` | 复用共享 `~` 展开，行为与文案不变 | 小改（去重） |
| `src/fs/home-content.ts` | home 只读示例内容（README / notes / .profile），每次调用返回全新节点 | 新增 |
| `src/fs/index.ts` | 创建初始树时把示例内容挂到 home 节点 | 小改 |
| `src/commands/builtin/index.ts` | 注册 `ls` / `cat` | 追加 2 条 |
| `src/fs/path.ts`、`src/fs/vfs.ts`、`src/fs/mount.ts`、`src/fs/build.ts` | 路径/VFS/挂载/构建器 | **零改动** |
| `src/terminal/context/CommandContext.ts`、`executor/context.ts`、`stores/terminal.ts` | 契约与会话 | **零改动**（两命令只用既有 `cwd` / `env` / `vfs` / `output`） |
| 组件、`theme.css`、解析器、注册表、执行器 | UI 与命令链路 | **零改动**（只输出 `text` / `error`） |

约束：

- 两条命令不 import Store / `window` / `fetch` / 静态文件（PLAN 第 6 节第 2 条），只通过 `CommandContext` 取数据。
- 路径统一走 `@/fs/path` 的 `resolve` 与 `ctx.vfs.resolve`；命令内**不复写** `.` / `..` / 重复斜杠 / 反斜杠 / 尾斜杠规则。
- 可预期失败（选项非法、路径不存在、目标是目录、文件过大）由命令写 `error` 块并正常返回；未捕获异常才由执行器兜底。
- 成功输出只写 `text`，不产生 `html` chunk；`v-html` 与转义问题在本里程碑不引入。

### 3.2 共享参数处理（`path-argument.ts`）

#### 3.2.1 动机

`cd` 已实现 `~` 展开，但函数私有且错误文案硬编码 `cd:`。`ls` / `cat` 若各复制一份，三处语义（`~`、`~user`、`HOME` 缺失）会逐渐漂移。抽成共享工具，`cd` 行为与文案**保持不变**，由既有 28 条 `cd` 用例回归保护。

```ts
// src/commands/builtin/path-argument.ts
import { resolve } from '@/fs/path'
import type { CommandContext } from '@/terminal/context/CommandContext'

export type PathArgumentResult =
  | { ok: true; target: string }
  | { ok: false; message: string }

/** 展开 `~` / `~/...`；`~user` 与其他形态明确报错（错误前缀取 command） */
export function expandHomeArgument(
  command: string,
  argument: string,
  env: Record<string, string>,
): PathArgumentResult {
  if (argument !== '~' && !argument.startsWith('~/')) {
    if (argument.startsWith('~')) {
      return { ok: false, message: `${command}: 不支持 ~user 形式: ${argument}` }
    }
    return { ok: true, target: argument }
  }

  const home = env.HOME
  if (!home) {
    return { ok: false, message: `${command}: 无法确定 home 目录（HOME 未设置）` }
  }
  return { ok: true, target: argument === '~' ? home : `${home}${argument.slice(1)}` }
}

/** 展开 `~` 后基于 cwd 解析为绝对路径（不校验存在性，交给 VFS） */
export function resolvePathArgument(
  command: string,
  argument: string,
  ctx: CommandContext,
): PathArgumentResult {
  const expanded = expandHomeArgument(command, argument, ctx.env)
  if (!expanded.ok) return expanded
  return { ok: true, target: resolve(ctx.cwd, expanded.target) }
}
```

#### 3.2.2 选项校验

只做「白名单外即拒绝」，不解析选项值（`ls` / `cat` 都是布尔开关）：

```ts
/** 返回错误文案；全部合法时返回 null */
export function rejectUnknownOptions(
  command: string,
  options: Record<string, string | boolean>,
  allowed: readonly string[],
): string | null {
  const unknown = Object.keys(options).filter((key) => !allowed.includes(key))
  return unknown.length > 0 ? `${command}: 不支持的选项: ${unknown.join(' ')}` : null
}
```

- 由解析器保证 `-la` 已拆成 `-l` / `-a`，命令侧只处理离散键。
- `--` 之后全部是位置参数（解析器行为），命令无需特殊处理。
- `cd` / `help` 本期不迁移到该函数，避免无意义的既有命令改动。

### 3.3 `ls` 命令

#### 3.3.1 处理顺序（任一选项错误即整体返回，不输出清单）

| 顺序 | 判断 | 行为 |
| --- | --- | --- |
| 1 | `rejectUnknownOptions('ls', options, ['-a', '-l'])` 非空 | 输出错误并返回，**不列任何目录** |
| 2 | 无位置参数 | 以 `ctx.cwd` 作为唯一操作数（错误文案也用 `ctx.cwd`） |
| 3 | 预解析全部操作数 | 逐个 `resolvePathArgument` → `ctx.vfs.resolve`；记录节点或错误，保持参数顺序 |
| 4 | 判断格式 | `-l` 决定长格式；`-a` 决定隐藏与 `.` / `..` |
| 5 | 逐个输出 | 错误 → `error` 块；目录/文件 → `text` 块，按 3.3.3 / 3.3.4 处理分隔 |

#### 3.3.2 默认格式（单列 + `/` 后缀）

```text
$ ls
notes/
README.md

$ ls -a
.
..
.profile
notes/
README.md

$ ls /
home/
mnt/

$ ls -a /
.
home/
mnt/
```

- 一行一个条目，目录追加 `/`；`.` / `..` 是合成条目，**不加** `/`（与真实 `ls -a` 一致）。
- 目录与文件无需颜色即可区分；不做列宽填充、不做多列拼接（理由见 Q-02）。
- 空目录单参数 → 不输出 chunk；空目录多参数 → 只输出 `路径:` 表头。
- 根目录的 `-a` 列表只有 `.`（没有 `..`），是唯一特例；`ls ..` 仍可显式访问父目录。

#### 3.3.3 长格式（`-l`）

```text
$ ls -l
drwxr-xr-x       -  notes/
-rw-r--r--     363  README.md

$ ls -al
drwxr-xr-x       -  .
drwxr-xr-x       -  ..
-rw-r--r--      84  .profile
drwxr-xr-x       -  notes/
-rw-r--r--     363  README.md
```

- 列：`权限(10) + 2 空格 + 大小(右对齐 width) + 2 空格 + 名称`。
- 权限固定：目录 `drwxr-xr-x`，文件 `-rw-r--r--`；一期没有真实权限位，不做 `chmod` 语义。
- 大小：文件为 `content` 的 **UTF-8 字节数**（`new TextEncoder().encode(content).byteLength`），目录为 `-`；空文件为 `0`。
- `width = max(6, 所有待显示文件大小字符串的最大长度)`：多路径时全局统一，保证跨目录块的大小列对齐。
- 不输出 `total`、属主、组、mtime、链接数；`VfsNode` 没有这些字段，不为一期伪造。

#### 3.3.4 多操作数与分隔

**预解析**（先全部 resolve，再输出）保证「任意参数是目录」可在输出前确定，从而决定表头与空行：

| 场景 | 输出 |
| --- | --- |
| 单参数目录 | 只输出内容，无表头 |
| 单参数文件 | 输出参数原文（`-l` 时为长格式行） |
| 多参数，全部是文件 | 每个文件一行/一长行，**连续输出、无表头、无空行** |
| 多参数，含至少一个目录 | 每个目录前输出 `参数原文:` 表头；所有 text 块之间空一行（首块前不加） |
| 某参数失败 | 立即输出该参数的 `error` 块，继续处理后续参数；错误块不参与「首块」计数 |

```text
$ ls /mnt /home
/mnt:

/home:
guest/

$ ls README.md /mnt
README.md

/mnt:

$ ls nope /
ls: 无法访问 nope: 目录不存在
/:
home/
mnt/
```

- 表头使用参数**原文**（`ls ~` 的目录头是 `~:`，不是展开后的路径）。
- 空目录作为多参数之一时只输出表头，下一块仍以空行分隔。
- 错误文案中的路径也用参数原文，不拼接引号、不做二次解析（与 M4 `cd` 约定一致）。

#### 3.3.5 隐藏条目与排序

| 规则 | 说明 |
| --- | --- |
| 隐藏判定 | 节点名以 `.` 开头即隐藏；`.profile` 默认不显示 |
| `-a` | 显示隐藏条目，并在最前面合成 `.`（所有目录）与 `..`（根除外） |
| 显式参数 | 直接传入 `.profile` / `.hidden/` 时正常处理，不受 `-a` 影响（Unix 行为） |
| 排序 | `Intl.Collator('zh-Hans-CN', { numeric: true })` 升序：中文按拼音、数字自然序（`file2` 在 `file10` 前）、大小写按中文排序规则 |
| 稳定性 | 排序在过滤后、格式化前完成；`.` / `..` 固定在最前，不参与排序 |

> 使用显式 locale 而不是依赖运行环境默认排序，保证开发机、CI 与浏览器行为一致；若某环境缺少该 locale，`Intl.Collator` 会回退到默认排序，`ls.spec.ts` 的 ASCII 用例仍稳定，中文排序用例依赖 Node 完整 ICU（项目 engines 已要求 Node 22/24）。

#### 3.3.6 实现骨架

```ts
const DIRECTORY_PERMISSIONS = 'drwxr-xr-x'
const FILE_PERMISSIONS = '-rw-r--r--'
const NAME_COLLATOR = new Intl.Collator('zh-Hans-CN', { numeric: true })

interface LsOperand {
  argument: string
  node: VfsNode | null
  error?: string
}

function utf8Bytes(text: string): number {
  return new TextEncoder().encode(text).byteLength
}

function collectOperands(ctx: CommandContext): LsOperand[] {
  const args = ctx.args.length > 0 ? ctx.args : [ctx.cwd]
  return args.map((argument) => {
    const resolved = resolvePathArgument('ls', argument, ctx)
    if (!resolved.ok) return { argument, node: null, error: resolved.message }
    const { node } = ctx.vfs.resolve(resolved.target)
    if (!node) {
      return { argument, node: null, error: `ls: 无法访问 ${argument}: 目录不存在` }
    }
    return { argument, node }
  })
}

export const lsCommand: Command = {
  name: 'ls',
  description: '列出目录内容',
  usage: 'ls [-a] [-l] [路径...]',
  execute(ctx) {
    const optionError = rejectUnknownOptions('ls', ctx.options, ['-a', '-l'])
    if (optionError) {
      ctx.output.push({ type: 'error', content: optionError })
      return
    }

    const showAll = Boolean(ctx.options['-a'])
    const longFormat = Boolean(ctx.options['-l'])
    const operands = collectOperands(ctx)
    const multiple = operands.length > 1
    const hasDirectory = operands.some((operand) => operand.node?.type === 'directory')
    const sizeWidth = longFormat ? measureSizeWidth(operands, showAll) : 0

    let wroteText = false
    for (const operand of operands) {
      if (operand.error) {
        ctx.output.push({ type: 'error', content: operand.error })
        continue
      }

      const node = operand.node!
      const lines =
        node.type === 'directory'
          ? formatDirectory(node, { showAll, longFormat, sizeWidth })
          : [formatFile(operand.argument, node, longFormat, sizeWidth)]

      if (lines.length === 0) {
        if (node.type === 'directory' && multiple) {
          ctx.output.write(`${wroteText && hasDirectory ? '\n' : ''}${operand.argument}:`)
          wroteText = true
        }
        continue
      }

      const body = lines.join('\n')
      const withHeader =
        node.type === 'directory' && multiple ? `${operand.argument}:\n${body}` : body
      ctx.output.write(`${wroteText && hasDirectory ? '\n' : ''}${withHeader}`)
      wroteText = true
    }
  },
}
```

> 骨架只示意控制流；`formatDirectory` / `formatFile` / `measureSizeWidth` 需按 3.3.2–3.3.5 实现，`node.parent === null` 用于判断根目录。错误分支持续输出、成功分支为空目录时不写 chunk，均由单测锁定。

### 3.4 `cat` 命令

#### 3.4.1 处理顺序

| 顺序 | 判断 | 行为 |
| --- | --- | --- |
| 1 | `rejectUnknownOptions('cat', options, ['-n'])` 非空 | 输出错误并返回 |
| 2 | 无位置参数 | 输出 `cat: 缺少文件参数（用法: cat [-n] <文件...>）` 并返回 |
| 3 | 逐个参数 | `resolvePathArgument('cat', arg, ctx)` → `ctx.vfs.resolve(target)` |
| 4 | 节点不存在 | `cat: <参数原文>: 文件不存在`，继续下一个 |
| 5 | 节点是目录 | `cat: <参数原文>: 是一个目录`，继续下一个 |
| 6 | 分类为图片 / 二进制 | 对应错误，继续下一个 |
| 7 | 超过大小阈值 | `cat: <参数原文>: 文件过大（超过 200 KB），无法显示`，继续下一个 |
| 8 | 文本 | 确保末尾换行 → 可选编号 → 写一个 `text` chunk |

- 所有错误走 `error` 块；`cat` 从不 `throw`，不修改 `cwd`。
- 多文件时**每个可读文件一个 `text` chunk**，错误 chunk 插在对应位置；视觉上连续，不额外插入空行。
- 文件内容为空（`content === ''`）时不写 chunk（Unix 行为），也不占行号。

#### 3.4.2 图片 / 二进制判定

判定顺序固定为「`meta.mime` → 扩展名 → 内容 NUL 嗅探」，避免无 mime 的 `.png` 被当作文本乱码：

| 输入证据 | 分类 | 结果 |
| --- | --- | --- |
| `meta.mime` 以 `image/` 开头 | 图片 | `cat: <arg>: 图片文件无法以文本方式显示，请使用 img 查看` |
| `meta.mime` 为 `text/*` 或 `application/json` / `xml` / `javascript` / `yaml` / `x-yaml` | 文本 | 正常读取 |
| `meta.mime` 为其他类型（如 `application/pdf`、`application/octet-stream`） | 二进制 | `cat: <arg>: 二进制文件，无法以文本方式显示` |
| 无 mime，扩展名属于图片集合（`png` / `jpg` / `jpeg` / `gif` / `webp` / `svg` / `bmp` / `ico` / `avif`） | 图片 | 同上 |
| 无 mime，扩展名属于二进制集合（`pdf` / `zip` / `gz` / `tar` / `rar` / `7z` / `mp3` / `mp4` / `wav` / `webm` / `ogg` / `woff` / `woff2` / `ttf` / `otf` / `eot` / `wasm` / `exe` / `dll` / `bin` / `dat`） | 二进制 | 同上 |
| 无 mime，且扩展名不属于图片 / 二进制集合（含文本扩展名与无扩展名） | 文本候选 | 进入 NUL 嗅探 |
| 文本候选且内容含 `\0` | 二进制 | 同上 |
| 文本候选且内容不含 `\0` | 文本 | 正常读取 |

- `svg` 归图片：M9 支持 svg 展示，`cat` 不应把 XML 源码当正文倾倒。
- 图片提示现在就指向 `img`：M5–M8 没有任何图片节点，访客不会看到该文案；M9 挂载图片后文案已经正确，无需再改一次。
- 大小阈值：`200 * 1024 = 204800` 字节（按 UTF-8 计）；`== 204800` 允许，`204801` 拒绝。分类先于阈值，避免大图片被误报为「文件过大」。

#### 3.4.3 末尾换行与 `-n` 编号

```ts
const MAX_TEXT_BYTES = 200 * 1024

function ensureTrailingNewline(content: string): string {
  return content.endsWith('\n') ? content : `${content}\n`
}

function numberLines(content: string, start: number): { text: string; next: number } {
  const lines = ensureTrailingNewline(content).split('\n')
  if (lines[lines.length - 1] === '') lines.pop()
  let counter = start
  const text = lines
    .map((line) => `${String(counter++).padStart(6)}\t${line}`)
    .join('\n')
  return { text: text === '' ? '' : `${text}\n`, next: counter }
}
```

- 行号固定 6 位右对齐 + `\t`（GNU `cat -n`），超过 6 位时自然变宽（不做截断）。
- 空行照常编号：内容 `a\n\nb` 编号为 `1 a`、`2 <空>`、`3 b`。
- 多文件共享一个递增计数器；空文件、错误文件不推进计数器。
- 不加 `-n` 时原样输出；已在末尾有换行的文件不重复追加，保留原有多个尾随空行。

#### 3.4.4 实现骨架

`utf8Bytes` 与 3.3.6 相同（`new TextEncoder().encode(text).byteLength`）；两条命令各自定义 3 行即可，不为它单独新增模块。

```ts
const IMAGE_EXTENSIONS = new Set(['png', 'jpg', 'jpeg', 'gif', 'webp', 'svg', 'bmp', 'ico', 'avif'])
const BINARY_EXTENSIONS = new Set([
  'pdf', 'zip', 'gz', 'tar', 'rar', '7z', 'mp3', 'mp4', 'wav', 'webm', 'ogg',
  'woff', 'woff2', 'ttf', 'otf', 'eot', 'wasm', 'exe', 'dll', 'bin', 'dat',
])
const TEXT_MIME = /^(?:text\/|application\/(?:json|xml|javascript|x-yaml|yaml)$)/

function extensionOf(name: string): string {
  const index = name.lastIndexOf('.')
  return index <= 0 ? '' : name.slice(index + 1).toLowerCase()
}

function classify(node: VfsNode): 'text' | 'image' | 'binary' {
  const mime = node.meta?.mime
  if (mime) {
    if (mime.startsWith('image/')) return 'image'
    if (TEXT_MIME.test(mime)) return 'text'
    return 'binary'
  }
  const ext = extensionOf(node.name)
  if (IMAGE_EXTENSIONS.has(ext)) return 'image'
  if (BINARY_EXTENSIONS.has(ext)) return 'binary'
  // 其余（含文本扩展名与无扩展名）按内容判断：含 NUL 视为二进制
  return (node.content ?? '').includes('\0') ? 'binary' : 'text'
}

export const catCommand: Command = {
  name: 'cat',
  description: '查看文本文件内容',
  usage: 'cat [-n] <文件...>',
  execute(ctx) {
    const optionError = rejectUnknownOptions('cat', ctx.options, ['-n'])
    if (optionError) {
      ctx.output.push({ type: 'error', content: optionError })
      return
    }
    if (ctx.args.length === 0) {
      ctx.output.push({
        type: 'error',
        content: 'cat: 缺少文件参数（用法: cat [-n] <文件...>）',
      })
      return
    }

    const numbered = Boolean(ctx.options['-n'])
    let lineNumber = 1

    for (const argument of ctx.args) {
      const resolved = resolvePathArgument('cat', argument, ctx)
      if (!resolved.ok) {
        ctx.output.push({ type: 'error', content: resolved.message })
        continue
      }

      const { node } = ctx.vfs.resolve(resolved.target)
      if (!node) {
        ctx.output.push({ type: 'error', content: `cat: ${argument}: 文件不存在` })
        continue
      }
      if (node.type === 'directory') {
        ctx.output.push({ type: 'error', content: `cat: ${argument}: 是一个目录` })
        continue
      }

      const kind = classify(node)
      if (kind === 'image') {
        ctx.output.push({
          type: 'error',
          content: `cat: ${argument}: 图片文件无法以文本方式显示，请使用 img 查看`,
        })
        continue
      }
      if (kind === 'binary') {
        ctx.output.push({
          type: 'error',
          content: `cat: ${argument}: 二进制文件，无法以文本方式显示`,
        })
        continue
      }

      const content = node.content ?? ''
      if (utf8Bytes(content) > MAX_TEXT_BYTES) {
        ctx.output.push({
          type: 'error',
          content: `cat: ${argument}: 文件过大（超过 200 KB），无法显示`,
        })
        continue
      }
      if (content === '') continue

      if (numbered) {
        const numberedResult = numberLines(content, lineNumber)
        lineNumber = numberedResult.next
        if (numberedResult.text !== '') ctx.output.write(numberedResult.text)
      } else {
        ctx.output.write(ensureTrailingNewline(content))
      }
    }
  },
}
```

### 3.6 契约与零改动说明

- **`CommandContext` 不变**：`ls` 用 `ctx.args` / `ctx.options` / `ctx.cwd` / `ctx.env` / `ctx.vfs` / `ctx.output`；`cat` 使用 `ctx.args` / `ctx.options` / `ctx.cwd` / `ctx.env` / `ctx.vfs` / `ctx.output`。没有新字段、没有新访问器。
- **`Vfs` 不变**：只用 `resolve` 取节点后读 `children` / `content`，不调用 `readDir` / `readFile`（避免 `readFile` 对目录返回 `null` 的语义混淆），也不触碰任何写能力。
- **`OutputChunk` 不变**：只写 `text` / `error`，不新增 `html`。
- **组件不变**：`TerminalOutput.vue` 已能渲染 `text` / `error`；单列输出与长行换行由既有 `white-space: pre-wrap` 处理。
- **`theme.css` 不变**：没有新 class；`cat -n` 的制表符按浏览器默认 8 列展开，与真实 `cat` 一致。
- **`help` 不变**：命令从 `ctx.commands` 动态生成，注册后自动出现。
