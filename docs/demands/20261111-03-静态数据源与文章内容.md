## 1. 需求背景

**为什么现在做 M7**：

- **M8 / M9 唯一的前置**：`blog list` / `blog read` 需要文章清单与正文，`/mnt/blog` 需要由同一份清单投影；没有真实数据，M8 无法开工。M9 的画廊清单也会沿用 M7 的模式。
- **先把「单一数据源」定死，再写命令**：M8 的 `blog read --raw` 与 `cat /mnt/blog/<id>.md` 必须读到同一份正文。若 M8 先写命令、后补数据层，极易把文章正文直接写进插件，导致两处维护、内容漂移（PLAN 第 8 节风险表已有该条目）。

- **无可见变化，变更风险低**：M7 不新增命令、不挂载路径、不改组件与主题，是 M8 之前最安全的一块地基；按 `AGENTS.md` 第三节与用户意见，纯数据变化不需要人工验收。

## 2. 需求描述

### 2.1 目标

把 `DataSource` 从占位实现替换为真实的 `StaticDataSource`：**元数据用 `public/content/articles/index.json` 声明，正文是 `public/content/articles/<id>.md`，运行时通过 `fetch` 按需加载**；用纯函数完成元数据校验、归一化、日期倒序排序与冻结，提供「按日期倒序的摘要列表」与「按 id 读取完整正文」两个异步方法，并保证失败可降级、返回值不可变。

本里程碑**不新增任何命令、不挂载任何路径、不改变任何可见输出**，目标是把 M8 所需的唯一内容来源准备好，并用自动化门禁锁死数据一致性。

```
构建期
  public/content/articles/{index.json, hello.md, about.md, vfs-notes.md}
        └─ 原样复制到 dist/content/articles/（不进 JS bundle，不内联正文）

运行期（首次调用数据源方法时）
  createStaticDataSource({ baseUrl = import.meta.env.BASE_URL })
        ├─ fetchArticleList()
        │     └─ fetch(`${baseUrl}content/articles/index.json`)   （只请求一次）
        │           └─ buildArticleCatalog(articles)
        │                 ├─ 校验并归一化（id / 标题 / 日期 / 摘要 / 标签）
        │                 ├─ 跳过非法条目、保留先出现的重复 id
        │                 ├─ 排序：日期倒序，同日 id 升序
        │                 └─ 冻结摘要与 tags
        └─ fetchArticle(id)
              ├─ 命中清单后 fetch(`${baseUrl}content/articles/<id>.md`)（按 id 缓存）
              └─ 正文可用 → 组装并冻结 Article；不可用 → null + 告警一次

装配（零改动）
  src/data/index.ts → dataSource 单例
        └─ commandRuntime({ dataSource, ... }) → CommandContext.dataSource / PluginApi.dataSource
              └─ M8 的 blog 命令与 /mnt/blog 投影（本里程碑不实现）
```

### 2.2 交付行为（数据层，非 GUI）

本里程碑不改变任何用户可见输出。以下行为由 5.1 的自动化验收逐项断言：

1. **启动不加载数据**：应用启动、命令装配、页面首屏都不请求文章资源；只有首次调用 `fetchArticleList()` / `fetchArticle()` 才发起 `fetch`。
2. **清单一次加载**：`fetchArticleList()` 返回 3 条摘要，顺序为 `vfs-notes`（2026-11-10）、`about`（2026-11-08）、`hello`（2026-11-06）；每条含 `id` / `title` / `date` / `excerpt` / `tags`，**不含 `content`**；重复调用不会再请求清单。
3. **正文按需加载**：`fetchArticle('vfs-notes')` 首次请求 `content/articles/vfs-notes.md`，返回完整 `Article`，`content` 与文件内容**完全一致**（含结尾换行）；再次调用命中缓存，不重复请求。
4. **未知 id 不请求正文**：`fetchArticle('nope')`、`fetchArticle('')`、`fetchArticle('../hello')`、`fetchArticle('Hello')` 均返回 `null`，不抛错、不写输出；只可能因判断清单而请求清单，不会请求正文。
5. **非法参数不发请求**：运行时传入非字符串 id（如 `undefined`）直接返回 `null`，不发任何请求。
6. **URL 跟随部署路径**：默认以 `import.meta.env.BASE_URL` 为根拼接，`/`、`/site/`、`https://cdn.example.com/site/` 三种 base 均能得到正确 URL；子路径部署无需改代码（M10 配置 `base` 即可）。
7. **多级缓存**：清单缓存（成功一次）、正文缓存（每个 id 成功一次）、文章对象缓存（同一 id 返回同一冻结实例）；`fetchArticleList()` 每次返回**新数组**（可安全排序），元素共享同一份冻结摘要。
8. **失败可降级、可重试**：清单网络错误 / 404 / JSON 非法 / 结构非法 → 空列表 + 告警一次，下一次调用重试；正文网络错误 / 404 → `null` + 告警一次，下一次调用重试。终端启动与既有命令不受影响。
9. **正文可用性检查**：空内容、含 NUL、超过 200 KB → `null` + 告警一次（`cat` 也无法显示）；缺少结尾换行 → 仍返回正文，但告警一次；真实数据不触发这些告警。
10. **元数据校验生效**：非法条目（非对象、id 非法/重复、标题/日期/摘要/标签非法）被跳过并记 issue，合法条目照常进入列表；重复 id 保留先出现者。真实数据 `issues` 为空。
11. **返回值不可变**：`Object.isFrozen()` 对每条摘要、每篇文章、每个 `tags` 数组均为 `true`。
12. **实例隔离**：`createStaticDataSource({ baseUrl, fetchImpl })` 注入自定义 `fetch` 时，与真实数据源互不影响；不同实例的缓存互不共享；空清单时列表 `[]`、正文 `null`。
13. **无可见变化**：`help` 仍为 10 条命令，`/mnt/demo` 内容不变，无新增命令、无新增输出块、无新增快捷键、无组件与样式改动；正常数据下控制台无新增 `console.warn` / `console.error`，无未处理 Promise rejection。
14. **数据与代码解耦（构建产物验证）**：`dist/content/articles/` 含 `index.json` 与 3 篇 `.md`；`dist/assets/*.js` 中**检索不到**文章正文标题，但能检索到清单 URL；`vite preview` 下直接请求清单与正文均返回 200。
15. **体积可控、零新增依赖**：相对 M6 构建基线（JS 96.86 kB / gzip 37.57 kB），M7 实测 JS 101.28 kB（gzip 39.21 kB），增量 **+4.42 kB（gzip +1.64 kB）**；CSS 不变（2.90 kB / gzip 1.02 kB）；不新增运行时/开发依赖。

### 3.2 目录与文件布局

```
public/
└── content/
    └── articles/
        ├── index.json            # 元数据清单（3 条）

        ├── about.md              # 2026-11-08
```

放置理由：

- **数据放 `public/content/articles/`**：`public/` 的资源原样复制到 `dist/`，适合「数据与代码分离」；新增/替换文章不需要改命令代码或重新打包数据。
- **元数据用 JSON 而非 TS 文件**：按用户评审意见，`index.json` 是纯数据、可被非开发者维护；运行时 `fetch` 后再校验（JSON 无类型保护，因此 `catalog.ts` 全面校验）。
- **`static/` 作为数据来源层**：未来 `ApiDataSource` 可与之并列放在 `src/data/api/`，`src/data/index.ts` 只切换实现，命令层无感。
- **不放 `src/fs/`**：VFS 是核心文件系统能力（M3 已定稿），文章是「数据」，M8 才把它投影为 `/mnt/blog`。

### 3.3 元数据清单（`public/content/articles/index.json`）

```json
{
  "articles": [
    {
      "id": "hello",
      "title": "你好，终端",
      "date": "2026-11-06",
      "excerpt": "这个站点为什么长成终端的样子，以及第一次进来可以先敲哪几条命令。",
      "tags": ["公告", "入门"]
    },
    {
      "id": "about",
      "title": "关于本站与作者",
      "date": "2026-11-08",
      "excerpt": "关于作者、这个站点的技术取舍，以及内容会怎么更新。",
      "tags": ["公告", "随笔"]
    },
    {
      "id": "vfs-notes",
      "title": "在浏览器里造一个文件系统",
      "date": "2026-11-10",
      "excerpt": "一个只读虚拟文件系统的设计笔记：路径、挂载与「只读契约」为什么值得。",
      "tags": ["技术", "前端", "终端"]
    }
  ]
}
```

约定：

- 清单声明顺序不代表展示顺序（展示按日期倒序），但保持「旧 → 新」便于 diff。
- `id` 一旦发布不轻易改名：M8 的 `/mnt/blog/<id>.md` 与 `blog read <id>` 都会暴露它。
- 新增文章 = 放一个 `articles/<id>.md` + 在 `index.json` 的 `articles` 数组加一条；两步缺一由 `articles.spec.ts` 的文件一致性断言拦截（3.9）。
- JSON 根为对象且必须含 `articles` 数组；结构非法时数据源告警一次并降级为空列表。

### 3.4 元数据校验（`catalog.ts`）

```ts
export type ArticleIssueKind =
  | 'invalid-entry'
  | 'invalid-id'
  | 'duplicate-id'
  | 'invalid-title'
  | 'invalid-date'
  | 'invalid-excerpt'
  | 'invalid-tags'

export interface ArticleIssue {
  kind: ArticleIssueKind
  source: string   // articles[<下标>]（可带 id）
  message: string  // 中文说明，已含定位信息
}

export interface ArticleCatalog {
  readonly summaries: readonly ArticleSummary[]
  readonly issues: readonly ArticleIssue[]
}

export function buildArticleCatalog(entries: readonly unknown[]): ArticleCatalog
```

校验规则（对应 `catalog.spec.ts`）：

| 字段 | 规则 | 违规 kind | 处理 |
| --- | --- | --- | --- |
| 条目形态 | 普通对象（非 `null` / 数组） | `invalid-entry` | 跳过 |
| `id` | 小写 kebab-case：`^[a-z0-9]+(?:-[a-z0-9]+)*$`，长度 1–64 | `invalid-id` | 跳过 |
| `id` 唯一 | 与已接受条目重复时保留先出现者 | `duplicate-id` | 跳过后者 |
| `title` | `trim()` 后非空、不含换行、长度 ≤ 120 | `invalid-title` | 跳过 |
| `date` | `YYYY-MM-DD`，且为真实日期（UTC 往返一致，拦 `2026-02-30`、非闰年 `02-29`） | `invalid-date` | 跳过 |
| `excerpt` | `trim()` 后非空、不含换行、长度 ≤ 200 | `invalid-excerpt` | 跳过 |
| `tags` | 数组，1–8 项；每项 `trim()` 后非空、不含空白、长度 ≤ 24；同一篇内不重复 | `invalid-tags` | 跳过 |

排序与冻结：

```ts
metas.sort((a, b) => {
  if (a.date !== b.date) return a.date < b.date ? 1 : -1 // 日期倒序
  return a.id < b.id ? -1 : a.id > b.id ? 1 : 0          // 同日按 id 升序（不依赖 locale）
})
```

- 只保留 `id` / `title` / `date` / `excerpt` / `tags`，未知字段丢弃。
- `tags` 复制后冻结（`Object.freeze([...tags]) as string[]`，类型沿用既有 `ArticleSummary`）；摘要对象与结果数组冻结。
- 不修改入参；`Object.freeze` 的 `Readonly<T>` 与既有契约的类型差异用一次显式断言收敛，**不修改** `DataSource`。

### 3.5 运行时加载（`StaticDataSource.ts`）

```ts
export interface FetchResponseLike {
  readonly ok: boolean
  readonly status: number
  json(): Promise<unknown>
  text(): Promise<string>
}
export type FetchLike = (url: string) => Promise<FetchResponseLike>

export interface StaticDataSourceOptions {
  /** 默认 import.meta.env.BASE_URL，兼容子路径部署 */
  baseUrl?: string
  /** 默认全局 fetch；测试注入替身 */
  fetchImpl?: FetchLike
  /** 默认 console.warn；测试捕获文案 */
  onWarn?: (message: string) => void
}

export function createStaticDataSource(options?: StaticDataSourceOptions): DataSource
```

路径与请求：

- 常量：`content/articles/index.json`、`content/articles/<id>.md`（`id` 做 `encodeURIComponent`）。
- `joinContentUrl(baseUrl, path)` 处理 `/`、`/site/`、`https://cdn/x/` 三种 base；已导出并有单测。
- 清单请求：`fetch(url)` → `ok` 判断 → `json()` → 根对象含 `articles` 数组 → `buildArticleCatalog(articles)`。
- 正文请求：命中清单后才请求；`text()` 后做正文可用性检查。

缓存策略：

| 缓存 | 粒度 | 失败处理 |
| --- | --- | --- |
| 清单 | 成功加载一次（`summaries`）；并发调用共享同一个 in-flight Promise | 失败不缓存，下次调用重试；告警按文案去重，只输出一次 |
| 正文 | 每个 id 成功一次（`Map<id, Promise<string \| null>>`） | 失败从缓存移除，下次调用重试 |
| 文章对象 | 每个 id 一个冻结 `Article` | 正文不可用时不生成 |

失败降级与告警（统一加前缀 `[fun-terminal] `，同文案只出现一次）：

| 场景 | 行为 |
| --- | --- |
| 清单 HTTP 非 2xx | 列表 `[]`，告警含状态码与 URL |
| 清单 JSON 解析失败 | 列表 `[]`，告警含解析错误 |
| 清单结构非法（根非对象 / 缺 `articles` / `articles` 非数组） | 列表 `[]`，告警提示 `{ "articles": [...] }` |
| 清单条目非法 | 跳过该条，列表保留合法条目，逐条告警 |
| 正文 HTTP 非 2xx / 网络错误 | `fetchArticle` 返回 `null`，告警 |
| 正文空、含 NUL、> 200 KB | `null`，告警（与 `cat` 的阈值/二进制规则一致） |
| 正文缺结尾换行 | 返回正文，告警一次（不静默修改内容） |
| 运行时 `fetch` 不存在 | 降级为空列表，告警「当前环境不支持 fetch」 |

其他约束：

- `fetchArticle` 先校验 `typeof id === 'string'`；非字符串直接 `null`，不发请求。
- `fetchArticleList()` 每次返回 `[...manifest]` 新数组，元素共享冻结摘要。
- 不读 `window`/`document`、不操作 DOM、不修改 VFS、不产生输出。
