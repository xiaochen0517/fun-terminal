## 1. 需求背景

M2 冻结了「解析 → 注册 → 执行 → 兜底 → 串行队列」链路，M3 落地了只读 VFS 与挂载，并把 `vfs` / `mounts` 注入 `CommandContext`。但**终端至今没有任何文件系统命令**：`help` 只列出 `echo` / `help` / `clear` 三条，`cd` / `pwd` / `history` 全部提示「未找到命令」。访客既看不到自己在哪，也无法移动——「终端」目前只是一个能回显、能清屏的输入框。

当前代码的真实状态：

| 项 | 现状 | M4 需要改变的部分 |
| --- | --- | --- |
| `src/commands/builtin/` | 只有 `echo` / `help` / `clear`（M2） | 新增 `pwd` / `cd` / `history` 三条核心命令 |
| `CommandContext` | 有 `cwd` / `setCwd` / `vfs` / `mounts`，**没有历史** | 新增 `history` 快照字段（Q-01） |
| 命令历史 | 只存在于 `stores/terminal.ts` 的 `history`，仅 ↑/↓ 组件读取 | 通过上下文供 `history` 命令读取，且与 ↑/↓ 共用同一份数据 |
| 提示符 | `PromptBar` 已从 `cwd` 派生、支持 home 缩写（M1） | 零组件改动：`cd` 调用 `ctx.setCwd` 后提示符自动同步 |
| `help` | 单列「名称 + 说明」，`help <命令>` 只有两行，不校验参数 | 表头/页脚、两列对齐、参数与选项校验、未知命令提示 |
| `src/fs/path.ts` 的 `isAbsolute` | 只认 `/` 前缀，`\mnt` 被当作相对路径 | 接受 `\` 前缀，兑现 M3 Q-06「反斜杠归一化」的既定意图（Q-08） |

**为什么现在做 M4**：

- **M5 的 `ls` / `cat` 以「用户能先 `cd` 到目录」为前提**：`ls` 不带参数时列的是 `cwd`，`cat` 的相对路径也基于 `cwd`。没有 `cd`，M5 只能靠绝对路径演示。
- **`history` 是契约缺口，越晚补越贵**：`CommandContext` 新增**必填**字段会让所有命令测试的伪造上下文一起改；在只有 3 条命令时补完，M5–M9 直接沿用。
- **提示符联动是 M1 人工验收过的高风险区**：`cwd` 第一次真正被命令修改，必须尽早暴露「回显提示符 / 输入行提示符 / `pwd` 三方不一致」的问题。
- **`cd` 是 M3 路径语义的第一个真实消费者**：`~` 展开、`.` / `..`、重复斜杠、反斜杠、根越界都会在这里一次性验证，问题暴露得越早，M5/M6 越稳。

## 2. 需求描述

### 2.1 目标

让终端具备完整的**自我导航能力**：知道自己在哪（`pwd`）、能移动到别处（`cd`）、能回看做过什么（`history`），并且提示符、命令回显与 `cwd` 三者始终一致。

```
               ┌──────────── 提示符（零改动） ────────────┐
               │ PromptBar ← cwd（Pinia Store，源）        │
               └────────────────▲─────────────────────────┘
                                │ ctx.setCwd(target)
   pwd      ──► ctx.cwd          │
   history  ──► ctx.history      │        cd ──► path.resolve(cwd, 展开后的参数)
   （Store 历史快照）             │              └─► ctx.vfs.resolve(target)
                                 │                    └─► 目录？→ setCwd
```

三条命令都只做「读上下文 → 写输出」：**不改组件、不改执行器、不改 Store 的数据结构**（只多一个 `getHistory` 访问器）。

### 2.2 用户可见行为

1. **`help`**：列出全部 6 条命令（`cd`、`clear`、`echo`、`help`、`history`、`pwd`），按名称升序两列对齐，带表头与「查看具体用法」页脚；`help <命令>` 给出说明与用法；`help <未知命令>` 报错并提示 `help`。
2. **`pwd`**：输出当前虚拟目录的绝对路径（如 `/home/guest`）；不接受参数与选项。
3. **`cd`**：切换目录**成功时完全静默**；下一次提示符路径段、后续命令回显中的提示符、`pwd` 输出三处立即一致。
   - 支持无参数（回 home）、`~`、`~/子路径`、绝对路径、相对路径、`.`、`..`、重复斜杠、结尾斜杠、反斜杠（如 `cd \mnt`）。
   - `cd ..` 在根目录不越界，`cd /mnt/../home` 与 `cd /home` 等价。
   - 目录不存在、目标不是目录、参数过多、带选项、`cd -`、`~user` 六类错误各自给出**明确中文提示**，且 `cwd` 保持不变。
4. **`history`**：输出带**右对齐序号**的命令历史，与 ↑/↓ 浏览的是同一份数据；`history` 自身也在列表中；连续重复的命令只出现一次（沿用 M1 的 Store 规则）；`clear` 清屏后历史仍完整。
5. **错误与提示**：错误统一走 `error` 输出块（红色），成功无噪音；不出现未处理异常、不打断会话。
6. **窄屏**：`history` / `help` 的长行在 375px 下自动换行、无横向滚动，输入行仍可聚焦。
7. **刷新**：`cwd` 回到 `/home/guest`、历史清空、提示符恢复 `~`（会话不持久化，沿用 D-08）。

> **访客不可见但必须成立**：`ctx.history` 是**快照副本**，命令无法通过它改写会话历史；`cd` 只通过 `ctx.setCwd` 生效，命令不直接触碰 Store（D-01）。

约束：

- 三条命令都不 import Store / `window` / `fetch`（PLAN 第 6 节第 2 条），只用 `CommandContext`。
- 路径统一走 `@/fs/path` 的 `resolve`，目录校验统一走 `ctx.vfs.resolve`；命令内**不复写**路径逻辑。

### 3.2 `history` 命令与历史契约

#### 3.2.1 契约缺口

`history` 需要读会话历史，但 `CommandContext` 没有该字段——M2 只把 `commands` / `env` 作为快照注入，历史一直只服务组件。因此本命令必须顺带补齐契约（Q-01）：

```ts
// src/terminal/context/CommandContext.ts
export interface CommandContext {
  // …既有字段不变…
  /** 已注册命令快照（按注册顺序） */
  commands: readonly Command[]
  /**
   * 会话命令历史快照（含当前这条命令本身），按提交顺序；
   * 与 ↑/↓ 浏览、Store 存储的是同一份数据，命令不可通过它改写会话。
   */
  history: readonly string[]
}
```

#### 3.2.2 输出格式

```
   1  pwd
   2  cd /mnt
   3  pwd
   4  history
```

- **单个 `text` chunk**，行间 `\n`；`.terminal-chunk` 已是 `white-space: pre-wrap`，空行与行首空格都会保留。
- 序号 **1 起、连续**，按 `max(4, String(条数).length)` 右对齐（`padStart`），序号后固定 **2 个空格**。
- 行内容为 Store 记录的**原始去空格命令**（`submit` 已 `trim`），不做二次改写。
- 历史为空 → **不输出任何 chunk**（与 bash 一致；真实运行时不可能为空，因为 `history` 自身已被记录）。
- 带位置参数或选项 → `history: 不接受参数`（`error` chunk），不输出列表。

#### 3.2.3 与 Store 语义的一致性

| Store 规则（M1 冻结） | `history` 的表现 |
| --- | --- |
| 提交时先 `recordHistory(command)` 再执行 | 列表**包含当前这条 `history`**，与 bash 一致 |
| 连续重复命令只保留一条（仅与上一条比较） | 连续 `pwd`、`pwd` 只出现一次；隔一条再出现则保留两条 |
| 上限 `MAX_HISTORY = 1000`，超出丢弃最旧 | 列表最多 1000 行；丢弃后序号从 1 重新编号（不显示全局计数） |
| 刷新即清空（D-08） | 刷新后 `history` 无输出 |

> 序号在丢弃最旧条目后会「重排」，与 bash 的全局累计序号不同：M1 的 Store 不保存丢弃计数，本期不为展示口径修改 Store（改造成本大于收益，列入 Q-05 记录）。

#### 3.2.4 实现骨架

```ts
const INDEX_MIN_WIDTH = 4

export const historyCommand: Command = {
  name: 'history',
  description: '查看命令历史',
  usage: 'history',
  execute(ctx) {
    if (ctx.args.length > 0 || Object.keys(ctx.options).length > 0) {
      ctx.output.push({ type: 'error', content: 'history: 不接受参数' })
      return
    }
    const entries = ctx.history
    if (entries.length === 0) return
    const width = Math.max(INDEX_MIN_WIDTH, String(entries.length).length)
    const lines = entries.map(
      (entry, index) => `${String(index + 1).padStart(width)}  ${entry}`,
    )
    ctx.output.write(lines.join('\n'))
  },
}
```

### 3.3 `pwd` 命令

- 输出 `ctx.cwd` **原样**：Store 的 `cwd` 只由初始值（`siteConfig.homeDir`）与 `ctx.setCwd`（`cd` 传入 `resolve` 后的规范路径）写入，因此天然是规范化绝对路径，`pwd` 不再做二次规范化。
- 无参数、无选项 → 一个 `text` chunk；任意参数或选项 → `pwd: 不接受参数`，不输出路径。
- 不感知挂载、不校验路径当前是否仍然存在（见 3.4.5）。

```ts
export const pwdCommand: Command = {
  name: 'pwd',
  description: '显示当前工作目录',
  usage: 'pwd',
  execute(ctx) {
    if (ctx.args.length > 0 || Object.keys(ctx.options).length > 0) {
      ctx.output.push({ type: 'error', content: 'pwd: 不接受参数' })
      return
    }
    ctx.output.write(ctx.cwd)
  },
}
```

### 3.4 `cd` 命令

#### 3.4.1 处理顺序（任一失败即输出错误并返回，`cwd` 不变）

| 顺序 | 判断 | 输出 |
| --- | --- | --- |
| 1 | 存在任何选项（`Object.keys(ctx.options)` 非空） | `cd: 不支持的选项: <选项…>`（空格分隔，按解析顺序） |
| 2 | 位置参数 > 1 | `cd: 参数过多（一次只能进入一个目录）` |
| 3 | 参数为 `-` | `cd: 不支持 cd -（返回上一次目录）` |
| 4 | `~` 展开失败（`~user` 或 HOME 缺失） | `cd: 不支持 ~user 形式: <原文>` / `cd: 无法确定 home 目录（HOME 未设置）` |
| 5 | `resolve(cwd, 展开后路径)` 后 `ctx.vfs.resolve` 无节点 | `cd: 目录不存在: <原文>` |
| 6 | 节点 `type !== 'directory'` | `cd: 不是目录: <原文>` |
| 7 | 全部通过 | **静默**：`ctx.setCwd(target)` |

- 无参数时等价于 `cd ~`；`cd --`（`--` 之后为空）同样按无参数处理（解析器行为）。
- `cd ""`（显式空字符串）按 `resolve` 语义等于当前目录，静默成功——与 bash 行为一致。
- 参数**原文**（`ctx.args[0]`）只用于错误文案；真正参与路径运算的是展开后的字符串。

#### 3.4.2 `~` 展开（命令层负责，path 层不展开）

| 输入形态 | 展开结果 |
| --- | --- |
| `~` | `ctx.env.HOME` |
| `~/x`、`~/x/y` | `${ctx.env.HOME}/x/y`（`resolve` 会再规范化） |
| `~user`、`~user/x` | **不支持**，报 `cd: 不支持 ~user 形式: ~user` |
| `a~b`、`x/~` | 不含前缀 `~`，按普通路径处理 |

```ts
type ExpandResult = { ok: true; value: string } | { ok: false; message: string }

function expandHomeArgument(arg: string, env: Record<string, string>): ExpandResult {
  if (arg !== '~' && !arg.startsWith('~/')) {
    if (arg.startsWith('~')) return { ok: false, message: `cd: 不支持 ~user 形式: ${arg}` }
    return { ok: true, value: arg }
  }
  const home = env.HOME
  if (!home) return { ok: false, message: 'cd: 无法确定 home 目录（HOME 未设置）' }
  return { ok: true, value: arg === '~' ? home : `${home}${arg.slice(1)}` }
}
```

- `HOME` 由 Store 以 `siteConfig.homeDir` 初始化，**只认 `env.HOME`**，不在命令里 import 配置（保持命令无全局依赖）；`HOME` 缺失时报错而不是偷偷回退到某个默认值，避免与提示符显示的 home 不一致时行为诡异地「看似成功」。
- 引号包裹不改变展开行为（`cd "~"` 也回 home）；与 bash「引号内 `~` 不展开」的差异本期不处理，属可接受的宽容行为。

#### 3.4.3 路径解析

```ts
const target = resolve(ctx.cwd, expanded.value) // 绝对路径：直接 normalize；相对：基于 cwd 拼
const { node } = ctx.vfs.resolve(target)         // node 为 null 表示不存在
```

- 绝对/相对、`.`、`..`、重复斜杠、结尾斜杠、根越界（`/..` → `/`）全部由 `path.resolve` 承担，`cd` 不写第二套规则。
- 反斜杠：`normalize` 会把 `\` 换成 `/`，但 `resolve` 先判断 `isAbsolute`。当前 `isAbsolute` 只认 `/`，导致 `cd \mnt` 变成 `/home/guest/mnt`（`isAbsolute('\\mnt') === false`）——与 M3 Q-06「访客按 Windows 习惯输入 `\` 也应被接受」的意图冲突。修正见 3.4.4（Q-08）。

#### 3.4.4 路径层修正（Q-08）

```ts
// src/fs/path.ts
export function isAbsolute(path: string): boolean {
  return path.startsWith('/') || path.startsWith('\\')
}
```

- 影响面：`resolve(base, target)` 对以 `\` 开头的输入从「相对 base」变为「绝对根路径」。相对路径中段的 `\` 不受影响（`a\b` 仍是相对路径，归一化为 `/a/b`）。
- 这是 M3 路径模块的**行为修正**（不是契约变更），补 2 条单测：`isAbsolute('\\mnt') === true`、`resolve('/home/guest', '\\mnt') === '/mnt'`。
- 若不接受此修正，`cd` 需自建一套「先换反斜杠再判断绝对」的临时逻辑，等于在命令层复制路径语义；不推荐。

#### 3.4.5 `cwd` 指向已不存在的目录（前瞻，不在本期实现）

M6 引入插件 `unmount` 后，可能出现「`cwd` 在 `/mnt/demo`，该挂载点被卸载」的状态。本期约定：

- `pwd` **仍原样输出 `ctx.cwd`**（与真实 shell 一致：目录被删后 `pwd` 依然显示路径）。
- 后续 `ls` / `cat` 等按「目录不存在」报错；`cd` 到任意有效目录即可恢复。
- 本期不做「自动回 home」「提示当前目录已失效」等特殊处理；M6 评审时再决定是否需要 `cd` 兜底（记入 4.3 风险）。

#### 3.4.6 实现骨架

```ts
export const cdCommand: Command = {
  name: 'cd',
  description: '切换当前工作目录',
  usage: 'cd [目录]',
  execute(ctx) {
    const optionKeys = Object.keys(ctx.options)
    if (optionKeys.length > 0) {
      ctx.output.push({ type: 'error', content: `cd: 不支持的选项: ${optionKeys.join(' ')}` })
      return
    }
    if (ctx.args.length > 1) {
      ctx.output.push({ type: 'error', content: 'cd: 参数过多（一次只能进入一个目录）' })
      return
    }

    const argument = ctx.args[0] ?? '~'
    if (argument === '-') {
      ctx.output.push({ type: 'error', content: 'cd: 不支持 cd -（返回上一次目录）' })
      return
    }

    const expanded = expandHomeArgument(argument, ctx.env)
    if (!expanded.ok) {
      ctx.output.push({ type: 'error', content: expanded.message })
      return
    }

    const target = resolve(ctx.cwd, expanded.value)
    const { node } = ctx.vfs.resolve(target)
    if (!node) {
      ctx.output.push({ type: 'error', content: `cd: 目录不存在: ${argument}` })
      return
    }
    if (node.type !== 'directory') {
      ctx.output.push({ type: 'error', content: `cd: 不是目录: ${argument}` })
      return
    }
    ctx.setCwd(target)
  },
}
```

### 3.5 `help` 排版打磨

数据仍**只来自 `ctx.commands`**（禁止硬编码；M6 起自动包含插件命令），只改版式与参数校验。

#### 3.5.1 无参数：表头 + 两列列表 + 页脚

```
可用命令（共 6 条）：

  cd       切换当前工作目录
  clear    清空终端输出（保留历史）
  echo     输出传入的文本
  help     查看可用命令与用法
  history  查看命令历史
  pwd      显示当前工作目录

输入 help <命令> 查看具体用法。
```

- 按 `name.localeCompare` 升序；命令名列宽 = 最长命令名长度（动态，插件命令边长后自动适配），左对齐 + 2 个空格，说明列起点一致。
- 每行前缀 2 个空格；表头、列表、页脚之间各一空行（单个 `text` chunk，`pre-wrap` 保留空行）。
- 「多列对齐」的落地口径：**命令名一列 + 说明一列**，不做「一屏拼多栏」。真正的多栏需要终端宽度探测与折行计算，与 M10 的响应式一起评估（Q-06）。
- 命令数为 0（仅测试场景）→ 只有表头与页脚，`共 0 条`。

#### 3.5.2 `help <命令>`

```
cd - 切换当前工作目录
用法: cd [目录]
```

- 第一行 `<name> - <description>`，第二行 `用法: <usage>`；`usage` 缺省时回退为 `用法: <name>`（插件命令可能不写 `usage`）。
- 不额外输出「所属插件」「选项列表」：`Command` 契约没有这些字段，本期**不扩展**（Q-06）。

#### 3.5.3 参数与错误

| 输入 | 输出 |
| --- | --- |
| `help` | 表头 + 列表 + 页脚 |
| `help cd` | 说明 + 用法 |
| `help nope` | `help: 未找到命令: nope，输入 help 查看全部命令` |
| `help cd pwd` | `help: 参数过多（一次只能查询一个命令）` |
| `help -x` / `help --all` | `help: 不支持的选项: -x` / `help: 不支持的选项: --all` |

校验顺序：选项 → 参数个数 → 命令查找（与 `cd` 保持一致的「先参数形态、后业务校验」）。

#### 3.5.4 实现骨架

```ts
const HELP_FOOTER = '输入 help <命令> 查看具体用法。'

function formatList(commands: readonly Command[]): string {
  const sorted = [...commands].sort((a, b) => a.name.localeCompare(b.name))
  const width = sorted.reduce((max, command) => Math.max(max, command.name.length), 0)
  const lines = sorted.map(
    (command) => `  ${command.name.padEnd(width)}  ${command.description}`,
  )
  return [
    `可用命令（共 ${sorted.length} 条）：`,
    '',
    ...lines,
    '',
    HELP_FOOTER,
  ].join('\n')
}
```

### 3.6 上下文契约扩展与接线

```ts
// src/terminal/executor/context.ts
```

```ts

buildContext: createCommandContextBuilder({
  // …
  getCommands: () => commandRuntime.commands,
  getHistory: () => history.value,

```

- **为什么用快照数组而不是 `getHistory()` 函数字段**：与 `env` / `commands` 的既有形态一致（每次执行时取值、拷贝），命令侧只读访问不需要函数；同时天然阻止命令改会话历史（`readonly` + 副本）。
- **为什么拷贝**：`readonly string[]` 只是编译期约束，拷贝可防止运行期 `push` 污染 Store；`history` 最多 1000 条字符串，拷贝成本可忽略。
- **一致性由串行队列保证**：执行器同一时刻只跑一条命令（M2 串行队列），`history` 执行期间 Store 不会追加新条目，快照不会「少一条 / 多一条」。
- 执行器、解析器、注册表、组件全部**零改动**：`PromptBar` 已从 `cwd` 派生，`cd` 改 `cwd` 即同步。

### 4.3 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `history` 为必填字段，所有命令测试的伪造上下文编译失败 | 测试大面积改 | 一次性改 `helpers.ts`；M5 起沿用，不再反复 |
| 快照拷贝被后续实现改成「传引用」 | 命令可改写会话历史 | 构建器统一 `[...]` 拷贝 + `context.spec.ts` 断言副本语义 |
| `cd` 后 `cwd` 指向被卸载的挂载点（M6 场景） | `pwd` 显示失效路径 | 本期约定不自动纠正（3.4.5），M6 评审是否 `cd` 兜底；`ls`/`cat` 自会报「目录不存在」 |
| `env.HOME` 与 `siteConfig.homeDir` 不一致 | `cd ~` 与提示符 `~` 指向不同目录 | HOME 只由 Store 以 `siteConfig.homeDir` 初始化；单测覆盖自定义 HOME；不在命令里读配置 |
| `isAbsolute` 语义变化影响既有 `resolve` 调用 | `\` 开头的相对意图被当成绝对根 | 只有路径**开头**的 `\` 受影响（Windows 习惯本就是根路径）；补 2 条路径单测 + 手工回归 `cd \mnt` / `cd a\b` |
| 严格拒绝参数（如 `pwd -P`）让习惯 Linux 的访客困惑 | 体验略差 | 文案明确「不接受参数」，`help pwd` 展示用法；参数化用法列入 Backlog（Q-04） |
| `history` 最多 1000 行，一次性写入 | 大历史时渲染变慢 | 本期接受（会话为一次性浏览）；M10 输出上限/分页统一处理 |
| 错误文案回显原文（`cd nope`）可能让路径不明确 | 定位略难 | 与 bash 一致且错误行紧邻输入；需要绝对路径时可先 `pwd`（Q-03） |
| `help` 说明列为中文全角字符，列宽视觉不齐 | 观感 | 只用 ASCII 命令名参与 `padEnd` 对齐，说明列只保证起点一致，不强求行尾对齐 |
| 契约改动后旧文档过时 | 后续按错误契约开发 | 4.2 列出架构文档 6.2/6.4/7/9/13 与 PLAN 的回写项，验收逐条检查 |
