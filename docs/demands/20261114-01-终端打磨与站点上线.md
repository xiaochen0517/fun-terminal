## 1. 需求背景

M1–M9 已完成并通过人工页面验收。终端已经具备「目录 / 文本 / 富文本 / 图片」四类内容的完整浏览能力，命令从 8 条核心命令扩展到 12 条（含 `img`）。

**但当前终端仍是「开发可用」，不是「可对外访问的个人站点」**。以下问题在 M1–M9 中刻意搁置、留到最后一个里程碑统一解决：

| 维度 | 现状（M9 完成） | 缺口 |
| --- | --- | --- |
| 站点配置 | `src/config/site.ts` 仅有 `username` / `hostname` / `homeDir` / `messages.welcome` | 无 `version`（应读 `package.json`）、无页面 `title`、无启动 `banner`，站点身份信息散落在 `site.ts`、`index.html` 与欢迎语中 |

## 2. 需求描述

### 2.1 目标

在不引入新依赖、不新增命令、不改变对外契约（`CommandContext` / `PluginApi` / `Vfs` / `MountApi` / `DataSource` / `OutputChunk`）的前提下，完成六件事：

1. **站点配置集中化**：`siteConfig` 增加 `version` / `title` / `banner`（版本号读 `package.json`）；启动 banner + motd、提示符、`help` 头部、页面标题统一从 `siteConfig` 派生。
2. **Tab 命令名 + 路径补全**：新增 `src/terminal/completion.ts`，首词按命令名补全、其后按路径补全（基于 VFS；唯一候选直接补全、多候选列出 + 补公共前缀）。
3. **快捷键**：Ctrl+L 清屏（保留输入与历史）、Ctrl+C 取消当前输入（保留历史）。
4. **输出上限**：输出 chunk 超过上限（1000 条）时丢弃最旧内容并插入截断提示，防止长时间使用卡顿。
5. **窄屏响应式**：窄屏（≤ 640px）减小字号/内边距、提示符允许换行。
6. **部署与文档收尾**：`vite.config.ts` 配置 `base`（支持子路径）；重写 `README.md` 为项目说明；回写架构文档、PLAN 与 README 索引。

> 无障碍增强（`role="log"` / `aria-live` 等）**不在本次范围**（Q-11）；输入框既有的 `aria-label` 保持不变、不新增无障碍工作。

```
应用启动
  └─ main.ts 设置 document.title = siteConfig.title
  └─ terminal Store 初始化 chunks = [...banner.map(system), ...welcome.map(system)]

用户输入（TerminalInput）
  ├─ Tab        → complete(modelValue, { commands, cwd, vfs, homeDir })
  │                ├─ 首词（无空格）→ 命令名补全
  │                ├─ 其后（有空格）→ 路径补全（~ 展开 + 基于 cwd 解析 + VFS 列子项）
  │                ├─ complete：填入完整结果 + 光标移尾
  │                └─ list    ：补到公共前缀 + 经 Terminal → Store.showCompletions 输出候选
  ├─ Ctrl+L     → emit clear-output → Store.clearOutput()（清输出、留输入与历史）
  ├─ Ctrl+C     → emit 空 modelValue（取消输入、留历史）
  └─ Enter      → Store.submit（不变）

输出写入（Store.append）
  └─ chunks.push(chunk) → capOutput(chunks, truncated) → 超限时丢最旧并插入截断提示
```

### 2.2 用户可见行为

以下文本与格式为验收基线（括号内为 chunk 类型）。

**A. 配置与启动**

1. **冷启动横幅**：刷新页面后，输出区顶部先显示 banner（多行，`system`），再显示两行欢迎语（`system`，即现有 motd）。banner 为纯 ASCII、等宽对齐、单行 ≤ 40 字符，内容含站点名 `fun-terminal` 与版本号 `v0.1.0`（版本号读自 `package.json`）。
2. **页面标题**：浏览器标签页标题为 `fun-terminal`（来自 `siteConfig.title`），与 `index.html` 的静态回退一致。
3. **`help` 头部带身份**（`text`）：`help`（无参数）输出首行变为 `fun-terminal v0.1.0`，随后是空行、`可用命令（共 12 条）：`、两列命令清单与页脚（页脚不变：`输入 help <命令> 查看具体用法。`）。修改 `package.json` 的 `version` 或 `siteConfig.hostname` 后，banner 与 `help` 头部同步变化。
4. **`help <命令>` 不变**：单命令查询的说明与用法输出不变（仅无参数清单增加头部行）。

**B. Tab 补全（命令名 + 路径）**

5. **命令名唯一候选直接补全**：输入 `ech` 后按 Tab → 输入框变为 `echo `（命令名 + 尾随空格），光标移到行尾。
6. **命令名多候选列出并补公共前缀**：输入 `c` 后按 Tab → 输入框补全到公共前缀（`c` 本身无更长公共前缀，故不变），输出区追加一条 `system` 提示：`候选：cat  cd  clear`（按名称升序）；再次按 Tab 不产生新输出（输入未变）。
7. **命令名多候选补到公共前缀**：输入 `hi` 后按 Tab → `history` 是唯一以 `hi` 开头的命令，直接补全为 `history `（同第 5 条）。
8. **路径候选列出**：输入 `cat /mnt/` 后按 Tab → 输出 `候选：blog/  demo/  gallery/`（目录带 `/` 后缀，`system`），输入不变（公共前缀为空）。
9. **路径唯一候选补全**：输入 `cat /mnt/b` 后按 Tab → 输入框补全为 `cat /mnt/blog/`（目录自动追加 `/`）。
10. **相对路径与 `~` 可用**：`cd /mnt` 后输入 `cat b` 再按 Tab → 补全为 `cat blog/`（相对 `cwd`）；输入 `cd ~/` 后按 Tab → 列出 home 子目录候选（`notes/`、`README.md` 等）。
11. **路径多候选补公共前缀**：输入 `cat /mnt/` 下有两个及以上以同一前缀开头的项时，先补到公共前缀再列候选（与命令名多候选行为一致）。
12. **无匹配 / 空输入不补全**：空输入按 Tab、输入 `zz` 按 Tab、输入 `ls no`（无 `no` 开头项）按 Tab → 均无变化、无输出。
13. **不改变会话状态**：Tab 补全不写历史、不改 `cwd`；候选提示是 `system` chunk，随输出一起被 `clear` 清空。

**C. 快捷键**

14. **Ctrl+L 清屏**：在任意时刻（含输入框有未提交内容时）按 Ctrl+L → 输出区清空，**当前输入内容与历史均保留**；随后继续输入可正常提交。
15. **Ctrl+C 取消输入**：输入到一半按 Ctrl+C → 输入框清空（不提交、不写历史、不产生输出）；历史与输出区不变；光标回到输入框。
16. **快捷键不影响组合键语义**：Ctrl+C 不会复制（输入框透明、镜像不可选中）；Ctrl+L 与 `clear` 命令行为一致（清输出、留历史）。

> **已知平台限制（Q-07 说明）**：Chrome/Edge 等浏览器将 `Ctrl+L`（聚焦地址栏）作为浏览器级快捷键，页面内 `preventDefault()` 无法拦截，此时 `Ctrl+L` 可能不生效；访客仍可用 `clear` 命令达到同等效果。Firefox 等浏览器可正常拦截。本项按「尽力绑定 + 文档说明」处理。

**D. 输出上限与截断**

17. **超过上限自动截断**：输出 chunk 超过 1000 条后，丢弃最旧内容，输出区顶部出现一条 `system` 截断提示：`输出已截断：较早内容已丢弃（仅保留最近 1000 条）`；截断提示只在首次超限时出现一次，后续继续超限只继续丢最旧、不重复插入提示。
18. **截断后会话仍可用**：截断后 `cd` / `ls` / `cat` / `help` / Tab / 历史等行为不变，滚动与输入流畅。
19. **`clear` 重置截断**：`clear` 清空输出后，截断提示与截断状态一并复位；再次超限时重新出现提示。
20. **历史上限不变**：命令历史仍保持 `MAX_HISTORY = 1000`，与输出上限相互独立（D-08）。

**E. 响应式（窄屏）**

21. **窄屏适配**：375px 宽下字号缩小（14px → 13px）、终端内边距减小、提示符过长时允许换行（`user@host` 与路径段可折行），输入区始终可点击聚焦、可输入、可滚动；页面无横向滚动条。

**F. 部署与文档**

22. **构建产物可部署**：`npm run build` 产物为纯静态文件；默认 `base` 为 `/`，通过 `VITE_BASE_PATH` 环境变量可改到子路径（如 `/fun-terminal/`），文章 `fetch`、图片资源、`favicon` 在子路径下均正确加载（`import.meta.env.BASE_URL` 已用于文章加载，图片走 Vite `?url` 产物自动带 base）。
23. **README 为项目说明**：`README.md` 替换 Vite 模板，包含项目简介、技术栈、本地开发脚本、命令清单、部署说明、文档链接。
24. **文档同步**：架构文档回写 M10 契约与实现项；`docs/PLAN.md` 状态/进度/变更记录更新；`docs/README.md` 索引登记本文。

function formatList(commands: readonly Command[], header = HELP_HEADER): string {
  const sorted = [...commands].sort((a, b) => a.name.localeCompare(b.name))

### 3.5 Tab 命令名 + 路径补全（`src/terminal/completion.ts`）

```ts
import { resolve } from '@/fs/path'
import type { Vfs } from '@/fs/vfs'

export interface CompletionOptions {
  commands: readonly string[]
  cwd: string
  vfs: Vfs
  homeDir: string
}

export type CompletionResult =
  | { type: 'complete'; value: string }                              // 完整替换后的输入
  | { type: 'list'; value: string; candidates: readonly string[] }  // value 为补到公共前缀后的输入
  | { type: 'none' }

export function complete(input: string, options: CompletionOptions): CompletionResult {
  if (input === '') return { type: 'none' }
  const firstSpace = input.indexOf(' ')
  if (firstSpace === -1) return completeCommandName(input, options.commands)
  return completePath(input, options)
}
```

**命令名补全（首词）**：

```ts
function completeCommandName(prefix: string, commands: readonly string[]): CompletionResult {
  const matches = [...commands].filter((name) => name.startsWith(prefix)).sort()
  if (matches.length === 0) return { type: 'none' }
  if (matches.length === 1) return { type: 'complete', value: `${matches[0]!} ` }
  return { type: 'list', value: longestCommonPrefix(matches), candidates: matches }
}
```

**路径补全（命令名之后，取最后一个空白分隔的 token）**：

```ts
function completePath(input: string, { cwd, vfs, homeDir }: CompletionOptions): CompletionResult {
  const lastSpace = input.lastIndexOf(' ')
  const before = input.slice(0, lastSpace + 1)   // 保留末 token 之前（含空格）
  const token = input.slice(lastSpace + 1)

  const slash = token.lastIndexOf('/')
  const dirText = slash === -1 ? '' : token.slice(0, slash + 1)  // 保留结尾斜杠，如 '/mnt/'
  const namePrefix = slash === -1 ? token : token.slice(slash + 1)

  const expandedDir = expandTilde(dirText, homeDir)              // 空串 → 由 resolve 落回 cwd
  const dir = resolve(cwd, expandedDir)
  const children = vfs.readDir(dir)
  if (!children) return { type: 'none' }

  const matches = children
    .filter((child) => child.name.startsWith(namePrefix))
    .sort((a, b) => a.name.localeCompare(b.name))
  if (matches.length === 0) return { type: 'none' }

  const names = matches.map((m) => (m.type === 'directory' ? `${m.name}/` : m.name))

  if (matches.length === 1) {
    const suffix = matches[0]!.type === 'directory' ? '/' : ''
    return { type: 'complete', value: before + dirText + matches[0]!.name + suffix }
  }
  const common = longestCommonPrefix(matches.map((m) => m.name))
  return { type: 'list', value: before + dirText + common, candidates: names }
}

function expandTilde(text: string, homeDir: string): string {
  if (text === '~') return homeDir
  if (text.startsWith('~/')) return homeDir + text.slice(1)
  return text
}

function longestCommonPrefix(values: readonly string[]): string {
  let prefix = values[0] ?? ''
  for (const value of values) {
    while (!value.startsWith(prefix)) prefix = prefix.slice(0, -1)
    if (prefix === '') break
  }
  return prefix
}
```

- **命令名来源**：`commandRuntime.commands` 的实时视图（含插件命令），Store 暴露 `commandNames` 只读派生值；补全结果随插件注册自动变化，不硬编码命令清单。
- **路径来源**：`commandRuntime.deps.vfs`（只读 `Vfs`）通过 Store 暴露；补全只查询、不修改 VFS。
- **行为**：
  - 首词（无空格）→ 命令名补全；其后（有空格）→ 对最后一个 token 做路径补全；
  - `complete`（唯一）：命令名补 `命令名 + 空格`，路径补「原 token 目录部分 + 名字（目录再加 `/`）」；
  - `list`（多候选）：先补到公共前缀（若更长），再输出候选；目录候选带 `/` 后缀；
  - `none`：空输入 / 无匹配 / 目录不存在 → 无操作。
- **候选排序**：命令名与路径名均按名称升序，输出稳定可预期。
- **边界**：`~` 展开只支持 `~` 与 `~/...`（与 `path-argument.ts` 的 `expandHomeArgument` 语义一致）；`.` / `..` / 重复斜杠由 `resolve` 规范化；目录后缀 `/` 与 `ls` 的展示风格一致。

### 3.7 输出上限（`src/terminal/output-limit.ts` + Store）

```ts
export const MAX_OUTPUT_CHUNKS = 1000
export const TRUNCATION_NOTICE = '输出已截断：较早内容已丢弃（仅保留最近 1000 条）'

/** 就地截断：超过上限时丢最旧，首次截断时在首部插入截断提示；返回是否处于「已截断」状态 */
export function capOutput(
  chunks: OutputChunk[],
  truncated: boolean,
  max = MAX_OUTPUT_CHUNKS,
): boolean {
  if (chunks.length <= max) return truncated

  if (!truncated) {
    chunks.splice(0, chunks.length - (max - 1))
    chunks.unshift({ type: 'system', content: TRUNCATION_NOTICE })
    return true
  }
  chunks.splice(1, chunks.length - max)
  return true
}
```

Store 接线：

```ts
let truncated = false

const outputBuffer = createOutputBuffer({
  get chunks() { return chunks.value },
  append(chunk) {
    chunks.value.push(chunk)
    truncated = capOutput(chunks.value, truncated)
  },
  clear() {
    chunks.value = []
    truncated = false
  },
})
```

- **上限值（Q-08）**：1000 条 chunk，与 `MAX_HISTORY = 1000` 一致（D-08）；作为可配置常量导出。
- **截断提示位置（Q-08）**：首部常驻（`index 0`），语义是「顶部之前的更早内容已丢弃」；只在首次超限插入一次，后续只继续丢最旧。
- **与 `clear` 的关系**：`clear` 清空并复位 `truncated`；截断提示随清空消失，再次超限时重新出现。
- **计数**：截断提示占一个位置，实际内容容量为 999 条 + 1 条提示；该细节对访客不可见，仅实现约定。
- **性能**：每次 append 为 O(1) 平摊（`push` + 极偶尔 `splice`/`unshift`）；不会因长会话累积 DOM 节点导致卡顿。

### 3.14 安全

- **无注入面**：banner、候选提示、截断提示均为固定/受控文本，走 `text`/`system` chunk，不经 `v-html`；`help` 头部由 `siteConfig`（站主维护的常量）拼接，无访客输入。
- **补全不执行**：Tab 只改写输入框 `modelValue`，不触发 `submit` / `execute`，无命令注入或误执行面；路径补全只读 `Vfs`，不修改树。
- **快捷键无副作用**：Ctrl+L / Ctrl+C 只操作输出/输入状态，不触碰 VFS、历史以外的状态；`preventDefault()` 阻止浏览器默认行为。
- **能力边界**：补全/上限纯函数不 import Store / `window` / `fetch`；组件经 Store 接线，不直接访问运行时单例。
- **无障碍**：本期不做无障碍增强（Q-11）；输入框既有 `aria-label` 不变。
