## 1. 需求背景

M1–M8 已完成并通过人工页面验收，M9（图片插件 `img`）需求文档已创建、处于「待审核」状态。到 M9 为止，终端已经具备「目录 / 文本 / 富文本 / 图片」四类内容的完整浏览能力，命令从 8 条核心命令扩展到 12 条（M9 并入 `img` 后）。

**但当前终端仍是「开发可用」，不是「可对外访问的个人站点」**。以下问题在 M1–M9 中刻意搁置、留到最后一个里程碑统一解决：

## 2. 需求描述

### 2.1 目标

在不引入新依赖、不新增命令、不改变对外契约（`CommandContext` / `PluginApi` / `Vfs` / `MountApi` / `DataSource` / `OutputChunk`）的前提下，完成六件事：

1. **站点配置集中化**：`siteConfig` 增加 `version` / `title` / `banner`；启动 banner + motd、提示符、`help` 头部、页面标题统一从 `siteConfig` 派生。
2. **Tab 命令名补全**：新增 `src/terminal/completion.ts` 纯函数，输入首词按命令名补全（唯一候选直接补全、多候选列出）。
3. **快捷键**：Ctrl+L 清屏（保留输入与历史）、Ctrl+C 取消当前输入（保留历史）。
4. **输出上限**：输出 chunk 超过上限（1000 条）时丢弃最旧内容并插入截断提示，防止长时间使用卡顿。
5. **响应式与无障碍**：窄屏（≤ 640px）减小字号/内边距、提示符允许换行；输出区增加 `role="log"` + `aria-live="polite"`。
6. **部署与文档收尾**：`vite.config.ts` 配置 `base`（支持子路径）；重写 `README.md` 为项目说明；回写架构文档、PLAN 与 README 索引。

```
应用启动
  └─ main.ts 设置 document.title = siteConfig.title
  └─ terminal Store 初始化 chunks = [...banner.map(system), ...welcome.map(system)]
       └─ TerminalOutput 以 role="log" + aria-live="polite" 渲染

用户输入（TerminalInput）
  ├─ Tab        → completeCommand(modelValue, commands)
  │                ├─ complete：填入命令名 + 空格
  │                └─ list    ：补全公共前缀 + 经 Terminal → Store.showCompletions 输出候选
  ├─ Ctrl+L     → emit clear-output → Store.clearOutput()（清输出、留输入与历史）
  ├─ Ctrl+C     → emit 空 modelValue（取消输入、留历史）
  └─ Enter      → Store.submit（不变）

输出写入（Store.append）
  └─ chunks.push(chunk) → capOutput(chunks, truncated) → 超限时丢最旧并插入截断提示
```

### 2.2 用户可见行为

以下文本与格式为验收基线（括号内为 chunk 类型）。

**A. 配置与启动**

1. **冷启动横幅**：刷新页面后，输出区顶部先显示 banner（多行，`system`），再显示两行欢迎语（`system`，即现有 motd）。banner 为纯 ASCII、等宽对齐、单行 ≤ 40 字符，内容含站点名 `fun-terminal` 与版本号 `v1.0.0`。
2. **页面标题**：浏览器标签页标题为 `fun-terminal`（来自 `siteConfig.title`），与 `index.html` 的静态回退一致。
3. **`help` 头部带身份**（`text`）：`help`（无参数）输出首行变为 `fun-terminal v1.0.0`，随后是空行、`可用命令（共 12 条）：`、两列命令清单与页脚（页脚不变：`输入 help <命令> 查看具体用法。`）。修改 `siteConfig.hostname` 或 `version` 后，banner 与 `help` 头部同步变化。
4. **`help <命令>` 不变**：单命令查询的说明与用法输出不变（仅无参数清单增加头部行）。

**B. Tab 命令名补全**

5. **唯一候选直接补全**：输入 `ech` 后按 Tab → 输入框变为 `echo `（命令名 + 尾随空格），光标移到行尾，便于继续输入参数。
6. **多候选列出并补全公共前缀**：输入 `c` 后按 Tab → 输入框补全到公共前缀（`c` 本身无更长公共前缀，故不变），输出区追加一条 `system` 提示列出候选：`候选命令：cat  cd  clear`（按名称升序）；再次按 Tab 不产生新输出（输入未变）。
7. **多候选补到公共前缀**：输入 `hi` 后按 Tab → `history` 是唯一以 `hi` 开头的命令，直接补全为 `history `（同第 5 条）。
8. **带参数不补全**：输入 `cat /mnt` 后按 Tab → 不变化、不输出（路径/参数补全属 Backlog，D-10）。
9. **空输入 / 无匹配不补全**：空输入按 Tab、或输入 `zz` 按 Tab → 均无变化、无输出。
10. **不改变会话状态**：Tab 补全不写历史、不改 `cwd`；候选提示是 `system` chunk，随输出一起被 `clear` 清空。

**C. 快捷键**

11. **Ctrl+L 清屏**：在任意时刻（含输入框有未提交内容时）按 Ctrl+L → 输出区清空，**当前输入内容与历史均保留**；随后继续输入可正常提交。
12. **Ctrl+C 取消输入**：输入到一半按 Ctrl+C → 输入框清空（不提交、不写历史、不产生输出）；历史与输出区不变；光标回到输入框。
13. **快捷键不影响组合键语义**：Ctrl+C 不会复制（输入框透明、镜像不可选中）；Ctrl+L 与 `clear` 命令行为一致（清输出、留历史）。

> **已知平台限制（Q-07 说明）**：Chrome/Edge 等浏览器将 `Ctrl+L`（聚焦地址栏）作为浏览器级快捷键，页面内 `preventDefault()` 无法拦截，此时 `Ctrl+L` 可能不生效；访客仍可用 `clear` 命令达到同等效果。Firefox 等浏览器可正常拦截。本项按「尽力绑定 + 文档说明」处理。

**D. 输出上限与截断**

14. **超过上限自动截断**：输出 chunk 超过 1000 条后，丢弃最旧内容，输出区顶部出现一条 `system` 截断提示：`输出已截断：较早内容已丢弃（仅保留最近 1000 条）`；截断提示只在首次超限时出现一次，后续继续超限只继续丢最旧、不重复插入提示。
15. **截断后会话仍可用**：截断后 `cd` / `ls` / `cat` / `help` / Tab / 历史等行为不变，滚动与输入流畅。
16. **`clear` 重置截断**：`clear` 清空输出后，截断提示与截断状态一并复位；再次超限时重新出现提示。
17. **历史上限不变**：命令历史仍保持 `MAX_HISTORY = 1000`，与输出上限相互独立（D-08）。

**E. 响应式与无障碍**

18. **窄屏适配**：375px 宽下字号缩小（14px → 13px）、终端内边距减小、提示符过长时允许换行（`user@host` 与路径段可折行），输入区始终可点击聚焦、可输入、可滚动；页面无横向滚动条。
19. **无障碍声明**：输出区容器带 `role="log"` 与 `aria-live="polite"`；隐藏输入框保持 `aria-label="终端命令输入"`；提示符保持 `aria-hidden="true"`（装饰性，不重复播报）。
20. **读屏行为**：新增输出（命令回显、命令结果、候选提示）由读屏按「礼貌」优先级播报，不打断当前操作。

**F. 部署与文档**

21. **构建产物可部署**：`npm run build` 产物为纯静态文件；默认 `base` 为 `/`，通过 `VITE_BASE_PATH` 环境变量可改到子路径（如 `/fun-terminal/`），文章 `fetch`、图片资源、`favicon` 在子路径下均正确加载（`import.meta.env.BASE_URL` 已用于文章加载，图片走 Vite `?url` 产物自动带 base）。
22. **README 为项目说明**：`README.md` 替换 Vite 模板，包含项目简介、技术栈、本地开发脚本、命令清单、部署说明、文档链接。
23. **文档同步**：架构文档回写 M10 契约与实现项；`docs/PLAN.md` 状态/进度/变更记录更新；`docs/README.md` 索引登记本文。

### 3.4 `help` 头部展示站点身份

`src/commands/builtin/help.ts` 的 `formatList` 增加头部行，身份来自 `siteConfig`：

```ts
import { siteConfig } from '@/config/site'

const HELP_HEADER = `${siteConfig.hostname} v${siteConfig.version}`

function formatList(commands: readonly Command[], header = HELP_HEADER): string {
  const sorted = [...commands].sort((a, b) => a.name.localeCompare(b.name))
  const width = sorted.reduce((max, c) => Math.max(max, c.name.length), 0)
  const lines = sorted.map((c) => `  ${c.name.padEnd(width)}  ${c.description}`)
  return [header, '', `可用命令（共 ${sorted.length} 条）：`, '', ...lines, '', HELP_FOOTER].join('\n')
}
```

- **为什么直接 import `siteConfig`**：`siteConfig` 是冻结的纯常量（类似 `HELP_FOOTER`），不属于「Store / window / fetch / 静态数据文件」，导入不破坏「命令经上下文取数据」的边界；相比往 `ctx.env` 塞 `HOSTNAME` / `VERSION`，改动更小、更可读（Q-03）。
- `formatList(commands, header)` 保留 `header` 入参（缺省用 `HELP_HEADER`），便于单测注入任意头部；`help <命令>` 分支不变。
- 影响面仅 `help`（无参数）输出首行；`help` 单命令查询、错误分支、选项校验均不变。

### 3.5 Tab 命令名补全（`src/terminal/completion.ts`）

```ts
export type CompletionResult =
  | { type: 'complete'; value: string; matched: string }
  | { type: 'list'; candidates: readonly string[]; common: string }
  | { type: 'none' }

/** 仅补全「输入首词」（命令名）；输入含空格或为空时不补全（路径/参数补全属 Backlog） */
export function completeCommand(input: string, commands: readonly string[]): CompletionResult {
  if (input === '' || input.includes(' ')) return { type: 'none' }

  const matches = [...commands].filter((name) => name.startsWith(input)).sort()
  if (matches.length === 0) return { type: 'none' }
  if (matches.length === 1) {
    const matched = matches[0]!
    return { type: 'complete', value: `${matched} `, matched }
  }
  return { type: 'list', candidates: matches, common: longestCommonPrefix(matches) }
}

function longestCommonPrefix(values: readonly string[]): string {
  let prefix = values[0] ?? ''
  for (const value of values) {
    while (!value.startsWith(prefix)) prefix = prefix.slice(0, -1)
    if (prefix === '') break
  }
  return prefix
}
```

- **命令名来源**：`commandRuntime.commands` 的实时视图（含插件命令），Store 暴露 `commandNames` 只读派生值；补全结果随插件注册自动变化，不硬编码命令清单。
- **排序**：候选按名称升序（与 `help` 一致），输出稳定可预期。
- **行为**：
  - `complete`（唯一）：补全为 `命令名 + 空格`，光标移到行尾；
  - `list`（多候选）：若公共前缀比当前输入更长，先补全到公共前缀；随后经 Store 输出候选提示；
  - `none`：无操作。

**组件接线（`TerminalInput.vue`）**：

```ts
const props = defineProps<{
  modelValue: string
  history: readonly string[]
  commands: readonly string[]
}>()

const emit = defineEmits<{
  'update:modelValue': [value: string]
  submit: [value: string]
  'clear-output': []
  'list-completions': [candidates: readonly string[]]
}>()

function complete() {
  const result = completeCommand(props.modelValue, props.commands)
  if (result.type === 'complete') {
    emit('update:modelValue', result.value)
    void nextTick(focusEnd)
    return
  }
  if (result.type === 'list') {
    if (result.common.length > props.modelValue.length) {
      emit('update:modelValue', result.common)
    }
    emit('list-completions', result.candidates)
  }
}
```

- `onKeydown` 在 `isComposing` / `keyCode === 229` 之后、Enter 判断之前处理 Tab（`event.key === 'Tab'` 时 `preventDefault()` + `complete()`）；Tab 不受 ctrl/meta/alt 拦截分支影响。
- **候选提示格式**（Store 方法）：`候选命令：${candidates.join('  ')}`（一条 `system` chunk）。12 条命令时候选集合很小，无需上限；保留「最多 N 条」的约定（N = 20，超出的仅显示前 20 条 + `…`）以备未来命令增多（Q-05）。

**Store 新增**：

```ts

```

### 3.7 输出上限（`src/terminal/output-limit.ts` + Store）

```ts
export const MAX_OUTPUT_CHUNKS = 1000
export const TRUNCATION_NOTICE = '输出已截断：较早内容已丢弃（仅保留最近 1000 条）'

/**
 * 就地截断输出：超过上限时丢弃最旧内容，并在首次截断时于首部插入截断提示。
 * 返回是否处于「已截断」状态。
 */
export function capOutput(
  chunks: OutputChunk[],
  truncated: boolean,
  max = MAX_OUTPUT_CHUNKS,
): boolean {
  if (chunks.length <= max) return truncated

  if (!truncated) {
    // 首次截断：丢最旧，给截断提示腾出一个位置（index 0）
    chunks.splice(0, chunks.length - (max - 1))
    chunks.unshift({ type: 'system', content: TRUNCATION_NOTICE })
    return true
  }

  // 已截断：保留 index 0 的提示，从 index 1 起丢最旧
  chunks.splice(1, chunks.length - max)
  return true
}
```

Store 接线：

```ts
let truncated = false

const outputBuffer = createOutputBuffer({
  get chunks() { return chunks.value },
  append(chunk) {
    chunks.value.push(chunk)
    truncated = capOutput(chunks.value, truncated)
  },
  clear() {
    chunks.value = []
    truncated = false
  },
})
```

- **上限值**：1000 条 chunk，与 `MAX_HISTORY = 1000` 一致（D-08）；作为可配置常量导出（Q-08）。
- **截断提示位置**：首部常驻（`index 0`），语义是「顶部之前的更早内容已丢弃」；只在首次超限插入一次，后续只继续丢最旧（Q-08）。
- **与 `clear` 的关系**：`clear` 清空并复位 `truncated`；截断提示随清空消失，再次超限时重新出现。
- **计数**：截断提示占一个位置，实际内容容量为 999 条 + 1 条提示；该细节对访客不可见，仅实现约定。
- **性能**：每次 append 为 O(1) 平摊（`push` + 极偶尔 `splice`/`unshift`）；不会因长会话累积 DOM 节点导致卡顿。

- **无注入面**：banner、候选提示、截断提示均为固定/受控文本，走 `text`/`system` chunk，不经 `v-html`；`help` 头部由 `siteConfig`（站主维护的常量）拼接，无访客输入。
- **补全不执行**：Tab 只改写输入框 `modelValue`，不触发 `submit` / `execute`，无命令注入或误执行面。
- **快捷键无副作用**：Ctrl+L / Ctrl+C 只操作输出/输入状态，不触碰 VFS、历史以外的状态；`preventDefault()` 阻止浏览器默认行为。
- **无障碍**：`role="log"` + `aria-live="polite"` 让读屏按礼貌优先级播报新增输出；输入框保留 `aria-label`；banner 为纯文本、不依赖图内文字。
- **能力边界**：补全/上限纯函数不 import Store / `window` / `fetch`；组件经 Store 接线，不直接访问运行时单例。
