## 1. 需求背景

`fun-terminal` 定位为「以终端为唯一交互入口的个人网站」。M0 阶段已经完成架构确认与目录/契约初始化：`src/` 下已有 8 个核心契约文件，但全部只有类型与接口，没有任何可运行的终端界面或命令链路。

| `src/App.vue` | 仍是 Vite 脚手架默认页面 | 改写为挂载终端 |

| `src/terminal/theme.css` | 不存在 | 建立 oh-my-zsh 风格主题与全局样式 |
| 测试 | 仅断言模板文案 `You did it!` | 改写为终端挂载与交互测试 |

M1 是第一个**访客可见**的里程碑，也是后续所有命令的宿主：

- M2 的命令解析/注册/执行需要终端提供输入、回显与输出区，否则命令层无处落地。
- M3 的 VFS、M4 的 `cd`/`pwd` 需要会话状态中的 `cwd` 与提示符联动。
- M8/M9 的富文本与图片输出需要 `OutputChunk` 的渲染分支。

因此 M1 不仅是「画一个终端界面」，还要一次性冻结三个跨里程碑约定：**会话状态模型、输出块模型、提示符与主题**。如果这些约定拖到 M2 再定，后续命令层、VFS 与博客插件都会被迫返工。

## 2. 需求描述

### 2.1 目标

访客打开页面即进入一个占满视口的暗色终端：可点击聚焦、可键入字符、回车后能看到自己的命令被回显、可用上下键翻历史、可用 `clear` 清屏；当前目录、命令历史、环境变量由 Pinia 统一管理，刷新页面后重置。

本里程碑只验证「外壳」：**输入能被看见、提交能被回显、历史能翻、屏幕能清**。不执行任何真实命令，也不接入解析器与注册表。

### 2.2 用户可见行为

1. **冷启动**：页面是全屏暗色终端，等宽字体，显示欢迎语与 `guest@fun-terminal ~ %` 提示符。
2. **输入**：点击页面任意非交互区域即可聚焦；键入字符实时可见，光标随输入移动；支持中文输入法与多行粘贴（转为单行）。
3. **提交**：回车后，刚输入的命令连同当时的提示符回显到输出区，并显示一行灰色提示「命令系统将在下一里程碑接入，当前仅支持 clear 清屏。」；输入框清空并保持聚焦。
4. **历史**：↑/↓ 浏览已提交命令，首次 ↑ 保留当前草稿，↓ 越过最新一条时恢复草稿；回填后可编辑再提交。
5. **清屏**：输入 `clear` 清空输出区并回到顶部，当前目录与环境变量不受影响；`clear` 本身仍记入历史。
6. **刷新**：刷新页面后欢迎语重新出现、历史清空、`cwd` 回到 `/home/guest`，无报错。
7. **窄屏**：375px 宽度下无横向溢出，提示符与输入仍可用（深度移动端适配属于 M10）。

### 2.3 演示脚本（人工验收用）

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | `npm run dev`，打开终端打印的地址 | 显示两行欢迎语与提示符；页面无外层滚动条，控制台无报错 |
| 2 | 点击终端空白处，输入 `hello world` | 字符实时显示，块状光标在行尾闪烁 |

## 3. 方案设计

### 3.1 总体结构与数据流

```
键盘 / 输入法
      │
      ▼
TerminalInput.vue
（透明 textarea + 文本镜像 + 自绘光标 + 历史导航）
      │ submit(raw)
      ▼
Terminal.vue
（输入状态、点击聚焦、滚动容器、自动滚动）
      │ store.submit(raw)
      ▼
stores/terminal.ts ──────────────► OutputChunk[]
      │                                  │
      ├─ history / cwd / env             ▼
      └─ createOutputBuffer(sink)   TerminalOutput.vue
                                         │
                                         ├─ text / system / error
                                         ├─ html（受控）
                                         └─ command → PromptBar + 命令文本
```

M1 **不经过** Parser / Registry / Executor：`store.submit()` 内部直接做「记录历史 → `clear` 特判 → 回显 + 临时提示」。这是有意为之的临时外壳：

- 组件只依赖 `store.submit(raw)` 这一入口，不感知命令如何执行。
- M2 只替换 `store.submit()` 的内部实现（改为 Parser → Registry → Executor），组件、输出模型、会话状态均不需要改动。
- 命令层不会直接 import Store（D-01），M1 也不会提前引入 VFS 或 `CommandContext` 扩展。

### 3.2 站点配置（`src/config/site.ts`）

站点身份与面向访客的固定文案集中在一个只读配置对象中，提示符、欢迎语、临时提示共用，避免散落硬编码。

```ts
// src/config/site.ts
export interface SiteConfig {
  /** 提示符左侧的用户名，如 guest */
  username: string
  /** 提示符左侧的主机名，如 fun-terminal */
  hostname: string
  /** 虚拟 home 目录，必须是 POSIX 绝对路径且不以 / 结尾 */
  homeDir: string
  messages: {
    /** 冷启动欢迎语，每条渲染为一个 system 输出块 */
    welcome: readonly string[]
    /** 命令层尚未接入时的临时提示 */
    commandUnavailable: string
  }
}

export const siteConfig: SiteConfig = {
  username: 'guest',
  hostname: 'fun-terminal',
  homeDir: '/home/guest',
  messages: {
    welcome: [
      '欢迎来到 fun-terminal —— 一个以终端为入口的个人站点。',
      '当前为终端外壳预览：支持命令回显、历史浏览与 clear 清屏。',
    ],
    commandUnavailable: '命令系统将在下一里程碑接入，当前仅支持 clear 清屏。',
  },
}
```

约定：

- `homeDir` 必须是绝对路径（以 `/` 开头）、不以 `/` 结尾；M1 的 `cwd` 初值直接取它。
- `username` / `hostname` 不包含空格，避免提示符分段歧义。
- M1 只读，不在运行时修改；M10 再扩展版本号、banner、部署配置等字段。
- 欢迎语与临时提示是**示例文案**，审核时可只改文案、不改结构（见 Q-04）。

### 3.3 会话状态（`src/stores/terminal.ts`）

#### 3.3.1 状态字段

| 字段 | 类型 | 初始值 | 说明 |
| --- | --- | --- | --- |
| `cwd` | `string` | `siteConfig.homeDir` | 当前虚拟工作目录；M1 不变化 |
| `history` | `string[]` | `[]` | 已提交命令的原始文本（trim 后） |
| `env` | `Record<string, string>` | `{ USER, HOME }` | 虚拟环境变量；M1 不变化 |
| `chunks` | `OutputChunk[]` | 欢迎语对应的 `system` 块 | 输出区唯一数据源 |

常量：

- `MAX_HISTORY = 1000`（D-08 建议值）。
- 输入长度上限 `INPUT_MAX_LENGTH = 1000` 由 `TerminalInput.vue` 持有（属于输入控件约束，不进入站点配置）。

#### 3.3.2 行为与代码骨架

```ts
// src/stores/terminal.ts
import { defineStore } from 'pinia'
import { ref } from 'vue'

import { siteConfig } from '@/config/site'
import { createOutputBuffer } from '@/terminal/context/buffer'
import type { OutputChunk } from '@/terminal/context/OutputBuffer'

export const MAX_HISTORY = 1000

export const useTerminalStore = defineStore('terminal', () => {
  const cwd = ref(siteConfig.homeDir)
  const history = ref<string[]>([])
  const env = ref<Record<string, string>>({
    USER: siteConfig.username,
    HOME: siteConfig.homeDir,
  })
  const chunks = ref<OutputChunk[]>(
    siteConfig.messages.welcome.map(
      (content): OutputChunk => ({ type: 'system', content }),
    ),
  )

  const outputBuffer = createOutputBuffer({
    get chunks() {
      return chunks.value
    },
    append(chunk) {
      chunks.value.push(chunk)
    },
    clear() {
      chunks.value = []
    },
  })

  function recordHistory(command: string) {
    if (history.value[history.value.length - 1] === command) return
    history.value.push(command)
    if (history.value.length > MAX_HISTORY) {
      history.value.splice(0, history.value.length - MAX_HISTORY)
    }
  }

  function submit(raw: string) {
    const command = raw.trim()
    if (!command) return

    recordHistory(command)

    if (command === 'clear') {
      outputBuffer.clear()
      return
    }

    outputBuffer.push({ type: 'command', cwd: cwd.value, input: command })
    outputBuffer.push({
      type: 'system',
      content: siteConfig.messages.commandUnavailable,
    })
  }

  function clearOutput() {
    outputBuffer.clear()
  }

  return { cwd, history, env, chunks, outputBuffer, submit, clearOutput }
})
```

#### 3.3.3 历史规则

1. 只记录**非空**提交；输入首尾空白先被 `trim`，记录的是 trim 后的文本。
2. **连续重复**命令只保留一条（相邻比较）；非连续重复仍保留。
3. 超过 `MAX_HISTORY` 时从最旧开始丢弃，只保留最近 1000 条。
4. `clear` 在清屏前先记入历史，因此清屏后按 ↑ 仍可找回。
5. 不做持久化：刷新页面即新建 Store，历史为空。
6. M1 的 `cwd` / `env` 固定；`setCwd`、`PWD` 联动与 `$HOME` 展开留到 M2/M4，避免提前引入 VFS 依赖。

#### 3.3.4 为什么输入框文本不放进 Store

输入文本是**组件级瞬时状态**，由 `Terminal.vue` 的 `ref` 持有并通过 `v-model` 传给 `TerminalInput.vue`。不放进 Store 的原因：

- 每次按键都写全局 Store 会放大响应式开销，也没有跨组件共享需求。
- 历史导航的草稿、光标位置等属于输入控件内部状态，放进 Store 会让 M2 的 Store 职责变混。
- Store 只保留「会话结果」：`cwd`、`history`、`env`、`chunks`。

### 3.4 输出模型与契约变更（D-03）

#### 3.4.1 现状与变更

当前 `OutputChunk` 只有 `text` / `html` 两型：

```ts
// 变更前
export interface OutputChunk {
  type: 'text' | 'html'
  content: string
}
```

M1 建议扩展为可判别联合，新增 `system`、`error`、`command` 三型：

```ts
// 变更后
export interface TextChunk {
  type: 'text'
  content: string
}
export interface HtmlChunk {
  type: 'html'
  content: string
}
export interface SystemChunk {
  type: 'system'
  content: string
}
export interface ErrorChunk {
  type: 'error'
  content: string
}
export interface CommandChunk {
  type: 'command'
  /** 执行该命令时的 cwd，用于回显当时的提示符 */
  cwd: string
  /** 用户提交的原始命令（trim 后） */
  input: string
}

export type OutputChunk =
  | TextChunk
  | HtmlChunk
  | SystemChunk
  | ErrorChunk
  | CommandChunk
```

#### 3.4.2 各类型语义

| 类型 | 生产者 | 渲染方式 | M1 是否使用 |
| --- | --- | --- | --- |
| `text` | 命令 / 执行器 | 正常前景色，保留换行 | 预留（M2 起） |
| `html` | 受控插件（博客等） | `v-html`，仅接受可信 HTML | 预留（M8 起） |
| `system` | 终端核心 | 弱化色（灰） | 欢迎语、临时提示 |
| `error` | 执行器 / 命令 | 错误色（红） | 预留（M2 起） |
| `command` | 终端核心（Store） | 提示符 + 命令文本，提示符分色 | 命令回显 |

> `command` 是「回显行」而非命令输出，只允许终端核心写入，命令实现不得使用。

#### 3.4.3 输出缓冲实现（`src/terminal/context/buffer.ts`）

`OutputBuffer.ts` 继续只放接口与类型；新增 `buffer.ts` 放工厂实现。工厂依赖一个最小 `OutputSink`，不直接依赖 Pinia Store，便于单测与替换。

```ts
// src/terminal/context/buffer.ts
import type { OutputBuffer, OutputChunk } from '@/terminal/context/OutputBuffer'

export interface OutputSink {
  readonly chunks: readonly OutputChunk[]
  append(chunk: OutputChunk): void
  clear(): void
}

export function createOutputBuffer(sink: OutputSink): OutputBuffer {
  return {
    write(text) {
      sink.append({ type: 'text', content: text })
    },
    writeHtml(html) {
      sink.append({ type: 'html', content: html })
    },
    push(chunk) {
      sink.append(chunk)
    },
    clear() {
      sink.clear()
    },
    get chunks() {
      return sink.chunks
    },
  }
}
```

**输出块语义（对 M2 很重要）**：

- 一个 `chunk` 渲染为一个**块级输出单元**；`write()` 不自动追加换行，也不把多次写入合并到同一行。
- 如果一条命令需要输出多行，应在一个 `content` 中携带 `\n`（`text`/`system`/`error` 均保留换行）。
- 如需在同一行分段着色，应输出一个结构化块（M1 只有 `command`），不要用多个 `text` 块拼一行。
- `text` 内容按纯文本渲染，Vue 插值自动转义；`html` 内容必须由受控代码生成，M8 起遵循 `html: false` 的 Markdown 配置。

#### 3.4.4 契约变更的影响

- 只改 `OutputChunk` 联合类型，`OutputBuffer` 的方法签名不变。
- `CommandContext`、`Command`、`CommandPlugin`、`CommandRegistry`、`DataSource`、VFS 均不变。
- 当前没有任何实现代码依赖 `OutputChunk`，变更成本最低；此时冻结比 M2 之后再改更安全。
- 审核通过后，需要回写《项目架构文档》的输出模型章节，并在 `docs/PLAN.md` 中把 D-03 标记为已确认；实施完成后再更新 M1 进度。

#### 3.4.5 备选方案与取舍

| 方案 | 问题 |
| --- | --- |
| 维持 `text` / `html` 两型，回显用 `text` | 提示符无法分色，失去 oh-my-zsh 视觉特征 |
| 回显拼成 `html` 块 | 用户输入必须手工 `escapeHtml`，每个回显点都要保证，XSS 面不必要地扩大 |
| 新增 `command` 块 | 结构化承载 `cwd` + `input`，无 HTML 注入面，且能快照执行时路径；为推荐方案 |

### 3.5 组件职责

#### 3.5.1 组件树

```
App.vue
└─ Terminal.vue
   ├─ TerminalOutput.vue
   │  └─ PromptBar.vue        （仅 command 块）
   └─ PromptBar.vue           （当前输入行）
   └─ TerminalInput.vue
```

#### 3.5.2 职责与接口

| 组件 | Props | Emits / Expose | 职责 |
| --- | --- | --- | --- |
| `Terminal.vue` | — | — | 组合布局；持有输入字符串；调用 Store；点击聚焦；滚动容器与自动滚动 |
| `TerminalOutput.vue` | `chunks: readonly OutputChunk[]` | — | 纯渲染；按类型分支；`command` 渲染提示符；`html` 走 `v-html` |
| `TerminalInput.vue` | `modelValue: string`；`history: readonly string[]` | `update:modelValue`；`submit`；`expose focus()`、`focusEnd()` | 透明 textarea、镜像文本、自绘光标、选区同步、IME、历史导航 |
| `PromptBar.vue` | `cwd: string` | — | 渲染 `用户@主机 路径 %`，路径按 home 缩写，分段着色 |

职责约束：

- 只有 `Terminal.vue` 直接使用 `useTerminalStore()`；其余组件通过 props/emits 工作，便于单测。
- `TerminalInput.vue` 不依赖 Store、不 import 命令层，历史数组由父组件传入。
- `TerminalOutput.vue` 不修改数据，不处理滚动，不感知 Store。
- `PromptBar.vue` 同时用于「当前输入行」和「历史回显行」，保证两处提示符样式完全一致。

#### 3.5.3 Terminal.vue 的关键行为

- 布局：全屏 flex 列；内部 `.terminal__scroll` 是唯一滚动容器，包含**输出区 + 输入行**（内容流式布局，提示符紧跟最后一行输出，贴近真实终端）。
- 自动滚动：监听 `chunks.length` 与输入长度，`nextTick` 后设置 `scrollTop = scrollHeight`。M1 采用「有新内容就滚到底」，不判断用户是否正在上翻；M10 再优化为「接近底部才自动滚」。
- 点击聚焦：根节点点击时，若目标不是 `a` / `button` / `textarea`，且当前没有文本选区，则调用 `inputRef.focusEnd()`；点击输入行由 textarea 原生定位光标。
- 挂载时尝试 `focusEnd()`；浏览器若因无用户手势拒绝聚焦，不视为错误，首次点击会补上。
- 提交：`store.submit(raw)` → 清空本地输入 → `nextTick` 后重新聚焦。

> 与 `PLAN.md` 的一处职责微调：自动滚动放在 `Terminal.vue` 而不是 `TerminalOutput.vue`，因为滚动容器同时包含输出与输入行；`TerminalOutput` 保持纯渲染。验收项不变。

#### 3.5.4 TerminalOutput.vue 的渲染规则

| chunk 类型 | 渲染 |
| --- | --- |
| `command` | `<PromptBar :cwd="chunk.cwd" />` + `chunk.input`（插值，自动转义） |
| `html` | `<div class="terminal-chunk__html" v-html="chunk.content" />` |
| `text` | 直接插值，`white-space: pre-wrap` |
| `system` | 直接插值，弱化色 |
| `error` | 直接插值，错误色 |

- `v-for` 使用索引作为 key：M1 的 `chunks` 只追加或在 `clear` 时整体清空，不存在中间插入/重排。
- 每个块是独立 block，保留 `content` 内部换行；不使用全局 `<pre>` 包裹，避免 M8 的 HTML 正文被 `pre` 限制。
- M1 没有任何 `html` 生产者；该分支只是为 M8 预留，且会配合 `escapeHtml` 与 Markdown 安全配置使用。

### 3.6 输入与光标

#### 3.6.1 分层结构

```
.terminal-input
├─ .terminal-input__mirror   可见层：文本 + 自绘光标
└─ textarea.terminal-input__capture
   透明文字、透明背景、透明原生光标；覆盖整行，负责真实输入/选区/IME
```

- 不使用 `opacity: 0`：那会连原生选区高亮一起隐藏。改为 `color: transparent; caret-color: transparent; background: transparent;`，让 textarea 的**半透明选区背景**可见，镜像文字透过选区显示。
- 两层共享完全相同的字体、字号、行高、字距、内边距、宽度与 `white-space`，保证镜像与 textarea 的换行位置一致。
- 镜像层 `pointer-events: none`，点击全部落在 textarea 上，浏览器原生完成「点击定位光标」。

#### 3.6.2 自绘光标

光标位置以 textarea 的 `selectionStart` 为唯一事实来源。镜像渲染时按当前位置切成三段：

```ts
const before = value.slice(0, caret)
const at = value.slice(caret, caret + 1) || ' ' // 行尾用空格占位
const after = value.slice(caret + 1)
```

- 光标是一个覆盖 `at` 字符的块：背景为主题光标色、文字反色；行尾时为空格块。
- 仅在「输入框聚焦、选区折叠、非输入法组合中」显示；失焦、拖选、组合输入时隐藏。
- 闪烁使用 CSS `steps` 动画；`prefers-reduced-motion: reduce` 时保持常亮。
- 选区非空时不画自绘光标，改用 textarea 原生选区高亮。
- 光标同步监听：`input`、`keyup`、`click`、`select`，以及聚焦期间的 `document.selectionchange`；组件卸载时移除全局监听。

#### 3.6.3 输入法（IME）

- `compositionstart` 时置 `isComposing = true` 并隐藏自绘光标；`compositionend` 后恢复。
- 组合期间按 Enter / ↑ / ↓ 一律不处理，交给输入法上屏。
- 组合结束用于「确认上屏」的那次 Enter 也不能提交：记录 `compositionend` 时刻，Enter 若紧随其后则只清除标记、不提交（兼容部分浏览器 `isComposing` 在 keydown 时为 false 的行为）。
- 组合期间镜像文本仍随 `input` 事件更新，候选窗口由 textarea 的原生光标位置定位。

#### 3.6.4 单行化与长度限制

- 输入框语义上是单行命令；粘贴内容中的 `\r\n` / `\r` / `\n` 一律替换为空格，避免命令块出现不可见换行。
- `maxlength = 1000`（`INPUT_MAX_LENGTH`）；超出由浏览器截断，不额外提示。
- 替换换行后尽量保持原光标偏移；若浏览器重置选区，则把光标放到文本末尾。

#### 3.6.5 自动增高与滚动

- 镜像层决定输入行的实际高度；textarea 绝对定位铺满该高度，不出现内部滚动条。
- 输入超过一行时输入行自动增高，由 `Terminal.vue` 的滚动逻辑保证底部可见。
- M1 不限制最大行数；1000 字符上限足以避免无限撑高。

#### 3.6.6 基础可访问性

- textarea 带 `aria-label="终端命令输入"`，关闭 `spellcheck` / `autocorrect` / `autocapitalize` / `autocomplete`。
- 提示符与镜像层 `aria-hidden="true"`，避免屏幕阅读器重复朗读装饰文本。
- 本里程碑不做 `aria-live`、焦点环、键盘全导航等完整方案，统一在 M10 处理。

> 已知边界：光标按 UTF-16 索引切分，组合 emoji 等代理对在极端位置可能被拆开显示；命令输入以 ASCII 为主，M1 不专门处理，M10 如需要再优化。

### 3.7 键盘与历史

| 按键 | 行为 |
| --- | --- |
| `Enter` | 非组合状态下 preventDefault：提交当前输入；空/纯空白不提交；提交后清空输入、重置历史导航、保持聚焦 |
| `↑` | 非组合状态下 preventDefault：上一条历史；首次按下先保存当前草稿；到最旧一条后停住，不循环 |
| `↓` | 非组合状态下 preventDefault：下一条历史；越过最新一条时恢复草稿并退出导航 |
| 其他按键 | 交给 textarea 原生处理（左右移动、Home/End、选区、删除等） |
| `Tab` | M1 不拦截、不补全；补全在 M10 |
| `Ctrl+L` / `Ctrl+C` | M1 不实现；快捷键在 M10 |

历史导航状态机：

- 组件内部维护 `navIndex: number | null` 与 `draft: string`；`navIndex === null` 表示正在编辑草稿。
- 首次按 ↑：`draft = 当前输入`，`navIndex = history.length - 1`；若历史为空则 no-op。
- 继续按 ↑：`navIndex` 递减，最小到 0 后停住。
- 按 ↓：`navIndex` 递增；超过 `history.length - 1` 时恢复 `draft`，`navIndex = null`。
- 回填历史后光标移到末尾。
- 对回填内容继续编辑**不会修改**历史条目；未提交的编辑在离开该条目后丢弃（再次 ↑ 取历史原文）。
- 提交、清空输入或历史数组变化时，重置 `navIndex` / `draft`。
- 不做 `Ctrl+R` 搜索、不做跨刷新保留；`history` 命令由 M4 提供。

### 3.8 临时回显与清屏

`store.submit(raw)` 的临时逻辑（M2 替换点）：

```ts
const command = raw.trim()
if (!command) return

recordHistory(command)

if (command === 'clear') {
  outputBuffer.clear()
  return
}

outputBuffer.push({ type: 'command', cwd: cwd.value, input: command })
outputBuffer.push({ type: 'system', content: siteConfig.messages.commandUnavailable })
```

行为细则：

- **回显格式**：`guest@fun-terminal ~ % <命令>`；提示符使用执行时的 `cwd` 快照，路径段颜色与当前提示符一致；命令文本使用默认前景色。
- **临时提示**：回显下一行输出灰色 system 块，文案取 `siteConfig.messages.commandUnavailable`。
- **`clear` 判定**：trim 后严格等于 `clear`，区分大小写；`clear foo`、`CLEAR` 都按普通输入处理（回显 + 临时提示）。
- **`clear` 效果**：清空 `chunks`、滚动位置回到顶部；`cwd`、`env`、`history` 不变；`clear` 本身在清屏前已记入历史。
- **空输入**：不产生回显、不写历史；父组件仍会清空输入框。
- **其他输入**（包括 `ls`、`cd`、`help`）：一律回显 + 临时提示，不报错、不解析，因为命令层尚未接入。
- **替换计划**：M2 把 `submit` 内部改为 Parser → Registry → Executor，并在执行器之前保留 `clear` 的临时前置特例；M4 由内置 `clear` 命令接管后删除 `if (command === 'clear')` 特例。组件与输出块模型不变。

| `OutputChunk` 契约在 M2 反复调整 | 命令层返工 | M1 一次冻结五型；D-03 审核确认后再实施 |
| 新输出总是强制滚到底，打断上翻阅读 | 阅读旧输出不便 | M1 接受；M10 改为「接近底部才自动滚」 |
| 1000 字符输入或大段输出撑高页面 | 布局抖动 | 外层固定视口、内部滚动；输入上限 1000；长输出由滚动容器消化 |
