## 1. 需求背景

M2 已完成命令内核：解析 → 注册 → 执行 → 兜底 → 串行队列的链路冻结，`echo` / `help` / `clear` 三条核心命令走完真实执行路径，并经人工页面验收。但**命令层目前拿不到任何文件系统**：`CommandContext` 只有 `args` / `options` / `cwd` / `env` / `dataSource` / `output` / `commands` / `setCwd`，`vfs` 与 `mounts` 仍是 M2 明确推迟的空位（M2 需求文档 Q-06）。

当前 `src/fs/` 的真实状态是「只有类型，没有实现」：

| 项 | 现状 | M3 需要改变的部分 |
| --- | --- | --- |
| `src/fs/path.ts` | 不存在 | 新增纯函数路径模块：`normalize` / `resolve` / `join` 等 |
| `src/fs/vfs.ts` | 仅 `VfsNode` / `Vfs` / `VfsResolveResult` 类型，无实现 | 实现节点构造器与 `createVfs()`，并补内部挂载写入能力 |
| `src/fs/mount.ts` | 仅 `MountManager` 接口（`mount(target, source, node)` + `apply(vfs)`），与架构文档的 `MountApi` 已不一致 | 按架构文档重定义 `MountApi` 并实现 `createMountManager()` |
| `src/fs/build.ts` | 不存在 | 新增「普通对象 → 只读子树」构建器，供插件复用 |
| `src/fs/index.ts` | 不存在 | 新增文件系统装配：初始树（`/`、`/home/<user>`、`/mnt`）+ 应用级单例 |
| `CommandContext` | 无 `vfs` / `mounts` | 按 D-01 扩展两个必填字段 |
| `src/commands/index.ts` | `CommandRuntimeDeps` 只有 `dataSource` | 增加 `vfs` / `mounts`，为 M6 的 `PluginApi` 预留装配位 |

还有一处**必须先解决的契约冲突**：`src/fs/mount.ts` 定义的 `MountManager` 带 `source` 字符串参数与 `apply(vfs)` 方法，而《项目架构文档》第 7 节与 `PLAN.md` M3/M6 已经统一到「`MountApi`：`mount(target, tree)` / `unmount(target)` / `list()`，核心负责挂载与 `parent` 指针修正」。两份契约只能留一份，且必须在没有实现时定稿（Q-01）。

为什么现在必须做 M3：

- **M4** 的 `cd` / `pwd` 要基于真实目录树校验「目录是否存在」「是不是目录」，`cd` 的路径语义（`~`、`.`、`..`）完全依赖本里程碑的路径模块。
- **M5** 的 `ls` / `cat` 需要 `readDir` / `readFile` 与 `VfsNode.meta`（二进制/图片识别）。
- **M6** 的插件装载器把 `api.mounts` 作为核心能力交给插件；`MountApi` 的返回值与失败原因不定稿，M6 的 `mount`/`unmount` 命令无法给出可读错误。
- **M8/M9** 的内容树全部由 `build.ts` 构造后挂到 `/mnt/**`；构建器与挂载白名单是本里程碑的产物。
- 路径规则一旦被 `cd`/`ls`/`cat` 依赖，改造成本随命令数量线性上升，必须在**只有 0 个文件系统命令**时冻结。

**依据文档**：

- `docs/PLAN.md` 第 3 节「M3 虚拟文件系统（VFS）与挂载」、第 5 节 D-01、第 6 节跨里程碑技术约定（路径、插件形态、测试）
- `docs/项目架构文档.md` 第 4 节（分层）、第 7 节（VFS 与挂载，含 `MountApi` 定义与白名单）、第 9 节（数据流）

## 2. 需求描述

### 2.1 目标

为终端提供**统一的、只读的虚拟目录树与路径语义**，作为后续所有文件系统命令与内容插件的唯一数据访问入口：

```
                    ┌──────────────────────────────┐
                    │ CommandContext               │
                    │  vfs: Vfs（只读查询）         │
                    │  mounts: MountApi（挂载管理） │
                    └───────────▲──────────────────┘
                                │ 上下文构建时注入
                    ┌───────────┴──────────────────┐
                    │ createCommandRuntime({...})  │
                    │  deps: dataSource/vfs/mounts │
                    └───────────▲──────────────────┘
                                │ 装配
 ┌──────────────────────────────────────────────────────────┐
 │ src/fs/index.ts  createFileSystem({ homeDir })           │
 │   ├─ vfs    : MutableVfs   初始树 / + /home/<user> + /mnt │
 │   └─ mounts : MountApi     绑定同一 vfs，白名单 /mnt/**    │
 ├──────────────────────────────────────────────────────────┤
 │ path.ts（纯函数）  build.ts（对象→子树）  vfs.ts  mount.ts │
 └──────────────────────────────────────────────────────────┘
```

本里程碑结束时，代码具备：

1. 一套**无 UI、无副作用、可单测**的 POSIX 路径函数（`src/fs/path.ts`）；
2. 一个**节点模型可构造、路径可解析、目录/文件可读取**的只读 VFS（`src/fs/vfs.ts`）；
3. 一个**白名单受限、可挂载/卸载、能修正 `parent` 指针**的挂载管理器（`src/fs/mount.ts`）；
4. 一个**由普通对象描述生成只读子树**的构建器（`src/fs/build.ts`），供 M6/M8/M9 复用；
5. 一个**初始树已就绪、可直接注入上下文**的文件系统装配（`src/fs/index.ts`）；
6. `CommandContext` 增加 `vfs` / `mounts`，M4 起的文件系统命令开箱可用。

### 2.2 用户可见行为

**本里程碑不新增任何命令，访客侧可见行为零变化。** 需要刻意确认的只有「不退化」：

1. 终端启动、欢迎语、提示符、输入回显、`echo`/`help`/`clear` 的行为与 M2 完全一致。
2. `help` 清单仍为 `echo`/`help`/`clear` 三条（VFS 不注册命令，`ls`/`cat` 仍提示未找到）。
3. `cwd` 仍为 `/home/guest`，`pwd` 尚不存在；提示符路径段显示不变。
4. 刷新页面后会话重置行为不变。
5. 浏览器控制台无新增报错、无未处理 Promise rejection（挂载告警仅在**非法挂载**时出现，装配阶段无告警）。

> M3 的产出是「能力」而非「界面」。VFS 是否真的可用，由 3.9 的单元测试与 5.2 的自动化验收项证明；M4 落 `cd`/`pwd` 时才第一次对访客可见。因此第 5 节不含新增功能的人工 GUI 验收项，只保留一次**人工回归确认**——该处理方式本身列入 Q-05 待确认。

## 3. 方案设计

### 3.1 总体结构与分层

| 模块 | 职责 | 依赖方向 |
| --- | --- | --- |
| `fs/path.ts` | 纯字符串路径运算，不认识节点 | 不依赖任何项目模块 |
| `fs/vfs.ts` | 节点构造、路径查找、读写查询；`attachNode`/`detachNode` 为核心内部写入 | 仅依赖 `fs/path.ts` |
| `fs/mount.ts` | 挂载白名单、挂载表、恢复语义 | 依赖 `fs/path.ts` + `fs/vfs.ts`（`MutableVfs`） |
| `fs/build.ts` | 普通对象 → 只读子树，校验节点名 | 依赖 `fs/vfs.ts` |
| `fs/index.ts` | 初始树 + `createFileSystem()` + 应用级单例 | 依赖上述四者 + `config/site.ts`（仅取默认 home） |
| `commands/index.ts` | 装配 registry + 文件系统 + 数据源 | 依赖 `fs/index.ts` |
| `stores/terminal.ts` | 把 `vfs`/`mounts` 透传给上下文构建器 | 依赖 `commands/index.ts` |

约束：

- 命令与插件只看到 `Vfs`（只读）与 `MountApi`，**看不到 `MutableVfs`**，从类型上就无法绕过白名单改树。
- `fs/path.ts`、`fs/vfs.ts`、`fs/mount.ts`、`fs/build.ts` 不含任何 `vue` / `pinia` / DOM 依赖，可在 Vitest 中直接实例化。
- 文件系统实例**不放进 Store**：它是应用级只读数据，会话只持引用（M2 的 `dataSource` 同构）。

### 3.2 路径模块（`src/fs/path.ts`，新增）

```ts
export function isAbsolute(path: string): boolean
export function normalize(path: string): string
export function join(...parts: string[]): string
export function resolve(base: string, target: string): string
export function dirname(path: string): string
export function basename(path: string): string
```

#### 3.2.1 规范化规则

| 规则 | 说明 |
| --- | --- |
| 空串 | `normalize('')` → `/` |
| 反斜杠 | 先统一替换为 `/`（Q-06）；因此 `\\mnt\\blog` → `/mnt/blog` |
| 重复斜杠 | 折叠为单个 `/`（`/mnt//blog` → `/mnt/blog`） |
| `.` 段 | 丢弃 |
| `..` 段 | 弹出上一段；**已在根时停留根**（`/..` → `/`，`/../../x` → `/x`） |
| 结尾斜杠 | 去除非根路径的结尾 `/`（`/mnt/` → `/mnt`；`/` → `/`） |
| 相对输入 | `normalize` / `join` 一律返回以 `/` 开头的**绝对路径**，相对段视为相对根（`a/b` → `/a/b`） |
| 大小写 | **不转换**，区分大小写（与 Linux 一致） |
| `~` | **不展开**，`~` 只是普通字符；展开由命令层（M4）基于 `siteConfig.homeDir` 负责 |

`normalize` 不校验名称合法性（是否含控制字符、是否超长），名称校验只在 `build.ts` 与挂载白名单处发生。

#### 3.2.2 函数语义

| 函数 | 语义 | 示例 |
| --- | --- | --- |
| `isAbsolute` | 是否以 `/` 开头 | `isAbsolute('/mnt')` → `true`；`isAbsolute('mnt')` → `false` |
| `normalize` | 规范化为绝对路径 | `normalize('/mnt/../home/./guest/')` → `/home/guest` |
| `join` | 拼接后规范化；无参数 → `/` | `join('/mnt', 'blog', 'a.md')` → `/mnt/blog/a.md` |
| `resolve` | `target` 为绝对路径则直接规范化，否则相对 `base` 解析；`target` 为空串 → `normalize(base)` | `resolve('/home/guest', '../mnt')` → `/home/mnt`；`resolve('/home/guest', '/mnt')` → `/mnt` |
| `dirname` | 父目录；根返回根 | `dirname('/a/b')` → `/a`；`dirname('/a')` → `/`；`dirname('/')` → `/` |
| `basename` | 末段名；根返回空串 | `basename('/a/b/')` → `b`；`basename('/')` → `''` |

`resolve(base, target)` 是 M4/M5 的统一入口：命令收到相对路径先 `resolve(ctx.cwd, arg)`，再把绝对路径交给 `ctx.vfs`。**`~` 展开必须发生在 `resolve` 之前**（M4 的 `cd` 负责），否则 `~` 会被当成普通目录名。

### 3.3 节点模型与 VFS 实现（`src/fs/vfs.ts`）

#### 3.3.1 契约变化

`VfsNode` / `VfsNodeType` / `VfsResolveResult` / `Vfs` **字段与签名保持不变**（`Vfs` 仍只有 5 个成员），仅补充实现与新增内部接口：

```ts
// 公开只读契约：命令、插件、CommandContext 只能用这个
export interface Vfs {
  readonly root: VfsNode
  resolve(path: string): VfsResolveResult
  exists(path: string): boolean
  readDir(path: string): VfsNode[] | null
  readFile(path: string): string | null
}

// 核心内部契约：只交给 MountManager，不出现在 CommandContext / PluginApi
export interface MutableVfs extends Vfs {
  /** 把 node 挂到 path（父目录必须已存在）；返回被替换的旧节点，无则 null */
  attachNode(path: string, node: VfsNode): VfsNode | null
  /** 从 path 摘除节点并返回；不存在返回 null */
  detachNode(path: string): VfsNode | null
}

export function createDirectoryNode(
  name: string,
  children?: readonly VfsNode[],
  meta?: Record<string, string>,
): VfsNode

export function createFileNode(
  name: string,
  content?: string,
  meta?: Record<string, string>,
): VfsNode

export function createVfs(options?: { root?: VfsNode }): MutableVfs
```

| 变更点 | 变更前 | 变更后 | 理由 |
| --- | --- | --- | --- |
| 节点构造 | 无 | `createDirectoryNode` / `createFileNode` | `build.ts`、测试、M6 插件树共用 |
| 挂载写入 | 无 | `MutableVfs.attachNode` / `detachNode` | 让 `MountApi` 能改树，同时不把写能力暴露给命令/插件 |
| `Vfs` 只读契约 | 已定义 | **不变** | 避免契约蔓延 |

`createDirectoryNode` 传入 `children` 时，会**同时设置每个子节点的 `parent`**并追加进 `children` 数组（便于 `build.ts` 递归构造）；`createFileNode` 的 `content` 缺省为 `''`。

#### 3.3.2 查询语义

| 调用 | 输入 | 结果 |
| --- | --- | --- |
| `resolve` | `/mnt/./blog/` | `{ node: <blog 节点>, path: '/mnt/blog' }` |
| `resolve` | `/nope` | `{ node: null, path: '/nope' }` |
| `resolve` | `/mnt/blog/x`，其中 `blog` 是文件 | `{ node: null, path: '/mnt/blog/x' }`（中途非目录即失败） |
| `resolve` | 相对路径 `mnt/blog` | `console.warn` 提示「VFS 路径必须为绝对路径」，并**按根解析**为 `/mnt/blog`（Q-04） |
| `exists` | 任意 | `resolve(path).node !== null` |
| `readDir` | 目录 | 子节点**数组副本**（保持插入顺序，不排序） |
| `readDir` | 文件 / 不存在 | `null` |
| `readFile` | 文件 | `content`（`undefined` 视为 `''`） |
| `readFile` | 目录 / 不存在 | `null` |
| `root` | — | 根目录节点，`root.parent === null`，`root.name === ''` |

- **根节点名为空串**，与 `basename('/') === ''` 保持一致；根名不参与任何展示。
- `readDir` 返回**副本**，命令改数组不会破坏树；但节点对象本身仍是引用（见 4.3 风险）。
- 排序、着色、`-a`/`-l` 格式化全部属于 M5 的 `ls`，VFS 不做展示层加工。
- 所有查询**不抛异常**：任何非法/不存在路径都返回 `null` 形态，由命令决定错误文案。

#### 3.3.3 写入语义（仅核心内部）

| 方法 | 前置条件 | 行为 |
| --- | --- | --- |
| `attachNode(path, node)` | `dirname(path)` 存在且为目录、且 `path !== '/'`（由 `MountManager` 预先校验） | `node.name = basename(path)`；`node.parent = 父节点`；同名子节点**原位替换**并返回旧节点（旧节点 `parent` 置 `null`），否则追加到末尾并返回 `null` |
| `detachNode(path)` | 父目录存在且 `path !== '/'` | 从 `children` 移除并返回该节点，`node.parent = null`；不存在返回 `null` |

前置条件被违反（父目录缺失/不是目录、尝试替换根节点）属**编程错误**，实现直接 `throw new Error(...)`；用户输入无法触发（挂载入口已校验，`mount.ts` 也不做二次兜底）。

#### 3.3.4 算法骨架

```ts
function normalizeAndWarn(path: string): string {
  if (!isAbsolute(path)) console.warn('[fun-terminal] VFS 路径必须为绝对路径，已按根解析:', path)
  return normalize(path)
}

function resolve(path: string): VfsResolveResult {
  const normalized = normalizeAndWarn(path)
  if (normalized === '/') return { node: root, path: normalized }
  let current = root
  for (const segment of normalized.split('/').filter(Boolean)) {
    if (current.type !== 'directory') return { node: null, path: normalized }
    const next = current.children?.find((child) => child.name === segment)
    if (!next) return { node: null, path: normalized }
    current = next
  }
  return { node: current, path: normalized }
}
```

### 3.4 挂载管理（`src/fs/mount.ts`，重写）

#### 3.4.1 契约定稿（Q-01 / Q-02）

删除 `MountManager`、`MountPoint.source`、`apply(vfs)`；按《项目架构文档》第 7 节落地 `MountApi`，并补上**失败原因**（Q-02）：

| 变更点 | 变更前（`MountManager`） | 变更后（`MountApi`） | 理由 |
| --- | --- | --- | --- |
| 命名 | `MountManager` | `MountApi` | 与架构文档第 7 节、`PLAN.md` M3/M6 统一 |
| 挂载入参 | `mount(target, source, node)` | `mount(target, tree)` | `source` 是 M0 时代「静态目录映射」的遗留概念，一期所有树都由 `build.ts` 构造，无需来源字符串 |
| 返回值 | `void` | `MountResult` / `boolean` | M6 的 `mount`/`unmount` 插件命令需要区分失败原因并输出中文提示 |
| 挂载点字段 | `{ target, source, node }` | `{ target, node }` | 去掉无意义的 `source` |
| 应用方式 | `apply(vfs)` | 构造时绑定 `vfs` | `apply` 要求把「挂载表」与「VFS 状态」分两步同步，容易产生不一致；构造时绑定后，`mount` 立即改树 |
| 嵌套 | 未定义 | 一期禁止（Q-03） | 父子挂载的恢复顺序会产生歧义（卸父后子挂载悬空），一期无业务需要 |

#### 3.4.2 校验与行为

`mount(target, tree)` 按顺序执行，任一失败即返回并 `console.warn`（不抛错，避免单个插件挂载失败阻断启动）：

| 顺序 | 校验 | 失败原因 | 告警文案（`[fun-terminal]` 前缀） |
| --- | --- | --- | --- |
| 1 | `target = normalize(target)` 后必须匹配 `/^\/mnt(\/[^/]+)+$/`（`/mnt` 本身不允许，至少一级子目录） | `invalid-target` | `挂载点非法，仅允许 /mnt/** 下至少一级子目录: <target>` |
| 2 | 目标父目录必须存在且为目录（`vfs.resolve(dirname(target))`） | `parent-missing` | `挂载父目录不存在或不是目录: <target>` |
| 3 | `tree.type === 'directory'` 且 `tree.parent === null`（同一树实例不可重复挂载） | `invalid-tree` | `挂载树必须是未挂载的目录节点: <target>` |
| 4 | 挂载表中无同一 `target` | `duplicate` | `挂载点重复，已保留先挂载者: <target>` |
| 5 | 与已有挂载点无父子关系（`a` 与 `a/b` 互斥） | `nested` | `不支持嵌套挂载: <target>（已有挂载点 <existing>）` |
| 6 | 全部通过 | — | 无告警：`previous = vfs.attachNode(target, tree)`，挂载表记录 `{ target, node: tree, previous }` |

- 白名单按**规范化后**的目标判断：`/mnt/../home` → `/home` 被拒；`/mnt/./blog/` → `/mnt/blog` 允许，挂载表与 `list()` 记录的都是规范化路径。
- 白名单只要求「段非空、不含 `/`」，**允许中文与 Unicode 目录名**（Q-07），因此 `/mnt/示例` 合法。
- 目标节点已存在（如初始树里的空目录 `/mnt/blog`）时被覆盖，旧节点存入 `previous`；目标不存在时新建并记为 `previous: null`。

`unmount(target)`：

| 情形 | 行为 |
| --- | --- |
| 目标未挂载 | `console.warn('挂载点不存在: <target>')`，返回 `false` |
| 有 `previous` | `vfs.attachNode(target, previous)` 恢复原节点（`parent` 指针由 `attachNode` 修正），返回 `true` |
| 无 `previous`（挂载时目标不存在） | `vfs.detachNode(target)` 移除该目录，父目录恢复原样，返回 `true` |
| 卸载成功后 | 被挂载树的 `parent` 置 `null`（`attachNode` 替换时处理），该树可再次挂载 |

`list()` 返回挂载点**快照数组**（按挂载顺序），调用方修改数组不影响内部状态。

#### 3.4.3 实现骨架

```ts
interface MountRecord {
  target: string
  node: VfsNode
  previous: VfsNode | null
}

export function createMountManager(vfs: MutableVfs): MountApi {
  const records = new Map<string, MountRecord>()

  function mount(target: string, tree: VfsNode): MountResult {
    const normalized = normalize(target)
    if (!MOUNT_TARGET_PATTERN.test(normalized)) return fail('invalid-target', normalized)
    const parent = vfs.resolve(dirname(normalized)).node
    if (!parent || parent.type !== 'directory') return fail('parent-missing', normalized)
    if (tree.type !== 'directory' || tree.parent !== null) return fail('invalid-tree', normalized)
    if (records.has(normalized)) return fail('duplicate', normalized)
    const nesting = findNestedTarget(records.keys(), normalized)
    if (nesting) return fail('nested', normalized, nesting)

    const previous = vfs.attachNode(normalized, tree)
    records.set(normalized, { target: normalized, node: tree, previous })
    return { ok: true }
  }

  function unmount(target: string): boolean {
    const normalized = normalize(target)
    const record = records.get(normalized)
    if (!record) { warn(`挂载点不存在: ${normalized}`); return false }
    if (record.previous) vfs.attachNode(normalized, record.previous)
    else vfs.detachNode(normalized)
    records.delete(normalized)
    return true
  }

  return { mount, unmount, list: () => [...records.values()].map(({ target, node }) => ({ target, node })) }
}
```

`MOUNT_TARGET_PATTERN = /^\/mnt(\/[^/]+)+$/`；`fail` 内部统一 `console.warn` 并返回 `{ ok: false, reason }`。

### 3.5 静态树构建器（`src/fs/build.ts`，新增）

供 M6/M8/M9 在 `install` 中把内容清单描述成子树，避免每个插件各写一套节点拼装：

```ts

export type TreeEntry =
  | string                                              // 文件：值为正文
  | { file: string; meta?: Record<string, string> }     // 文件：正文 + 元信息
  | { dir: TreeSpec; meta?: Record<string, string> }    // 目录：子项 + 元信息

export function buildTree(
  spec: TreeSpec,
  options?: { name?: string; meta?: Record<string, string> },
): VfsNode
```

示例（M8 博客插件将来的用法）：

```ts
buildTree({
  'hello.md': '# 你好\n正文…',
  'about.md': { file: '关于我', meta: { mime: 'text/markdown' } },
  'drafts': { dir: { 'wip.md': '草稿' } },
})
// → 目录节点（name 由 options.name 决定，默认 ''），由 mounts.mount('/mnt/blog', tree) 重命名为 blog
```

校验规则（违反即 `throw new Error('...')`，属构建期配置错误；M6 的装载器会隔离单个插件的 `install` 异常）：

| 规则 | 说明 |
| --- | --- |
| 节点名非空 | `''` 不合法 |
| 节点名不含 `/`、`\` | 避免与路径分隔符冲突 |
| 节点名不是 `.` / `..` | 避免与规范化语义冲突 |
| `TreeEntry` 形态 | 字符串 → 文件；对象必须含 `file` 或 `dir` 之一（同时含两者视为非法） |
| 元信息 | `meta` 原样挂到节点，不做语义校验（`mime` 约定由 M8/M9 使用） |
| 重复键 | JS 对象字面量的重复键由语言静默取后者，构建器不做检测（一期树为手写常量） |

`buildTree` 递归使用 `createDirectoryNode` / `createFileNode`，因此所有子节点 `parent` 在构造时即正确。
