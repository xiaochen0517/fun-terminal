## 1. 需求背景

M6 已把「插件挂载内容 + 注册命令」的装载机制跑通并人工验收（`/mnt/demo` + `mount` / `unmount`，`ready` 就绪门）；M7 已把数据层从占位实现换成真实的 `StaticDataSource`（`public/content/articles/index.json` 元数据 + 3 篇 Markdown 正文，运行时 `fetch`、三级缓存、失败降级），并完成自动化验收。**但到目前为止，这 3 篇文章对访客完全不可见**：没有任何命令消费 `ctx.dataSource`，`/mnt` 下也只有 `demo`，`html` 输出块虽在 M1 就定稿，却没有任何命令真正产出富文本。

当前代码的真实状态（M7 完成后）：

| 项 | 现状 |
| --- | --- |
| 命令 | 10 条：`echo` / `help` / `clear` / `pwd` / `cd` / `history` / `ls` / `cat`（核心）+ `mount` / `unmount`（demo 插件） |
| `/mnt` | 仅 `demo/`（示例插件在装配阶段挂载） |
| 文章数据 | `public/content/articles/index.json`（3 条）+ `hello.md` / `about.md` / `vfs-notes.md`；`StaticDataSource` 已可用，但**无任何命令消费** |
| Markdown | 无渲染层、无 `markdown-it` 依赖、`theme.css` 无正文样式 |
| `html` 输出块 | `OutputBuffer.writeHtml()` 与 `TerminalOutput` 的 `v-html` 渲染均已在 M1 就位，**零实际使用** |
| 测试基线 | 31 个测试文件 / 419 个用例；`terminal-store.spec.ts` 断言 `help` 为「共 10 条」、`/mnt` 仅 `demo/`、挂载列表仅 1 项 |

**为什么现在做 M8**：

- **内容闭环的最后一块**：M7 只把数据准备好，访客能「看到文章」的唯一路径是命令。缺了 M8，M7 的价值无法被任何人感知；M8 完成后「列表 → 阅读（富文本）→ 原文 → 标签筛选」全部在终端内闭环。
- **前端唯一剩下的大块可见变化**：M9（图片插件）规模为 S、M10 是打磨收尾；M8 是 M6/M7 两块地基的第一次实战检验（插件异步 `install` + `dataSource` 投影 VFS + `html` 输出块 + Markdown 渲染 + 正文样式）。
- **契约必须在此定型**：`/mnt/blog` 与 `blog` 命令要「同源」——同一份正文既要能被 `cat` 按文本读，又要能被 `blog read` 渲染成富文本。若先写命令、后补挂载，极易出现两份内容各自维护（PLAN 第 8 节风险表已列该条）。
- **渲染安全必须在只有 3 篇文章时建立**：`markdown-it` 的 `html:false`、链接 `rel="noopener noreferrer"`、动态文本 `escapeHtml` 一旦漏配，后续文章数量增长后很难追溯与补救。
- **可见变化明确、适合人工验收**：本里程碑会改变 `help` 条数、`/mnt` 内容与新增 1 条命令的 5 种用法，属于 `AGENTS.md` 第三节定义的 GUI 可见变化，必须走人工页面验收。

## 2. 需求描述

### 2.1 目标

新增**博客插件**（`src/commands/plugins/blog/`），通过 M6 的 `PluginApi` 完成两件事：

1. **把文章投影进 VFS**：`install(api)` 阶段从 `api.dataSource` 读取清单与正文，挂载 `/mnt/blog`，文件名 `<id>.md`，内容与 `DataSource` 返回的正文完全一致——`cat /mnt/blog/<id>.md` 读到的是同一份原文。
2. **注册 `blog` 命令**：单条命令 + 4 个子命令，覆盖浏览闭环：

```
blog list               按发布日期倒序列出全部文章（id / 日期 / 标题）
blog read <id>          富文本阅读（Markdown → HTML，html chunk）
blog read --raw <id>    纯文本原文（text chunk，与 cat 一致）
blog tags               标签及文章数
blog tag <tag>          按标签过滤列表
```

同时新增**Markdown 渲染层**（`src/markdown/`，唯一新依赖 `markdown-it`）与**正文样式**（`theme.css` 的 `.md` 作用域），并把渲染安全（原始 HTML 不生效、链接新窗口 + `rel="noopener noreferrer"`、动态文本转义）固化为可测约束。

```
应用启动（模块装配）
  └─ createCommandRuntime({ dataSource, vfs, mounts, plugins: [demoPlugin, blogPlugin] })
       ├─ 同步：注册 8 条核心命令
       └─ ready = 按序 await install：
            ├─ demoPlugin.install  → 挂载 /mnt/demo
            └─ blogPlugin.install
                 ├─ await api.dataSource.fetchArticleList()          （清单，1 次请求）
                 ├─ await Promise.all(ids.map(fetchArticle))         （正文，按 id 缓存）
                 ├─ createBlogTree(已加载文章) → buildTree({ '<id>.md': { file, meta } })
                 └─ api.mounts.mount('/mnt/blog', tree)              （失败只告警，命令仍注册）

用户执行 `blog read vfs-notes`
  └─ Store → Executor → await ready（保证已装载）
       └─ blogCommand.execute(ctx)
            ├─ 分发子命令 read + 校验 --raw
            ├─ await ctx.dataSource.fetchArticle('vfs-notes')   （缓存命中，毫秒级）
            ├─ renderMarkdown(article.content)                  （html:false / linkify / breaks）
            └─ ctx.output.writeHtml('<article class="md">…</article>')
                 └─ TerminalOutput 以 v-html 渲染，.md 样式接管排版
```

### 2.2 用户可见行为

以下文本与格式为验收基线（括号内为 chunk 类型）。

**A. 命令发现**

1. **`help` 变为 11 条**：新增 `blog` 一行，仍按名称升序、两列对齐、页脚不变（`text`）。`blog` 的说明为 `浏览博客文章（list / read / tags / tag）`，`help blog` 输出该说明与 `用法: blog <list|read|tags|tag> [参数]`。
2. **`/mnt` 多一个目录**：`ls /mnt` 输出 `blog/` 与 `demo/`（按 M5 的排序规则，`blog` < `demo`）；`ls /mnt/blog` 输出 `about.md` / `hello.md` / `vfs-notes.md`；`ls -l /mnt/blog` 的大小列等于对应 Markdown 的 UTF-8 字节数（`text`）。

**B. 列表**

3. **`blog list`**（`text`）：

   ```
   共 3 篇文章（按发布日期倒序）：

     vfs-notes  2026-11-10  在浏览器里造一个文件系统
     about      2026-11-08  关于本站与作者
     hello      2026-11-06  你好，终端

   输入 blog read <id> 阅读全文，输入 blog tags 查看标签。
   ```

   `id` 列按最长 id 左对齐补空格，`id` 与日期、日期与标题之间各两个空格；行首缩进两格。
4. **`blog list` 的空态**：数据源返回空列表（内容未发布或加载失败）时输出系统提示（`system`）：`blog: 暂无文章（内容尚未发布或加载失败，稍后重试即可）`。

**C. 富文本阅读**

5. **`blog read <id>` 输出富文本**（`html`）：单个 `<article class="md">` 块，内含
   - 一行 meta：`<div class="md__meta">2026-11-10 · 技术 / 前端 / 终端</div>`（日期 · 标签用 ` / ` 连接；无标签时只留日期；日期缺失时只留标签）；
   - 渲染后的正文：`#` → `<h1>`、`##` → `<h2>`、段落、无序 / 有序列表、`>` → `<blockquote>`、```` ```ts ```` → `<pre><code class="language-ts">`、行内代码 → `<code>`、表格 → `<table>`、外部链接 → `<a href="…" target="_blank" rel="noopener noreferrer">`。
6. **代码块与表格不撑破布局**：`<pre>` 在自身块内横向滚动，`<table>` 同样在自身块内横向滚动；375px 宽下页面本身**不出现横向滚动条**，输入行仍可见可用。
7. **阅读不追加多余提示**：`blog read` 只输出 meta + 正文，不追加页脚、不输出 Markdown 标记；命令回显（`command` 块）与提示符仍各占一行，不与正文粘连。
8. **`blog read --raw <id>` 输出纯文本原文**（`text`）：内容与 `cat /mnt/blog/<id>.md` 完全一致（含结尾换行，`#`、`>`、```` ``` ```` 等标记原样保留），提示符另起一行。
9. **未知 id**：`blog read nope` 输出错误（`error`）：`blog: 文章不存在: nope，输入 blog list 查看全部文章`；不发起正文请求（由数据源保证），会话不中断。
10. **正文为空**：`blog read <id>` 拿到空正文时输出 `blog: 文章内容为空: <id>`，不渲染空壳 `<article>`。

**D. 标签**

11. **`blog tags`**（`text`）：按文章数倒序、数量相同按标签名（`Intl.Collator('zh-Hans-CN')`）升序，格式为每行 `  标签（N 篇）`：

    ```
    共 6 个标签（按文章数倒序）：

      公告（2 篇）
      技术（1 篇）
      前端（1 篇）
      入门（1 篇）
      随笔（1 篇）
      终端（1 篇）
    ```

    无标签时输出 `blog: 暂无标签`（`system`）。
12. **`blog tag <tag>`**（`text`）：输出 `标签「公告」下的文章（2 篇）：` + 空行 + 与 `blog list` 相同的行格式；无命中时输出错误 `blog: 标签「xxx」下暂无文章，输入 blog tags 查看全部标签`；列表为空时先按第 4 条的空态处理。

**E. 参数与错误（全部为 `error`，且不改变 VFS / 会话状态）**

13. `blog`（无子命令）→ `blog: 缺少子命令（可用: list / read / tags / tag，输入 help blog 查看用法）`
14. `blog nope` → `blog: 未知子命令: nope（可用: list / read / tags / tag，输入 help blog 查看用法）`
15. `blog read` → `blog: 缺少文章 id（用法: blog read [--raw] <id>）`
16. `blog read a b` → `blog: 参数过多（一次只能阅读一篇）`
17. `blog read -n hello` → `blog: 不支持的选项: -n`
18. `blog list foo` / `blog tags foo` → `blog: 子命令 list 不接受参数` / `blog: 子命令 tags 不接受参数`
19. `blog tag` → `blog: 缺少标签（用法: blog tag <标签>）`；`blog tag a b` → `blog: 参数过多（一次只能筛选一个标签）`；`blog tag --raw 公告` → `blog: 不支持的选项: --raw`
20. **参数与选项解析沿用 M2 规则**：`blog read --raw hello` 与 `blog read hello --raw` 等价；`blog tag "公告"` 与 `blog tag 公告` 等价。

**F. 稳定与回归**

21. **首屏不阻塞、首条命令等待就绪**：页面渲染与输入不等待插件装载；首条命令前 `await ready`（静态数据毫秒级），不会误报「未找到命令」。
22. **降级可读且可重试**：清单或正文加载失败时，`/mnt/blog` 仍作为目录存在（内容可能为空），`blog list` 输出第 4 条空态；数据源失败不缓存，再次执行命令可重试成功；终端其他命令不受影响。
23. **无噪音**：正常路径不写 `console.*`；无未处理 Promise rejection；不新增快捷键、UI 控件、主题切换。
24. **既有交互无退化**：`ls` / `cat` / `cd` / `pwd` / `history` / `clear` / `echo` / `mount` / `unmount` 与 M6 已验收行为一致；`mount` / `unmount` 因 `/mnt/blog` 存在，挂载列表由 1 项变为 2 项（`/mnt/blog`、`/mnt/demo`），`unmount /mnt/demo` 后 `ls /mnt` 仍剩 `blog/`（属预期，见 Q-12）。
25. **刷新重置**：刷新后 `cwd` 回 home、历史清空，`/mnt/blog` 随插件重新装载再次可见。

> **访客不可见但必须成立**：`blog` 命令不 import Store / `window` / `fetch` / 静态文件，只通过 `ctx.dataSource`、`ctx.vfs`、`ctx.output` 工作；插件不直接改 VFS，只提交只读子树给 `api.mounts`；Markdown 原文中的 HTML 标签不生效（渲染为文本）。

> - **正文内容以 M7 交付的 3 篇文章为准**（`public/content/articles/`）；若在验收前修改了文章，需重跑数据层单测。

### 3.2 依赖与渲染器

**新增依赖**（唯一一项，需在评审时确认）：

| 依赖 | 类型 | 版本 | 理由 |
| --- | --- | --- | --- |
| `markdown-it` | 运行时 | `^14`（锁定到 lockfile） | CommonMark 级解析、表格 / 删除线 / 代码围栏齐全、可关 HTML、可注入链接规则；3 篇文章已使用标题、列表、表格、代码块、引用、链接，自研解析器风险高于收益 |
| `@types/markdown-it` | 开发 | `^14` | 官方类型包 |

**渲染配置**（D-06 定稿）：

```ts
const md = new MarkdownIt({
  html: false,      // 原始 HTML 不生效，渲染为文本（XSS 面收敛）
  linkify: true,    // 裸 URL 自动成链接
  breaks: true,     // 单换行即 <br>，符合终端里「一行就是一行」的直觉
  typographer: false, // 不做引号/破折号替换，避免中文语境下的意外替换
})
```

- **链接规则**：覆盖 `link_open`，对每个 `<a>` 追加 `target="_blank"` 与 `rel="noopener noreferrer"`（已有同名属性时不重复追加）；`javascript:` 等危险协议由 `markdown-it` 的 `validateLink` 拒绝，测试断言 `` [x](javascript:alert(1)) `` 不产生 `href="javascript:`。
- **转义边界**：文章正文由 `markdown-it` 自行转义；**命令拼进 HTML 的动态文本**（日期、标签、标题）必须经 `escapeHtml`——本里程碑唯一的动态 HTML 来自 `.md__meta`。
- **渲染 API**：

```ts
/** 渲染单篇 Markdown 为 HTML 片段（不含外层容器） */
export function renderMarkdown(source: string): string
```

  外层 `<article class="md">` 与 meta 由 `read.ts` 组装，渲染器保持「纯 Markdown → HTML」职责，便于单测与后续复用（M9 的图片说明若需富文本也可复用）。
- **体积预估**：`markdown-it` + `linkify-it` + `mdurl` + `punycode.js` + `uc.micro` 预计为 JS 增加 **约 20–25 kB（gzip）**；实测值在实现后登记到 3.10 与 4.4。若实测 gzip 增量超过 30 kB，再评估「首次 `blog read` 时动态 `import()` 渲染器」（列为 M10 可选项，本里程碑先静态引入）。

### 3.3 命令规格

#### 3.3.1 命令与子命令分发（`command.ts`）

```ts
export const blogCommand: Command = {
  name: 'blog',
  description: '浏览博客文章（list / read / tags / tag）',
  usage: 'blog <list|read|tags|tag> [参数]',
  async execute(ctx) { ... },
}
```

分发顺序（每一步失败即输出错误并 `return`，不抛错）：

1. 取 `ctx.args[0]` 作为子命令；缺失 → 2.2 第 13 条；不在 `list` / `read` / `tags` / `tag` 中 → 第 14 条。
2. 选项按子命令校验（`rejectUnknownOptions`，复用 `src/commands/path-argument.ts`）：
   - `read`：允许 `--raw`；
   - `list` / `tags` / `tag`：不允许任何选项。
3. 参数按子命令校验（数量、必填），错误文案见 2.2 第 15–19 条。
4. 调用对应 handler；handler 返回 `Promise<void>`，所有错误自行 `ctx.output.push({ type: 'error' })`。

说明：

- **单命令 + 子命令**而非 5 条顶级命令：符合 PLAN 第 6 节「子命令用空格分隔（`blog read`）」与架构 6.4 的规划，`help` 只多一行，语义聚集。
- **选项位置不敏感**：`--raw` 由解析器放入 `ctx.options`，与出现在子命令前后无关；实现不解析 `args` 里的 `--raw`。
- **`--raw` 只对 `read` 生效**：`blog --raw hello` 的 `args[0]` 仍是 `hello`，会按第 14 条报「未知子命令: hello」，不会把 `hello` 误当 id；`--raw` 的有效位置只由 `read` 分支消费。

#### 3.3.2 `blog list`（`list.ts`）

```ts
const summaries = await ctx.dataSource.fetchArticleList()
if (summaries.length === 0) { system: 'blog: 暂无文章（内容尚未发布或加载失败，稍后重试即可）'; return }
ctx.output.write(formatArticleList(summaries))
```

- 数据源已按「日期倒序、同日 id 升序」排序并冻结，命令**不再排序**，也不就地修改条目（Q-05 于 M7 已定）。
- 行格式由 `format.ts` 统一：

```ts
const idWidth = Math.max(...summaries.map((item) => item.id.length))
`  ${item.id.padEnd(idWidth)}  ${item.date ?? '—'}  ${item.title}`
```

  `date` 在类型上可选（`ArticleSummary.date?`），catalog 保证运行时存在，缺省回退为 `—`；`id` 为 ASCII，`padEnd` 与显示宽度一致。
- 头部：`共 ${n} 篇文章（按发布日期倒序）：`；尾部：`输入 blog read <id> 阅读全文，输入 blog tags 查看标签。`，头尾之间各留一个空行。

#### 3.3.3 `blog read`（`read.ts`）

```ts
const article = await ctx.dataSource.fetchArticle(id)
if (!article) { error: `blog: 文章不存在: ${id}，输入 blog list 查看全部文章`; return }
if (article.content.trim() === '') { error: `blog: 文章内容为空: ${id}`; return }

if (raw) {
  ctx.output.write(ensureTrailingNewline(article.content))   // 与 cat 同规则：无结尾换行时补一个
  return
}

const meta = [article.date, article.tags?.join(' / ')].filter(Boolean).join(' · ')
ctx.output.writeHtml(
  `<article class="md"><div class="md__meta">${escapeHtml(meta)}</div>${renderMarkdown(article.content)}</article>`,
)
```

- **`--raw` 与 `cat` 同源**：`/mnt/blog/<id>.md` 的节点内容就是 `article.content`，`--raw` 输出同一字符串；两者都只在缺结尾换行时补一个，因此第 8 步的「逐字一致」可由测试锁定。
- **`ensureTrailingNewline` 就地实现 2 行**（与 `cat.ts` 同规则），不为此新增共享模块，避免把 `cat` 的内部细节变成跨命令 API；两处一致性由测试断言（`--raw` 输出 === `vfs.readFile('/mnt/blog/<id>.md')` 经同规则处理）。
- **不追加页脚**：保持阅读输出干净；发现性由 `help blog` 与 `blog list` 页脚承担（Q-07）。
- **空正文判定用 `trim()`**：只有空白字符的内容视为空，避免渲染出无内容的外壳。
- **不再读 VFS**：`read` 只走 `ctx.dataSource`，因此即使 `/mnt/blog` 挂载失败，`blog read` 仍可用（Q-04）。

#### 3.3.4 `blog tags`（`tags.ts`）

```ts
const summaries = await ctx.dataSource.fetchArticleList()
const counts = new Map<string, number>()
for (const item of summaries) for (const tag of item.tags ?? []) counts.set(tag, (counts.get(tag) ?? 0) + 1)
const rows = [...counts.entries()].sort((a, b) =>
  b[1] - a[1] || TAG_COLLATOR.compare(a[0], b[0]),
)
```

- `TAG_COLLATOR = new Intl.Collator('zh-Hans-CN', { numeric: true })`，与 M5 的文件名排序保持同一中文约定。
- 输出：`共 ${n} 个标签（按文章数倒序）：` + 空行 + 每行 `  ${tag}（${count} 篇）`；空态为 `system` 的 `blog: 暂无标签`。
- 标签名直接来自数据源（catalog 已校验：1–8 项、非空、无空白、长度 ≤ 24、篇内不重复），命令不再过滤。

#### 3.3.5 `blog tag`（`tag.ts`）

```ts
const keyword = ctx.args[1]!.trim()
const matches = summaries.filter((item) => (item.tags ?? []).includes(keyword))
if (matches.length === 0) { error: `blog: 标签「${keyword}」下暂无文章，输入 blog tags 查看全部标签`; return }
ctx.output.write(`标签「${keyword}」下的文章（${matches.length} 篇）：\n\n${formatArticleRows(matches)}`)
```

- 匹配规则：**精确匹配**（大小写敏感、不去除内部空格），入参先 `trim()`；中文标签无大小写问题，英文标签按字面匹配。
- 列表为空时先走 `blog list` 的空态（2.2 第 4 条），不再输出「标签下暂无文章」，避免误导。

### 3.4 `/mnt/blog` 投影（`tree.ts` + `index.ts`）

```ts
export const BLOG_MOUNT_TARGET = '/mnt/blog'

export interface BlogEntry {
  summary: ArticleSummary
  article: Article
}

/** 清单 + 正文 → 只读子树；空输入返回空目录（保证 /mnt/blog 始终存在） */
export function createBlogTree(entries: readonly BlogEntry[]): VfsNode
```

实现要点：

- 用 `buildTree` 生成子树，文件名 `<id>.md`，元信息：

```ts
{
  file: entry.article.content,
  meta: {
    mime: 'text/markdown',
    title: entry.summary.title,
    date: entry.summary.date ?? '',
    tags: (entry.summary.tags ?? []).join(','),
  },
}
```

  `mime` 命中 `cat.ts` 的 `TEXT_MIME`（`text/*`），因此 `cat` 按文本读取，不触发图片/二进制分支。
- **`install` 流程**（`index.ts`）：

```ts
install: async (api) => {
  const summaries = await api.dataSource.fetchArticleList()
  const entries: BlogEntry[] = []
  for (const summary of summaries) {
    const article = await api.dataSource.fetchArticle(summary.id)
    if (article) entries.push({ summary, article })   // 正文加载失败的文章不进快照
  }
  api.mounts.mount(BLOG_MOUNT_TARGET, createBlogTree(entries))  // 失败只告警，不抛错
}
```

- **空清单也挂载**：`createBlogTree([])` 返回空目录，`/mnt` 的 `ls` 结果因此稳定（`blog/` 始终存在），测试与降级场景下的可见行为也可预期。
- **串行预取**（`for ... of await`）而非 `Promise.all`：`fetchArticle` 内部已按 id 缓存去重，串行可保证 `/mnt/blog` 中文件的顺序与清单一致（`buildTree` 按对象键序），代价是 3 篇正文各一次请求；如实测首屏等待明显，再改为并行（Q-03）。
- **失败不阻断**：`fetchArticleList` 返回 `[]`（数据源内部已降级并告警一次）时挂空目录；`mount` 返回 `ok:false`（重复 / 目标非法）时 MountApi 已告警，插件**不抛错**，`blog` 命令照常注册——`blog read` 走数据源，仍可用。
- **快照语义**：`/mnt/blog` 是安装期快照，安装后不再更新；静态内容下与 `DataSource` 一致。若某篇文章正文在安装时加载失败，该文件不会出现在 `/mnt/blog`（但 `blog read` 会按需重试）；此限制记入 4.4 风险表。
- **不注册额外挂载管理命令**：`/mnt/blog` 的卸载仍被 M6 的 `mount` / `unmount`（仅 `/mnt/demo`）排除在外，避免访客误删站点内容。

import { vi } from 'vitest'

// 默认：空清单，不发真实请求；需要真实/自定义数据的用例自行 vi.stubGlobal('fetch', ...)
vi.stubGlobal(
  'fetch',
  vi.fn(async () => ({
    ok: true,
    status: 200,
    json: async () => ({ articles: [] }),
    text: async () => '',

)
```
