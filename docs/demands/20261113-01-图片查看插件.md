## 1. 需求背景

M8 已完成：博客插件在 `install` 阶段把文章清单与正文投影为 `/mnt/blog`，`blog list/read/--raw/tags/tag` 全部可用，`html` 输出块首次投入生产并由 `.md` 样式承载 Markdown 正文。**但终端目前只能浏览「目录」与「文本」，不能查看图片**：`cat` 明明已经能识别图片并提示「请使用 `img` 查看」，`img` 这条命令却还不存在，访客照着提示输入只会得到「未找到命令」。这是当前站点唯一一处**主动引导用户走进死胡同**的交互。

当前代码的真实状态（M8 完成后）：

| 项 | 现状 |
| --- | --- |
| 命令 | 11 条：`echo` / `help` / `clear` / `pwd` / `cd` / `history` / `ls` / `cat`（核心）+ `mount` / `unmount`（demo 插件）+ `blog`（博客插件） |
| `/mnt` | `blog/` 与 `demo/` 两个目录；`mount` 列表 2 项 |
| 图片 | `cat` 的 `IMAGE_EXTENSIONS` 含 png / jpg / jpeg / gif / webp / svg / bmp / ico / avif，命中时输出 `cat: xxx: 图片文件无法以文本方式显示，请使用 img 查看`；**`img` 尚未注册** |
| 画廊 | `src/commands/plugins/image/README.md` 仅为占位；无图片资源、无清单、无 `/mnt/gallery` |
| `html` 输出 | 唯一生产者是 `blog read`；`theme.css` 只有 `.md` 与 `.md img`，没有 `figure` / 图片说明的样式 |
| 测试基线 | 42 个测试文件 / 483 个用例；`terminal-store.spec.ts` 断言 `help` 为「共 11 条」、`/mnt` 为 `blog/` + `demo/`、`mount` 列表 2 项 |

**为什么现在做 M9**：

- **闭上唯一的死胡同**：`cat` 对图片的提示必须有一个真实可用的落点，否则「终端里什么都能看」的承诺不成立。M9 是 `cat` 提示的兑现，而不是锦上添花。
- **内容浏览的最后一块拼图**：M5 做了 `ls` / `cat`（目录与文本），M8 做了 `blog read`（富文本），M9 补上图片，「目录 → 文本 → 图片」三类内容全部可浏览；M10 只剩打磨与上线。
- **验证 `html` 输出块的第二种形态**：M8 的 `html` 承载的是 Markdown 文档流；M9 要承载**媒体元素 + 说明文字**，需要把「HTML 结构、响应式尺寸、alt/说明转义、加载时机」一次性定清楚，避免后续每个内容插件各写一套。
- **规模小、可控**：PLAN 将 M9 定为 S；无新依赖、无运行时网络加载、不改 `DataSource` / `CommandContext` / `PluginApi` / `OutputChunk`，只需 3 张示例图、1 条命令与 1 个挂载点。
- **可见变化明确、适合人工验收**：`help` 条数、`/mnt` 内容、`mount` 列表、图片排版、窄屏与破图表现都属于 `AGENTS.md` 第三节定义的 GUI 可见变化，必须走人工页面验收。

## 2. 需求描述

### 2.1 目标

新增**图片查看插件**（`src/commands/plugins/image/`），通过 M6 的 `PluginApi` 完成两件事：

1. **把示例画廊挂进 VFS**：`install(api)` 阶段把构建期确定的 3 张不同格式图片（PNG / JPEG / WebP）投影为只读子树，挂载到 `/mnt/gallery`；图片节点用 `meta` 携带 `mime` / `src` / `alt` / `title` / `description` / `width` / `height`，VFS 不保存二进制正文。
2. **注册 `img` 命令**：`img <图片路径>` 读取 VFS 节点，校验格式与资源地址后，输出一个 `<figure class="img">` 富文本块（`html` chunk），由 `.img` 样式负责响应式尺寸与说明文字。

同时新增**画廊清单与 3 张示例图**（`src/data/static/gallery/`）、**图片输出样式**（`theme.css` 的 `.img` 作用域），并顺带修正 `ls -l` 对外部资源的字节数展示（见 Q-03）。示例图从公共领域 / CC0 来源下载，使用 PNG、JPEG、WebP 三种格式，不手绘生成。

```
应用启动（模块装配）
  └─ createCommandRuntime({ dataSource, vfs, mounts, plugins: [demoPlugin, blogPlugin, imagePlugin] })
       ├─ 同步：注册 8 条核心命令
       └─ ready = 按序 await install：
            ├─ demoPlugin.install  → 挂载 /mnt/demo
            ├─ blogPlugin.install  → 预取文章并挂载 /mnt/blog
            └─ imagePlugin.install → 挂载 /mnt/gallery（同步，无网络请求）

用户执行 `img /mnt/gallery/domain-name.png`
  └─ Store → Executor → await ready（保证画廊已挂载）
       └─ imgCommand.execute(ctx)
            ├─ rejectUnknownOptions / 参数数量校验
            ├─ resolvePathArgument（~ 展开 + 基于 cwd 解析为绝对路径）
            ├─ ctx.vfs.resolve → VfsNode
            ├─ 文件 / 目录 / 图片格式 / meta.src 校验
            ├─ 组装 <figure>（alt / 标题 / 说明 / src 全部转义）
            └─ ctx.output.writeHtml('<figure class="img">…</figure>')
                 └─ TerminalOutput 以 v-html 渲染，.img 样式接管排版
```

### 2.2 用户可见行为

以下文本与格式为验收基线（括号内为 chunk 类型）。

**A. 命令发现与目录**

1. **`help` 变为 12 条**：新增 `img` 一行，仍按名称升序、两列对齐、页脚不变（`text`）。`img` 的说明为 `在终端中查看图片（png / jpg / jpeg / gif / webp / svg 等）`，位于 `history` 与 `ls` 之间。
2. **`help img`**（`text`）：

   ```
   img - 在终端中查看图片（png / jpg / jpeg / gif / webp / svg 等）
   用法: img <图片路径>
   ```

3. **`/mnt` 变为三个目录**：`ls /mnt` 输出 `blog/`、`demo/`、`gallery/`；`ls /mnt/gallery` 输出 `domain-name.png`、`pluto.jpg`、`saturn.webp`；`ls -l /mnt/gallery` 每行显示固定权限位、大小列与文件名（`text`）。
4. **图片大小显示为 `-`**：图片节点的二进制正文不在 VFS 中，无法得知真实字节数，`ls -l` 的大小列显示 `-`（与 `.` / `..` 的占位方式一致），**不伪造 `0` 或占位正文的长度**（Q-03）。
5. **`mount` 列表变为 3 项**：`mount` 输出「已挂载的目录（3）：」并列出 `/mnt/demo`、`/mnt/blog`、`/mnt/gallery`（按插件安装顺序，`text`）。

**B. 正常查看**

6. **`img /mnt/gallery/domain-name.png` 输出富文本**（`html`）：单个 `<figure class="img">` 块，结构固定为

   ```html
   <figure class="img"><img src="…" alt="…" width="977" height="358" loading="lazy" decoding="async"><figcaption class="img__caption"><span class="img__title">域名的组成</span><span class="img__desc">PNG 示例图：CC0 的域名结构示意图，带说明文字。</span></figcaption></figure>
   ```

   - 图片在输出区按比例显示，带 1px 暗色边框与圆角，与终端主题一致；
   - 标题来自清单 `title`，说明来自 `description`；标题为空时回退为文件名，说明为空则不输出说明行；
   - `width` / `height` 仅在清单给出合法正整数时输出，用于加载前预留宽高比，避免图片加载完成后把输入行顶出视口；
   - 命令回显（`command` 块）与提示符仍各占一行，不与图片块粘连。

7. **相对路径可用**：`cd /mnt/gallery` 后执行 `img domain-name.png` 与绝对路径效果一致；`img ./pluto.jpg` 同样可用；`~` 展开复用既有 `path-argument.ts`（home 下没有图片时按「文件不存在」处理）。

8. **三张不同格式的图都可查看**：
   - `img /mnt/gallery/pluto.jpg` 渲染 JPEG 照片「冥王星」，`width="1280"`、`height="1280"`；
   - `img /mnt/gallery/saturn.webp` 渲染 WebP 照片「土星」，`width="1280"`、`height="654"`；
   - `domain-name.png`（977×358）、`pluto.jpg`（1280×1280）、`saturn.webp`（1280×654）三张图的标题与说明文字均正确。

9. **图片不改变会话状态**：`img` 不修改 `cwd`、不写历史以外的状态；命令本身仍按 M1/M2 规则进入 `history`；`clear` 会清掉已渲染的图片（`html` chunk 随输出清空），历史保留。

10. **窄屏自适应**：桌面视口下图片最大不超过正文宽度；375px 宽下图片等比缩小、不撑破布局、页面本身不出现横向滚动条；说明文字自动换行；输入行始终可点击聚焦并输入。
11. **长图不占满屏**：图片最大高度限制为 `70vh`，超出时等比缩小；说明文字始终可见。
12. **无额外交互**：点击图片不会打开灯箱、不会跳转、不会缩放的交互（PLAN 明确排除）；点击页面仍按 M1 行为聚焦输入。

**C. 错误（全部为 `error`，且不改变 VFS / 会话状态）**

13. `img`（无参数）→ `img: 缺少图片路径（用法: img <图片路径>）`
14. `img a b` → `img: 参数过多（一次只能查看一张图片）`
15. `img -f x` → `img: 不支持的选项: -f`
16. `img /mnt/gallery/nope.png` → `img: 文件不存在: /mnt/gallery/nope.png`
17. `img /mnt/gallery`（目录）→ `img: /mnt/gallery: 是一个目录`
18. `img ~/README.md`（文本文件）→ `img: ~/README.md: 不是图片文件`
19. `img /path/to/photo.tiff`（图片类但不支持）→ `img: 不支持的图片格式: /path/to/photo.tiff（支持 png / jpg / jpeg / gif / webp / svg / bmp / ico / avif）`
20. 图片节点缺少 `meta.src` → `img: 图片资源缺失: <参数原文>`
21. `meta.src` 不是受支持的地址形态（如 `javascript:` / `data:` / 空串）→ `img: 图片地址不合法: <参数原文>`
22. 以上错误均只输出一条 `error`，不抛异常、不清屏、不影响后续命令。

**D. 稳定与回归**

23. **`cat` 的图片提示仍然成立且终于可用**：`cat /mnt/gallery/domain-name.png` 输出 `cat: /mnt/gallery/domain-name.png: 图片文件无法以文本方式显示，请使用 img 查看`；紧接着执行 `img` 即可看到图片。`cat` 本身零改动。
24. **既有命令无退化**：`ls` / `cat` / `cd` / `pwd` / `history` / `clear` / `echo` / `mount` / `unmount` / `blog` 与 M6–M8 已验收行为一致。
25. **预期中的可见变化**：`help` 11 → 12 条；`/mnt` 增加 `gallery/`；`mount` 2 → 3 项。这是 M9 的预期结果，不是回归（Q-10）。
26. **刷新重置**：刷新后 `cwd` 回 home、历史清空，`/mnt/gallery` 随插件重新装载再次可见，图片可再次查看。
27. **无噪音、无阻塞**：正常路径不写 `console.*`；无未处理 Promise rejection；插件 `install` 同步完成，不新增启动网络请求；图片只在该条 `img` 渲染时才由浏览器请求。
28. **图片加载后自动贴底**：图片下载完成、输出区高度变大时，若用户仍停留在底部，终端自动滚动到最底部，输入行保持可见；用户主动上滚阅读历史时，不会被异步图片加载强行拉回。

> **访客不可见但必须成立**：`img` 命令不 import Store / `window` / `fetch` / 静态文件，只通过 `ctx.vfs`、`ctx.output`、`ctx.args` 工作；插件不直接改 VFS，只提交只读子树给 `api.mounts`；`alt`、标题、说明与 `src` 全部经转义；示例素材是 PNG / JPEG / WebP 位图，不含脚本、事件处理器或外部资源引用。

```ts
const galleryAssets = import.meta.glob<string>(
  './*.{png,jpg,jpeg,gif,webp,svg,bmp,ico,avif}',
  {
    eager: true,
    query: '?url&no-inline', // 不把图片内联成 base64，保持资源可缓存、HTML chunk 精简
    import: 'default',
  },
)

/** 由文件名解析构建期 URL；清单与文件不一致时返回 null */
export function resolveGallerySrc(file: string): string | null {
  return galleryAssets[`./${file}`] ?? null
}

/** 供一致性测试使用：当前目录下被 Vite 收录的图片文件名 */
export function galleryAssetFiles(): readonly string[] {
  return Object.keys(galleryAssets).map((key) => key.replace(/^\.\//, ''))
}
```

- **为什么用 `import.meta.glob`**：新增图片只需「放文件 + 登记清单」两处，不需要改 import 语句；`?url` 由 Vite 负责生成带 hash 的产物 URL，自动兼容 `base` 子路径部署（M10）。
- **为什么加 `&no-inline`**：Vite 默认把小于 4 KB 的资源内联为 `data:` URL，会让 HTML chunk 变长且失去缓存；`?no-inline` 强制产出独立文件。若当前 Vite/Vitest 版本下该参数不生效（表现为 `src` 以 `data:` 开头），回退为在 `vite.config.ts` 设置 `build.assetsInlineLimit: 0`，并按 7.2 登记偏差。
- **运行时缺失不崩**：`createGalleryTree` 遇到 `resolveGallerySrc(file) === null` 时输出一次 `console.warn('[fun-terminal] 画廊资源缺失，已跳过: <file>')` 并跳过该条，其余图片、`img` 命令与终端启动不受影响；构建期缺失由 `gallery.spec.ts` 直接失败暴露。

### 3.3 `img` 命令规格（`img.ts`）

#### 3.3.1 命令契约

```ts
export const imgCommand: Command = {
  name: 'img',
  description: '在终端中查看图片（png / jpg / jpeg / gif / webp / svg 等）',
  usage: 'img <图片路径>',
  execute(ctx) {
    const optionError = rejectUnknownOptions('img', ctx.options, [])
    if (optionError) return fail(ctx, optionError)

    if (ctx.args.length === 0) return fail(ctx, 'img: 缺少图片路径（用法: img <图片路径>）')
    if (ctx.args.length > 1) return fail(ctx, 'img: 参数过多（一次只能查看一张图片）')

    const argument = ctx.args[0]!
    const resolved = resolvePathArgument('img', argument, ctx)
    if (!resolved.ok) return fail(ctx, resolved.message)

    const { node } = ctx.vfs.resolve(resolved.target)
    if (!node) return fail(ctx, `img: 文件不存在: ${argument}`)
    if (node.type === 'directory') return fail(ctx, `img: ${argument}: 是一个目录`)

    const image = readImage(node, argument)
    if (!image.ok) return fail(ctx, image.message)

    ctx.output.writeHtml(renderImageFigure(image.value))
  },
}
```

- `fail` 与 `renderImageFigure` 为模块内小函数（各 2–5 行）；不为此新增共享模块，也不复用 `blog/format.ts`（插件之间不互相 import 内部实现）。
- `readImage(node, argument)` 只读 `node.meta` / `node.name` 并用 `argument` 组装错误文案，**不读文件系统、不发请求**；因此可在纯单测中构造任意节点。

#### 3.3.2 图片分类与支持格式

按 Q-02 的建议，`img` 支持与 `cat` 图片分类一致的 9 种扩展名，避免出现第二个死胡同：

```ts
const IMAGE_EXTENSIONS = new Set([
  'png', 'jpg', 'jpeg', 'gif', 'webp', 'svg', 'bmp', 'ico', 'avif',
])
const IMAGE_MIMES = new Set([
  'image/png', 'image/jpeg', 'image/gif', 'image/webp',
  'image/svg+xml', 'image/bmp', 'image/x-icon', 'image/avif',
])
const IMAGE_LIKE_EXTENSIONS = new Set(['tif', 'tiff', 'heic', 'heif'])
```

扩展名取最后一个 `.` 之后的部分并统一转小写（与 `cat.ts` 的 `extensionOf` 一致）；无扩展名视为空串。

分类规则（`mime` 与扩展名任一命中即视为支持，避免 MIME 厂商别名或缺 mime 导致误判）：

| 条件 | 结果 | 命令行为 |
| --- | --- | --- |
| 扩展名 ∈ `IMAGE_EXTENSIONS`，或 `mime` ∈ `IMAGE_MIMES` | 支持 | 继续校验 `meta.src` 并渲染 |
| `mime` 以 `image/` 开头，或扩展名 ∈ `IMAGE_LIKE_EXTENSIONS` | 是图片类但不支持 | `img: 不支持的图片格式: <参数>（支持 png / jpg / jpeg / gif / webp / svg / bmp / ico / avif）` |
| 其他（文本、无扩展名、未知二进制） | 非图片 | `img: <参数>: 不是图片文件` |

- **为什么支持 9 种**：`cat` 对 bmp / ico / avif 也提示「请使用 img 查看」；若 `img` 只支持 6 种，用户会从 `cat` 的错误信息再走进一条新的死胡同。浏览器对 9 种均有原生渲染能力。
- **为什么任一命中即可**：构建期清单同时给出 `mime` 与扩展名，任一足够；厂商别名（如 `image/vnd.microsoft.icon`）或缺 `mime` 的自定义节点都不会被误判为「不是图片」。
- **`meta.src` 是唯一渲染地址**：`img` 不从 `node.content` 猜测、不拼接路径；没有 `src` 的图片节点明确报「图片资源缺失」，不渲染空 `<img>`。

#### 3.3.3 资源地址校验

```ts
const SAFE_SRC = /^(?:\/(?!\/)|\.\/|https?:\/\/)/i

function isSafeImageSrc(src: string): boolean {
  const value = src.trim()
  if (value === '' || value.length > 2048) return false
  if (/[\u0000-\u001f\u007f]/.test(value)) return false // 控制字符
  if (/\s/.test(value)) return false // 原始空格需编码；构建期 URL 不应含空格
  return SAFE_SRC.test(value)
}
```

允许：`/assets/...`、`./assets/...`、`https://...`、`http://...`；拒绝 `javascript:`、`data:`、`file:`、`blob:`、`//` 协议相对地址与空串。`src` 最终仍会经 `escapeHtml` 放进属性，双重防护。

- 允许 `http(s)` 是为后续内容源预留（示例图全部走构建期同源路径，不引用外链）；若评审希望一期完全禁止远程图，可把正则收窄为仅 `/` 与 `./`，不影响示例。
- **不预检 404**：VFS 只有 URL、不加载二进制；`img` 不发 `HEAD`/`GET`，避免额外请求、CORS 与首屏延迟。资源缺失时浏览器显示破图图标与 `alt`，说明文字仍在（Q-12）。

#### 3.3.4 输出结构

```ts
interface ImagePresentation {
  src: string
  alt: string
  title: string
  description?: string
  width?: number
  height?: number
}

function renderImageFigure(image: ImagePresentation): string {
  const size = [
    image.width ? ` width="${image.width}"` : '',
    image.height ? ` height="${image.height}"` : '',
  ].join('')
  const desc = image.description
    ? `<span class="img__desc">${escapeHtml(image.description)}</span>`
    : ''
  return (
    `<figure class="img">` +
    `<img src="${escapeHtml(image.src)}" alt="${escapeHtml(image.alt)}"${size} loading="lazy" decoding="async">` +
    `<figcaption class="img__caption">` +
    `<span class="img__title">${escapeHtml(image.title)}</span>${desc}` +
    `</figcaption></figure>`
  )
}
```

- **单一 `html` chunk**：一次 `writeHtml` 输出整个 `<figure>`，不先写文本路径；命令回显已经展示了路径。
- **回退规则（在 `readImage` 中）**：`title` 为空时用 `node.name`；`alt` 为空时用 `title`，再回退 `node.name`；`description` 为空则不输出 `<span class="img__desc">`。
- **尺寸**：`meta.width` / `meta.height` 解析为正整数（1–10000）才输出；非法值忽略，不影响图片显示。
- **转义**：`src`、`alt`、`title`、`description` 四个动态值全部经 `escapeHtml`（`src` 额外受 3.3.3 白名单约束），杜绝属性闭合注入。

#### 3.3.6 `ls -l` 的外部资源大小（`ls.ts` 小幅修正）

```ts
function sizeOf(node: VfsNode): string {
  if (node.type !== 'file') return '-'
  // 外部资源（如图片，正文不在 VFS 内）无法得知字节数，显示占位符而非伪造 0
  if (node.meta?.src) return '-'
  return String(utf8Bytes(node.content ?? ''))
}
```

- 影响面：仅 `ls -l` 的大小列；文本文件（含 `/mnt/blog/*.md`、home 示例文件）继续显示 UTF-8 字节数，`measureSizeWidth` 与 `.` / `..` 的占位逻辑不变。
- 若评审不希望动核心 `ls`，退回「显示 0」即可删除这两行判断（保留 `sizeOf` 的其余逻辑），但需接受 `ls -l` 把图片显示成 0 字节（Q-03）。

### 3.4 `/mnt/gallery` 投影（`tree.ts` + `index.ts`）

```ts
export const GALLERY_MOUNT_TARGET = '/mnt/gallery'

/** 清单 + 资源 URL → 只读子树；缺失资源跳过并告警 */
export function createGalleryTree(
  entries: readonly GalleryEntry[] = galleryEntries,
): VfsNode {
  const spec: TreeSpec = {}

  for (const entry of entries) {
    const src = resolveGallerySrc(entry.file)
    if (!src) {
      console.warn(`[fun-terminal] 画廊资源缺失，已跳过: ${entry.file}`)
      continue
    }
    if (Object.prototype.hasOwnProperty.call(spec, entry.file)) {
      throw new Error(`画廊文件名重复: ${entry.file}`)
    }

    spec[entry.file] = {
      file: '', // 二进制正文不进 VFS；cat 由 mime 识别为图片并提示用 img
      meta: {
        mime: entry.mime,
        src,
        alt: entry.alt,
        title: entry.title,
        ...(entry.description ? { description: entry.description } : {}),
        width: String(entry.width),
        height: String(entry.height),
      },
    }
  }

  return buildTree(spec)
}
```

节点 meta 约定（`Record<string, string>`，不改类型）：

| 键 | 来源 | 用途 |
| --- | --- | --- |
| `mime` | 清单 | `cat` 分类为图片；`img` 校验格式 |
| `src` | Vite 构建期 URL | `<img src>`；`ls -l` 判断「外部资源」 |
| `alt` | 清单 | `<img alt>`，无障碍与破图兜底 |
| `title` | 清单 | `figcaption` 主行 |
| `description` | 清单（可选） | `figcaption` 次行 |
| `width` / `height` | 清单 | `<img width height>`，加载前预留比例 |

**插件装配**：

```ts
export const imagePlugin: CommandPlugin = {
  id: 'image',
  commands: [imgCommand],
  install(api) {
    api.mounts.mount(GALLERY_MOUNT_TARGET, createGalleryTree())
  },
}
```

- **同步 `install`**：素材 URL 在构建期已确定，无需 `await`；`ready` 门保证 `img` 执行前画廊已挂载。
- **空/部分清单也挂载**：所有资源都缺失时 `createGalleryTree` 返回空目录，`/mnt/gallery` 仍存在；`img` 照常注册，访问具体文件时报「文件不存在」。
- **挂载失败不阻断**：目标被占用（如测试预挂载）时 `MountApi` 告警并返回 `ok:false`，插件不抛错，`img` 命令仍注册——与 M8 的语义一致；此时 `img` 读取的是既有 VFS 内容，可能报文件不存在。
- **不在 `/mnt/gallery` 上提供卸载入口**：`mount` / `unmount` 仍只管理 `/mnt/demo`（M6 定稿），避免访客误删站点内容。
- **不经过 `DataSource`**：画廊是构建期资源，`PluginApi.dataSource` 不使用；不扩展 `DataSource` 接口。

### 3.10 安全与无障碍

- **转义**：`src` / `alt` / `title` / `description` 全部经 `escapeHtml`；图片 HTML 中的动态文本（标题、说明、`alt`、`src`）是本里程碑唯一的注入面，测试覆盖引号与尖括号注入。
- **地址白名单**：只允许同源路径、`./` 相对路径与 `http(s)`；明确拒绝 `javascript:` / `data:` / `file:` / `blob:`，避免把清单配置错误放大成注入面。
- **图片格式安全**：示例素材为 PNG / JPEG / WebP 位图，不含脚本、事件属性或外部引用；`img` 仍支持 SVG（Q-02），但 SVG 只通过 `<img>` 上下文加载，浏览器不会执行其中的脚本。`img` 不接受用户上传，一期没有任意 SVG 注入路径。
- **无障碍**：`alt` 在清单中强制非空；`figure` / `figcaption` 提供语义；图片不可聚焦、无点击行为，不引入额外键盘陷阱；说明文字使用正文色与弱化色，满足终端主题对比度。
- **加载**：`loading="lazy"` + `decoding="async"`，避免阻塞其他输出渲染；`width` / `height` 预留比例，减少布局抖动。
- **能力边界**：插件与命令不 import Store / `window` / `fetch`；`img` 只读 VFS；不产生网络请求（浏览器加载图片由 `<img>` 自身触发）。

### 4.4 风险与对策

| 风险 | 影响 | 对策 |

| 图片资源 404 或构建时未产出 | 破图、访客看不到内容 | `gallery.spec.ts` 锁定清单 ↔ 资源；`tree.ts` 缺失即跳过并告警；破图时 `alt` + 说明文字仍在；人工验收检查网络 200 |

| 中文说明文字在窄屏溢出 | 布局破坏 | 说明文字 `normal` 换行 + `max-width`；375px 人工验收 |
| 既有测试断言失效（`help` 条数、`/mnt`、`mount`、卸载/重挂后列表） | 门禁失败 | 4.1 已列 5 处更新点；不改行为只改期望 |
