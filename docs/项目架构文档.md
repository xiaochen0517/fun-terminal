# 项目架构文档

> 本文档记录 fun-terminal 项目的总体架构设计，是理解项目结构与技术选型的核心参考。
> 依据需求文档 `docs/demands/20261106-01-模拟终端网站整体架构设计.md` 编写。

## 1. 项目概述

- **项目名称**：fun-terminal
- **项目定位**：以"模拟终端"为唯一交互入口的个人网站。访客通过类 Linux 命令行方式浏览站内信息（个人介绍、文章博客等）。
- **核心交互**：仿 Linux 终端界面，键入命令浏览信息，兼具趣味性与技术展示价值。
- **技术栈**：Vue 3 + Vite + TypeScript + Pinia

### 终端渲染选型

- **结论**：自研轻量终端渲染，不引入 xterm.js。
- **理由**：本项目"终端"本质是受控文本输入框 + 输出列表，不需要真实终端协议（ANSI 全量解析、PTY）。自研可完全掌控样式与交互（含 oh-my-zsh 风格提示符），且与 Vue 组件体系更契合。
- **预留**：后期若需富文本/复杂着色，再评估引入 xterm.js。

## 4. 总体架构分层

```
┌─────────────────────────────────────────────┐
│              展示层（View Layer）             │
│   Terminal 组件 / 输出渲染 / 交互捕获          │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│          命令执行层（Command Layer）          │
│  Command Registry / Parser / Executor        │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│         命令实现层（Plugin Layer）            │
│  内置命令 / 外置插件（目录、文本、图片、博客）    │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│          数据层（Data Layer）                 │
│  VFS 虚拟文件系统 / DataSource 抽象 / 静态数据  │
└─────────────────────────────────────────────┘
```

### 各层职责

| 层级      | 职责                                        | 对应目录        |
| ------- | ----------------------------------------- | ----------- |
| 展示层     | 渲染终端界面、捕获输入、展示输出、命令历史                  | `terminal/` |
| 命令执行层   | 解析输入、查找命令、分发执行                          | `terminal/` |
| 命令实现层   | 各命令的具体逻辑，遵循统一命令契约                       | `commands/` |
| 数据层     | 数据访问抽象（DataSource）与虚拟文件系统（VFS）           | `data/` `fs/` |

## 5. 命令分类

命令按实现形态分为两类，均遵循统一的插件契约（见第 6 节）。

| 类别     | 定位           | 示例                                        | 加载方式     |
| ------ | ------------ | ----------------------------------------- | -------- |
| 内置命令   | 终端基础能力，随核心集成 | `echo`、`history`、`help`、`clear`、`pwd`、`cd` | 核心启动即加载 |
| 外置插件命令 | 独立功能模块，按需挂载 | 目录插件（`ls`）、文本插件、图片查看插件、博客插件           | 独立插件注册  |

## 6. 插件化命令架构

### 6.1 设计目标

- 命令**即插即用**：新增命令无需改动核心代码，仅需按约定实现并注册。
- 命令实现与终端 UI、解析器、数据层**解耦**。
- 为后续"命令包/工具集"按需加载、远程安装预留扩展点（一期不实现远程安装）。

### 6.2 命令契约（Command Interface）

```ts
interface CommandContext {
  args: string[]                              // 解析后的参数
  options: Record<string, string | boolean>   // 选项
  cwd: string                                 // 当前虚拟工作目录
  env: Record<string, string>                 // 虚拟环境变量
  dataSource: DataSource                      // 数据访问抽象
  output: OutputBuffer                        // 输出缓冲（向终端写内容）
}

interface Command {
  name: string                                // 命令名，如 'ls'
  description: string                         // 命令说明，供 help 展示
  usage?: string                              // 用法示例
  execute(ctx: CommandContext): Promise<void> | void
}

interface CommandPlugin {
  commands: Command[]                         // 该插件提供的命令集合
  install?(registry: CommandRegistry): void
}
```

### 6.3 注册机制

- 内置命令随终端核心启动即加载；外置插件命令通过 `CommandPlugin.install()` 注册到全局 `CommandRegistry`。
- 注册表按命令名建立映射，执行时查找并分发；命令名冲突时后注册者覆盖或抛出警告（策略待定）。

### 6.4 命令清单规划

| 命令 | 类别 | 说明 |
| --- | --- | --- |
| `echo` | 内置 | 输出文本 |
| `history` | 内置 | 查看命令历史 |
| `help` | 内置 | 查看帮助信息（中文） |
| `clear` | 内置 | 清屏 |
| `pwd` | 内置 | 显示当前虚拟目录 |
| `cd` | 内置 | 切换虚拟目录 |
| `ls` | 外置（目录插件） | 列出目录内容（基于 VFS） |
| `cat` | 外置（文本/目录插件） | 读取文件内容 |
| `blog` | 外置（博客插件） | 浏览博客文章 |
| 图片查看命令 | 外置（图片插件） | 展示图片（具体命令名待定） |

> 注：`cat` 视实现归属文本插件或目录插件，开发阶段再最终确定。

## 7. 虚拟文件系统（VFS）与挂载

- 目录插件基于**虚拟文件系统（VFS）** 工作，将站点内静态资源/内容目录映射为虚拟路径。
- 站点静态内容（如 `public/` 内容、博客文章目录）挂载到虚拟路径 `/mnt` 下，供 `ls`、`cat`、`cd` 统一读写。
- VFS 提供统一的节点模型（目录/文件）与路径解析；命令层只面向 VFS 接口操作，不直接访问真实文件路径。
- 一期仅支持站内静态内容的虚拟映射，**不涉及访客本地磁盘读取**。

## 8. 博客集成方案

### 8.1 目标

在终端内通过命令浏览文章，如 `blog list` 列出文章、`blog read <id>` 阅读正文。

### 8.2 一期方案：纯前端静态实现

- 文章以 Markdown 文件存放于 `src/data/static/articles/`（或 `public/`），构建时随包发布。
- 使用 `markdown-it` 渲染为富文本（HTML），支持标题层级、代码块等排版。
- 提供两种查看方式：`cat` 纯文本输出原文；博客插件富文本（md 渲染）展示正文。
- 通过 `StaticDataSource` 提供文章列表与正文读取。

### 8.3 后期扩展：接入后端

通过 `DataSource` 抽象预留，可平滑切换：

| 维度     | 一期（纯前端）           | 后期（后端）       |
| ------ | ------------------ | ------------ |
| 数据来源   | 静态文件               | REST/API     |
| 文章更新   | 重新构建               | 后台/数据库直接更新   |
| 动态能力   | 无                  | 评论、统计、搜索、鉴权  |
| 实现替换点  | `StaticDataSource` | `ApiDataSource` |

**关键结论**：命令层严格依赖 `DataSource` 接口、而非直接触碰静态文件，一期到二期迁移成本最低——仅需新增 `ApiDataSource` 实现并替换注入，命令代码基本无需改动。

### 8.4 后端选型倾向（后续参考，一期不落地）

- 若引入后端，优先轻量方案（Node.js 系框架或 Serverless），与前端技术栈统一。
- 具体选型待一期完成后、明确动态需求时再单独立项评审。

## 9. 状态管理与数据流

- 终端会话状态（当前虚拟目录 `cwd`、命令历史、环境变量）由 Pinia 管理。
- 输出内容采用流式缓冲（`OutputBuffer`），支持 `clear` 清屏。
- 命令内部状态（如文章浏览位置）不全局化，保持命令独立性。
- 数据流：用户输入 → Parser 解析 → Registry 查找 → Command 执行 → 读写 DataSource / VFS → OutputBuffer 输出 → 终端渲染。

## 10. 视觉与语言约定

- **视觉风格**：参照 oh-my-zsh 基础样式——暗色背景、等宽字体、模拟 `zsh` 提示符（含路径段与分支提示符占位）。
- **语言约定**：不做中英双语切换。博客内容、帮助信息等面向访客的文本使用**中文**；命令名、选项等使用**英文**（遵循 Linux 惯例）。
